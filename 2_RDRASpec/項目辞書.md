# 項目辞書（AG-01 プロダクトディスカバリー）

> 位置づけ： AG-01 の全項目について、桁数・長さ・文字セット・値の範囲・表示ラベルを1か所で定義する辞書（2026-11-16 作成、叩き台）。
> 使い道：
> - 桁数の最終確定はこの辞書で行う（Issue #563「詳細設計で明確化」の受け皿）
> - アプリ側の入力検証はこの辞書の定義から生成・実装する（Issue #567「相関チェックはアプリ側検証」の単項目側）
> - 画面・帳票の表示ラベルはこの辞書の「表示ラベル」を既定値として使う
> - 実装では、この辞書の制約値を**値オブジェクトの定数**として定義し、単一の情報源とする（5 章、ADR-002）
> - DB の型・制約は `物理データモデル.md` と一致させる。ズレが出たらどちらが正か決めて両方直す
>
> 表の読み方： 「要確認」は叩き台の仮置きで、未確定のもの。確定したら要確認を外す。

## 1. 共通ルール

### 1.3 長さ・範囲の共通原則

- 最大長は**文字数**で数える（バイト数ではない）。DB の VARCHAR(n) も文字数指定で一致する
- 最小長 1 は「空文字不可」を意味する。必須（NOT NULL）項目は原則 最小長 1 以上
- 任意項目は未入力（NULL）を許す。入力する場合は最小長 1（空文字での登録は不可）とする【要確認】
- 数値の最大値・最小値は、型の上限ではなく業務上の範囲を書く。未定のものは「要確認」
- 表示ラベルは全画面共通の既定値。画面固有に言い換える場合は画面設計側で定義し、この辞書のラベルは変えない
- **区分値**（状態・分類など）は**処理の分岐条件として使用する**。DB にはコード値のみを保持し、日本語ラベルは DB に持たない。値集合はアプリ側の enum で管理し、条件判定は enum 定数で行う（文字列リテラルや表示ラベルで判定しない）（ADR-003）
- **カテゴリー**（更新頻度・出所・影響範囲・連絡方法など）は処理の分岐に使用せず、**検索条件としてのみ使用する**。値（コードと表示名）は DB に保持し、データとして追加・変更できる（ADR-004）
- 項目が区分値かカテゴリーかの切り分けは「処理の分岐に使うか」で決める

## 5. 実装方針：値オブジェクトへの定数定義

この辞書の制約値（最大長・最小長・最小値・最大値・文字セット）は、実装時に各項目の**値オブジェクトへ定数として定義**し、コード上の単一の情報源とする。数値を各所に直書きしない（ADR-002）。

### 5.1 定数の持ち方

```java
// 例：プロダクトビジョンの名称
public record ProductVisionTitle(String value) {

    public static final int MAX_LENGTH = 200;   // 項目辞書「最大長」
    public static final int MIN_LENGTH = 1;     // 項目辞書「最小長」

    public ProductVisionTitle {
        Objects.requireNonNull(value, "ビジョン名は必須です");
        if (value.isBlank() || value.length() > MAX_LENGTH) {
            throw new IllegalArgumentException(
                "ビジョン名は " + MIN_LENGTH + "〜" + MAX_LENGTH + " 文字で入力してください");
        }
    }
}
```

- 文字列項目： `MAX_LENGTH` / `MIN_LENGTH` を定数化する。文字セットは `Pattern` 定数（例：コード値の `^[A-Z_]+$`）として持つ
- 数値項目： `MIN_VALUE` / `MAX_VALUE` を定数化する（例： PersonaAge の 0〜150、KanoResponseCount の 0〜）
- 状態・区分項目： 値集合は enum で表現し、enum 自体を単一の情報源とする（コード値と表示ラベルの対応も enum に持たせる）。DB にはコード値のみを保持し、日本語ラベルは持たない。区分値は処理の分岐条件として使用するものであり、条件判定はこの enum に対して行う（ADR-003）
- カテゴリー項目： 値は DB に保持するため、値オブジェクトに値集合は持たない。検索条件として参照するだけにし、処理の分岐に使わない（ADR-004）
- 表示ラベル： 値オブジェクトには持たせない。画面・帳票側の表示リソース（メッセージ定義）がこの辞書の表示ラベルを既定値として使う

### 5.2 定数の参照箇所

| 参照箇所 | 使い方 |
|---------|--------|
| ドメイン検証 | 値オブジェクトのコンストラクタ／ファクトリが定数で検証する。YAVI のバリデータ定義からも同じ定数を参照する |
| JPA マッピング | `@Column(length = ProductVisionTitle.MAX_LENGTH)` のように定数式で参照する（コンパイル時定数なのでアノテーションに使える） |
| API 定義 | リクエスト DTO の検証（@Size 等）や OpenAPI の `@Schema(maxLength = ...)` から定数を参照する |
| テスト | 境界値テスト（最大長ちょうど／最大長+1 など）は定数を基準に組み立てる。辞書の値を変えたら定数を変え、テストが追随する |
| Flyway DDL | SQL は Java 定数を参照できない。DDL の桁数はこの辞書の値と一致させ、ズレはレビューと物理データモデルとの突き合わせで防ぐ |

### 5.3 辞書とコードの関係

- 設計フェーズではこの辞書が源泉。実装時は値オブジェクトの定数が源泉となり、辞書は定数の写しとして追随させる
- 値を変えるときは「辞書 → 定数 →（必要なら）DDL」の順に反映し、片方だけ変えた状態を残さない
