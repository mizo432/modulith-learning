# 要件組み立てチェックリスト (フェーズ2: 要件を組み立てる)

本チェックリストは、RDRAのフェーズ2「要件を組み立てる」における確認項目をまとめたものです。
フェーズ1で整えた枠組みを前提として、「システム要件定義」を中心に要件を具体化し、要件同士の関係性を明確にしているかを確認します。

---

## Step5: 業務からユースケース (UC)を導き出す

### システム境界レイヤー

- [ ] 業務からユースケース (UC)を導き出しているか
- [ ] システム化する部分が整理されているか
- [ ] ユースケースを洗い出すことで、どの業務をシステムでサポートするのかが明らかか
- [ ] システム化の範囲が可視化されているか
- [ ] 画面（人と関わる入出力）が特定されているか
- [ ] イベント（外部システムとの連携）が特定されているか
- [ ] ユースケース一覧が作成されているか
- [ ] ユースケース図が作成されているか

### 画面定義

- [ ] 画面一覧が作成されているか
- [ ] 画面定義が明確か（画面名、関連ユースケース、入力・出力項目）
- [ ] 画面とユースケースの関連付けが適切か
- [ ] 画面定義書が作成されているか（画面レイアウト、入力項目、出力項目、バリデーションルール）

### イベント定義

- [ ] イベント一覧が作成されているか
- [ ] イベント定義が明確か（イベント名、トリガー、関連ユースケース）
- [ ] イベントとユースケースの関連付けが適切か

---

## Step6: 情報や状態とUCを関連づけ、要件の精度を上げる

- [ ] 洗い出した情報とユースケースを関連づけているか
- [ ] 状態とユースケースを関連づけているか
- [ ] 情報をハブとして他のユースケースと繋いでいるか
- [ ] ユースケースによる情報の変化を状態として表しているか
- [ ] 状態を用いてユースケースの妥当性を評価しているか
- [ ] アクターをユースケースに関連付けているか
- [ ] 外部システムをユースケースに関連付けているか
- [ ] UC複合図が作成されているか（ユースケース、画面、イベント、情報、条件を関連づける）

---

## 共通確認項目

- [ ] 4つのレイヤーが厳格に区別されているか
    - システム価値レイヤー: 要求、アクター、外部システム
    - システム外部環境レイヤー: 業務、BUC、アクティビティ
    - システム境界レイヤー: ユースケース、アクター
    - システムレイヤー: 情報、状態、条件、バリエーション、画面、イベント
- [ ] 各レイヤー間の「Why」の依存関係が明確か
- [ ] 粒度が要件レベルで統一されているか
    - UC: それを実行することで実行した人に何かうれしいことがある
    - 情報モデル: エンティティレベル以上
- [ ] AIが要求を一方的に決定していないか（ユーザーの確認を得ているか）
- [ ] 元の要件ドキュメントを変更していないか

---

## フェーズ3: 整合性・網羅性を確認し、精度を高める

本チェックリストは、RDRAのフェーズ3「整合性・網羅性を確認し、精度を高める」における確認項目をまとめたものです。
フェーズ2で組み立てた要件の整合性と網羅性を検証し、仕様化に耐えうる精度へと引き上げます。

---

### Step7: UC（ユースケース）につながる条件を洗い出す

- [ ] システムがどのような条件下で動作するかを考察しているか
- [ ] 条件がUCにどのように影響するかを明確にしているか
- [ ] ビジネスを駆動するために必要なビジネスルールを明確にしているか
- [ ] 条件として整理しているか
- [ ] 条件一覧が作成されているか
- [ ] 条件とUCの関連付けが適切か

### Step8: 条件の軸となるバリエーションを洗い出す

- [ ] 条件をバリエーションの組合せで表現できるか
- [ ] 条件をバリエーションと状態の組合せで表現できるか
- [ ] 条件からバリエーションを逆引きできるか
- [ ] バリエーション一覧が作成されているか
- [ ] バリエーションと条件の関連付けが適切か

### Step9: 条件とバリエーションの要素を洗い出す

- [ ] 各条件について具体的な要素を洗い出しているか
- [ ] 各バリエーションについて具体的な要素を洗い出しているか
- [ ] 要件がさらに詳細化され、開発チームにとって明確な実装指針となるか
- [ ] バリエーション条件図が作成されているか

---

### 整合性チェック項目

- [ ] 要素間の関係性を俯瞰して確認しているか
- [ ] 不整合を検出する仕組みを活用しているか
- [ ] UCと情報の関連付けに矛盾がないか
- [ ] UCと状態の関連付けに矛盾がないか
- [ ] UCと条件の関連付けに矛盾がないか
- [ ] 画面とUCの関連付けに矛盾がないか
- [ ] イベントとUCの関連付けに矛盾がないか
- [ ] 外部システムとイベントの関連付けに矛盾がないか

### 網羅性チェック項目

- [ ] 全UCが少なくとも1つの情報と関連付けられているか
- [ ] 全UCが少なくとも1つのアクターと関連付けられているか
- [ ] 状態遷移を持つエンティティは全状態が定義されているか
- [ ] 条件に関連するバリエーションが定義されているか
- [ ] 画面一覧に全UCに関連する画面が含まれているか
- [ ] イベント一覧に全UCに関連するイベントが含まれているか

---

## 共通確認項目 (フェーズ3追加)

- [ ] 要件定義以降でビジネスルールを仕様化するプロジェクトの場合は、ここで要件定義を終えるか判断するか
- [ ] UCが洗い出されたことでシステムで何を対象とし、何を対象外とするかが決まっているか
- [ ] 見積可能かどうかを確認したか
- [ ] プロジェクトチームが成熟していない場合は手戻りを少なくするためにフェーズ3まで実施したか
