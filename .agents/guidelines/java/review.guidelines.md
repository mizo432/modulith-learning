# Java レビューガイドライン

本ガイドラインは、modulith-learning プロジェクトにおける Java コードのレビュー手順とチェックポイントを定義します。

## 1. レビューの基本方針

- コードレビューは、品質保証と知識共有の両面から実施します。
- レビュー時は、モジュール境界の遵守、テスト規約の準拠、Null安全性、例外処理の適切性を重点的に確認します。
- PRレビューは3回の反復サイクルで実施し、潜在的な不具合や設計上の課題を段階的に排除します。

## 2. モジュール境界の検証

- Spring Modulith による公開API/SPIと内部実装の分離が適切に行われているか確認します。
- `internal` パッケージへの不正な参照がないか検証します。
- モジュール間の循環参照がないか `ModulithTest.java` の検証結果を確認します。

## 3. アーキテクチャ準拠の確認

- オニオンアーキテクチャ / クリーンアーキテクチャの層構造に従っているか確認します。
- Domain層が外部フレームワークに依存していないか検証します。
- 各層の責務が適切に分離されているか評価します。

## 4. テスト規約の準拠

- テストメソッド名が `should` で始まっているか確認します。
- 日本語の `@DisplayName` が付与されているか確認します。
- `@Nested` による構造化が適切に行われているか確認します。
- AssertJの使用と `.as("...")` による意図の明記を確認します。
- 境界値・異常系のテストが網羅されているか確認します。

## 5. Null安全性の検証

- JSpecifyアノテーション（`@NonNull`, `@Nullable`）が適切に付与されているか確認します。
- Nullポインター例外が発生する可能性のある箇所がないか検証します。

## 6. 例外処理の適切性

- 業務エラーとシステム障害の区別が適切か確認します。
- 事前条件検証がメソッドの先頭で行われているか確認します。
- 機密情報が例外メッセージに露出していないか確認します。

## 7. コードスタイルの統一

- Google Java Style に準拠しているか確認します。
- Lombokアノテーションの適切な使用を確認します。
- 命名規則が統一されているか確認します。

## 8. パフォーマンスとセキュリティ

- N+1問題などのパフォーマンスボトルネックがないか確認します。
- SQLインジェクションなどのセキュリティリスクがないか確認します。
- 適切なインデックスが設定されているか確認します。
