# TypeScript レビューガイドライン

本ガイドラインは、modulith-learning プロジェクトにおける TypeScript コードのレビュー手順とチェックポイントを定義します。

## 1. レビューの基本方針

- コードレビューは、品質保証と知識共有の両面から実施します。
- レビュー時は、型安全性、コンポーネント設計、テスト規約の準拠を重点的に確認します。
- Storybookによるテストが適切に記述されているか確認します。

## 2. 型安全性の検証

- `any`型の使用がないか確認します。
- インターフェースや型エイリアスが適切に定義されているか確認します。
- Propsの型定義が明確で、デフォルト値が設定されているか確認します。
- 型推論に過度に依存せず、明示的な型注釈を使用しているか確認します。

## 3. コンポーネント設計の確認

- 単一責任の原則に従っているか確認します。
- コンポーネントのサイズが適切で、分割可能な箇所がないか確認します。
- カスタムフックの抽出が適切に行われているか確認します。
- 副作用の管理が適切で、クリーンアップ関数が実装されているか確認します。

## 4. テスト規約の準拠

- Storybookによるテストが記述されているか確認します。
- loading / error / empty / success の各状態がカバーされているか確認します。
- `play`関数によるインタラクションテストが適切か確認します。
- ストーリーファイルの命名規則が統一されているか確認します。

## 5. パフォーマンスの確認

- 不要なリレンダリングが発生していないか確認します。
- `useMemo`や`useCallback`の適切な使用を確認します。
- 大きなリストの仮想化が検討されているか確認します。
- コードスプリットが適切に行われているか確認します。

## 6. セキュリティの確認

- XSS攻撃に対する対策が講じられているか確認します。
- ユーザー入力のサニタイズが適切か確認します。
- 機密情報がクライアント側に露出していないか確認します。

## 7. コードスタイルの統一

- 命名規則が統一されているか確認します。
- インデントやフォーマットが一貫しているか確認します。
- コメントが適切に記述されているか確認します。
- 不要なコードや未使用のインポートがないか確認します。

## 8. アクセシビリティの確認

- ARIA属性が適切に使用されているか確認します。
- キーボード操作に対応しているか確認します。
- 色覚多様性を考慮したカラーコントラストを確認します。
