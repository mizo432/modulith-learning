# ドキュメント格納先ディレクトリ命名規則 (Document Directory Naming Guidelines)

本ガイドラインは、`docs/` ディレクトリ内のドキュメント格納先ディレクトリの命名規則と構造を定義します。

---

## 1. トップレベルディレクトリ

`docs/` ディレクトリ直下には、開発フェーズごとに番号付きディレクトリを作成します。

| ディレクトリ名                          | 説明                   |
|-----------------------------------------|------------------------|
| `01 Current system analysis`            | 現状システム分析       |
| `02 Request analysis`                   | 要求分析               |
| `05 バッチガイド`                       | バッチ処理ガイド       |
| `11.事業領域`                           | 事業領域一覧           |
| `12 業務領域`                           | 業務領域一覧           |
| `20 question`                           | 質問・問い合わせ       |
| `21 cording`                            | コーディング関連       |
| `21 data`                               | データ関連             |
| `21 要望`                               | 要望書                 |
| `22 要件定義書`                         | 要件定義書             |
| `23 詳細設計書`                         | 詳細設計書             |
| `95 Architecture decision record (ADR)` | アーキテクチャ判断記録 |
| `96 addressInfo`                        | 住所情報               |
| `97 spring cloud`                       | Spring Cloud 関連      |
| `98 Jpa`                                | JPA 関連               |
| `98 Role`                               | ロール関連             |
| `99 Dictionary`                         | 辞書・用語集           |
| `RESTful api`                           | RESTful API 関連       |
| `resource`                              | リソース関連           |

### 命名規則

- ディレクトリ名は2桁の番号プレフィックスで始める
- 番号は開発フェーズの順序を表す
- 番号の後にスペースを1つ入れる
- ディレクトリ名は日本語または英語で記述する
- 番号の範囲は以下の通り：
    - `01-09`: 現状分析・要求分析フェーズ
    - `10-19`: 事業領域・業務領域
    - `20-29`: 要望・要件定義・詳細設計
    - `90-99`: 参照資料・技術リファレンス

## 2. 要望書ディレクトリ構造

`docs/21 要望/` ディレクトリ内には、以下のサブディレクトリを作成します。

| ディレクトリ名 | 説明       |
|----------------|------------|
| `機能要望`     | 機能要望   |
| `非機能要望`   | 非機能要望 |

### 機能要望サブディレクトリ

`docs/21 要望/機能要望/` ディレクトリ内には、モジュールごとにサブディレクトリを作成します。

| ディレクトリ名      | 説明                     |
|---------------------|--------------------------|
| `AG アジルーム`     | アジルームモジュール     |
| `DO 開発運用`       | 開発運用モジュール       |
| `ER 元号レジストリ` | 元号レジストリモジュール |
| `TA 税率レジストリ` | 税率レジストリモジュール |

注：`DO 開発運用` モジュールには `データベース定義` サブディレクトリが存在する場合もあります。

### 非機能要件サブディレクトリ

| ディレクトリ名        | 説明               |

`docs/22 要件定義書/06 機能要件/` ディレクトリ内には、モジュールごとにサブディレクトリを作成します。

| ディレクトリ名  | 説明                 |

### 機能要件モジュール内構造

各モジュールディレクトリ内には、以下の番号付きサブディレクトリを作成します。

| ディレクトリ名    | 説明               |
|-------------------|--------------------|
| `01.システム価値` | システムの価値定義 |
| `02.外部環境`     | 外部環境定義       |
| `03.システム境界` | システムの境界定義 |
| `04.システム`     | システム内部の定義 |

サブディレクトリの例：

- `02.外部環境/02.業務/01.外部システム定義/`
- `03.システム境界/02.アクター/`
- `03.システム境界/03.ユースケース/`

## 4. 詳細設計書ディレクトリ構造

`docs/23 詳細設計書/` ディレクトリ内には、モジュールごとにサブディレクトリを作成します。

| ディレクトリ名 | 説明               |
|----------------|--------------------|
| `AR_承認申請`  | 承認申請モジュール |
| `AS_関連付け`  | 関連付けモジュール |
| `AZ_認可`      | 認可モジュール     |
| `DO_開発運用`  | 開発運用モジュール |
| `EF_電子帳票`  | 電子帳票モジュール |
| `NT_通知`      | 通知モジュール     |

### モジュール内構造

各モジュールディレクトリ内には、以下のサブディレクトリを作成します。

| ディレクトリ名        | 説明               |
|-----------------------|--------------------|
| `01 データベース設計` | データベース設計   |
| `backend`             | バックエンド設計   |
| `frontend`            | フロントエンド設計 |

ただし、モジュールによってはサブモジュールディレクトリを作成する場合もあります。
例えば、`AS_関連付け` モジュールには `Party パーティー` というサブモジュールが存在し、
その下に `backend`、`frontend` が配置されます。

### データベース設計サブディレクトリ

`docs/23 詳細設計書/{モジュール}/01 データベース設計/` ディレクトリ内には、以下のサブディレクトリを作成します。

| ディレクトリ名          | 説明               |
|-------------------------|--------------------|
| `03 テーブルカラム定義` | テーブルカラム定義 |
| `03 viewカラム定義`     | Viewカラム定義     |

注：`AR_承認申請` モジュールのみ `05 viewカラム定義` として番号が異なります。

### バックエンド設計サブディレクトリ

`docs/23 詳細設計書/{モジュール}/backend/` ディレクトリ内には、以下のサブディレクトリを作成します。

| ディレクトリ名 | 説明       |
|----------------|------------|
| `api`          | API設計    |
| `batch`        | バッチ設計 |

注：`api` ディレクトリの下には `ユースケース記述` サブディレクトリを作成する場合もあります。

## 5. ADRディレクトリ構造

`docs/95 Architecture decision record (ADR)/` ディレクトリ内には、ADRごとに番号付きファイルを作成します。

### 命名規則

- ファイル名は `番号-タイトル.md` の形式で記述する
- 番号は3桁のゼロ埋め形式で記述する
- タイトルは英小文字とハイフンで記述する

### サブディレクトリ

| ディレクトリ名 | 説明         |
|----------------|--------------|
| `example`      | 例ファイル   |
| `template`     | テンプレート |

### 例

- `001-frontend-framework-selection.md`
- `index.md`

## 6. 質問・問い合わせディレクトリ構造

`docs/20 question/` ディレクトリ内には、質問ごとに番号付きファイルを作成します。

### 命名規則

- 番号は2桁のゼロ埋め形式で記述する
- タイトルは日本語で記述する

### 例

- `02-データベースの選択.md`

## 10. 注意事項

1. ディレクトリ名には特殊文字（`!@#$%^&*()` など）を使用しない
2. ディレクトリ名には半角スペースは使用しない（番号の後のスペースのみ可）
3. ディレクトリ名には全角英数字は使用しない
4. ディレクトリ名にはアンダースコアは使用しない
5. ディレクトリ名にはハイフンは使用しない（番号の区切りには使用可）
6. ディレクトリ名にはスラッシュは使用しない
7. ディレクトリ名にはバックスラッシュは使用しない
8. ディレクトリ名にはコロンは使用しない
9. ディレクトリ名にはセミコロンは使用しない
10. ディレクトリ名にはカンマは使用しない
11. ディレクトリ名にはピリオドは使用しない（番号の区切りには使用可）
12. ディレクトリ名にはクエスチョンマークは使用しない
13. ディレクトリ名にはエクスクラメーションマークは使用しない
14. ディレクトリ名にはアットマークは使用しない
15. ディレクトリ名にはハッシュマークは使用しない
16. ディレクトリ名にはドルマークは使用しない
17. ディレクトリ名にはパーセントマークは使用しない
18. ディレクトリ名にはキャレットマークは使用しない
19. ディレクトリ名にはアンパサンドマークは使用しない
20. ディレクトリ名にはアスタリスクマークは使用しない
