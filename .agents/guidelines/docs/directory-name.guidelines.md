# ドキュメント格納先ディレクトリ命名規則 (Document Directory Naming Guidelines)

本ガイドラインは、`docs/` ディレクトリ内のドキュメント格納先ディレクトリの命名規則と構造を定義します。

---

## 1. トップレベルディレクトリ

`docs/` ディレクトリ直下には、開発フェーズごとに番号付きディレクトリを作成します。

| ディレクトリ名                          | 説明                   |
|-----------------------------------------|------------------------|
| `01 Current system analysis`            | 現状システム分析       |
| `02 Request analysis`                   | 要求分析               |
| `05 バッチガイド`                       | バッチ処理ガイド       |
| `11 事業領域`                           | 事業領域一覧           |
| `12 業務領域`                           | 業務領域一覧           |
| `13 非機能要件大項目`                   | 非機能要件大項目一覧   |
| `14 用語分類`                           | 用語分類               |
| `20 question`                           | 質問・問い合わせ       |
| `21 要望`                               | 要望書                 |
| `22 要件定義書`                         | 要件定義書             |
| `23 詳細設計書`                         | 詳細設計書             |
| `24 coding`                             | コーディング関連       |
| `25 data`                               | データ関連             |
| `90 RESTful api`                        | RESTful API 関連       |
| `91 resource`                           | リソース関連           |
| `95 Architecture decision record (ADR)` | アーキテクチャ判断記録 |
| `96 addressInfo`                        | 住所情報               |
| `97 spring cloud`                       | Spring Cloud 関連      |
| `98 Jpa`                                | JPA 関連               |
| `99 Dictionary`                         | 辞書・用語集           |
| `99a Role`                              | ロール関連             |

### 命名規則

- ディレクトリ名は2桁の番号プレフィックスで始める
- 番号は開発フェーズの順序を表す
- 番号の後にスペースを1つ入れる
- ディレクトリ名は日本語または英語で記述する
- 番号の範囲は以下の通り：
    - `01-09`: 現状分析・要求分析フェーズ
    - `10-19`: 事業領域・業務領域・非機能要件・用語分類
    - `20-29`: 要望・要件定義・詳細設計・コーディング・データ
    - `90-99`: 参照資料・技術リファレンス

## 2. 要望書ディレクトリ構造

`docs/21 要望/` ディレクトリ内には、以下のサブディレクトリを作成します。

| ディレクトリ名 | 説明       |
|----------------|------------|
| `機能要望`     | 機能要望   |
| `非機能要望`   | 非機能要望 |

### 機能要望サブディレクトリ

`docs/21 要望/機能要望/` ディレクトリ内には、事業領域ごとにサブディレクトリを作成します。

[事業領域一覧](../../docs/11 事業領域/事業領域一覧.md)を参照

## 3. 要件定義書ディレクトリ構造

`docs/22 要件定義書/` ディレクトリ直下には、事業領域ごとにサブディレクトリを作成します。

事業領域の命名規則は、`2文字コード + スペース + 日本語名` の形式です。

[業務領域一覧](../../docs/12 業務領域/業務領域一覧.md)を参照

各事業領域ディレクトリ内には、以下のサブディレクトリを作成します：

| ディレクトリ名  | 説明       |
|-----------------|------------|
| `01 非機能要件` | 非機能要件 |
| `03 機能要件`   | 機能要件   |
| `07 用語集`     | 用語集     |

### 非機能要件サブディレクトリ

`docs/22 要件定義書/[事業領域]/01 非機能要件/` ディレクトリ内には、非機能要件一覧.md
と非機能要件一覧.tsvを配置します。

### 非機能要件大項目（参照のみ）

`docs/13 非機能要件大項目/` ディレクトリは、非機能要件の大項目一覧を格納します。
RDRA ではこのディレクトリを参照のみで利用し、出力は行いません。

### 機能要件サブディレクトリ

`docs/22 要件定義書/[事業領域]/03 機能要件/` ディレクトリ内には、業務領域ごとにサブディレクトリを作成します。
各業務領域ディレクトリ内には、RDRAの4レイヤーに対応するサブディレクトリが構成されます：

| レイヤー         | ディレクトリ名     | 内容                                        |
|------------------|--------------------|---------------------------------------------|
| システム価値     | `01.システム価値/` | 要求、アクター、外部システム                |
| システム外部環境 | `02.外部環境/`     | 業務、BUC、アクティビティ、外部システム定義 |
| システム境界     | `03.システム境界/` | ユースケース、アクター                      |
| システム         | `04.システム/`     | 情報、ステート、イベント、画面、帳票        |

### 用語集サブディレクトリ

各事業領域配下の `07 用語集/` ディレクトリ内には、用語集.md と 用語集.tsv を配置します。

用語分類は `docs/14 用語分類/` ディレクトリに用語分類一覧.tsv を配置します。

## 4. 詳細設計書ディレクトリ構造

`docs/23 詳細設計書/` ディレクトリ内には、モジュールごとにサブディレクトリを作成します。

モジュールの命名規則は、`2文字コード_日本語名` の形式です。

| ディレクトリ名  | 説明                 |
|-----------------|----------------------|
| `AG_アジルーム` | アジルームモジュール |
| `AR_承認申請`   | 承認申請モジュール   |
| `AS_関連付け`   | 関連付けモジュール   |
| `AZ_認可`       | 認可モジュール       |
| `DO_開発運用`   | 開発運用モジュール   |
| `EF_電子帳票`   | 電子帳票モジュール   |
| `NT_通知`       | 通知モジュール       |

### モジュール内構造

各モジュールディレクトリ内には、以下のサブディレクトリを作成します。

| ディレクトリ名        | 説明               |
|-----------------------|--------------------|
| `01 データベース設計` | データベース設計   |
| `backend`             | バックエンド設計   |
| `frontend`            | フロントエンド設計 |

ただし、モジュールによってはサブモジュールディレクトリを作成する場合もあります。
例えば、`AS_関連付け` モジュールには `Party パーティー` というサブモジュールが存在し、
その下に `backend`、`frontend` が配置されます。

### データベース設計サブディレクトリ

`docs/23 詳細設計書/{モジュール}/01 データベース設計/` ディレクトリ内には、以下のサブディレクトリを作成します。

| ディレクトリ名          | 説明               |
|-------------------------|--------------------|
| `02 テーブルカラム定義` | テーブルカラム定義 |
| `03 viewカラム定義`     | Viewカラム定義     |

### バックエンド設計サブディレクトリ

`docs/23 詳細設計書/{モジュール}/backend/` ディレクトリ内には、以下のサブディレクトリを作成します。

| ディレクトリ名 | 説明       |
|----------------|------------|
| `api`          | API設計    |
| `batch`        | バッチ設計 |

注：`api` ディレクトリの下には `ユースケース記述` サブディレクトリを作成する場合もあります。

## 5. ADRディレクトリ構造

`docs/95 Architecture decision record (ADR)/` ディレクトリ内には、ADRごとに番号付きファイルを作成します。

### 命名規則

- ファイル名は `番号-タイトル.md` の形式で記述する
- 番号は3桁のゼロ埋め形式で記述する
- タイトルは英小文字とハイフンで記述する

### サブディレクトリ

| ディレクトリ名 | 説明         |
|----------------|--------------|
| `example`      | 例ファイル   |
| `template`     | テンプレート |

### 例

- `001-frontend-framework-selection.md`
- `index.md`

---

## 6. 質問・問い合わせディレクトリ構造

`docs/20 question/` ディレクトリ内には、質問ごとに番号付きファイルを作成します。

### 命名規則

- ファイル名は `番号-タイトル.md` の形式で記述する
- 番号は2桁のゼロ埋め形式で記述する
- タイトルは日本語で記述する

### 例

- `01-スプリングブートのバージョン.md`
- `02-データベースの選択.md`

`docs/90 RESTful api/` ディレクトリ内には、API仕様書やAPI関連のドキュメントを格納します。

### サブディレクトリ

| ディレクトリ名 | 説明        |
|----------------|-------------|
| `spec`         | API仕様書   |
| `examples`     | API使用例   |
| `changelog`    | API変更履歴 |

注：これらのサブディレクトリは必要に応じて作成します。

---

## 10. 注意事項

1. ディレクトリ名には、番号プレフィックスと番号後のスペース、および番号内のピリオドを除き、特殊文字は使用しない
2. ディレクトリ名には全角英数字は使用しない
3. **例外：** 詳細設計書のモジュール名ではアンダースコアを使用可能（例：`AG_アジルーム`）
4. **例外：** ADRファイル名ではハイフンを使用可能（例：`001-frontend-framework-selection.md`）
