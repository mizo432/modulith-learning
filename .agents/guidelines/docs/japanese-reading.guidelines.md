# ドキュメント作成共通ルール - 日本語として読めるかチェックする (Japanese Readability Check Guidelines)

本ガイドラインは、すべてのドキュメント作成時に適用する共通ルールです。ドキュメントの内容が日本語として自然に読めることを確認します。

---

## 1. 適用範囲

本ルールは、以下のすべてのドキュメント作成時に適用されます。

- 要望書
- 要件定義書
- 詳細設計書
- 各種一覧表（アクター一覧、ユースケース一覧、情報一覧など）
- 図表（情報ER図、状態モデル図、UC複合図など）
- その他、`docs/` 配下に配置されるすべてのドキュメント

---

## 2. チェック項目

ドキュメントを作成する際、以下の項目を確認してください。

| チェック項目 | 確認内容 | 判定基準 |
|:---|:---|:---|
| **タイトルの日本語化** | ドキュメントのタイトルが日本語で書かれているか | 日本語で意味が通じるか |
| **概要の日本語化** | 概要セクションが日本語で書かれているか | 日本語として自然な文章か、機械翻訳のような不自然な表現がないか |
| **詳細の日本語化** | 詳細セクションが日本語で書かれているか | 箇条書きや表の内容が日本語として読めるか |
| **説明の日本語化** | 各項目の説明が日本語で書かれているか | 説明が日本語として理解できるか |
| **表の日本語化** | 表の見出しと内容が日本語で書かれているか | 表の内容が日本語として読めるか |
| **図の日本語化** | 図のキャプションや説明が日本語で書られているか | 図の内容が日本語として理解できるか |
| **技術用語の扱い** | 技術用語は適切に扱われているか | API名、クラス名、コマンドなどは原文のまま可。それ以外は日本語訳すること |

---

## 3. 注意事項

### 3.1 技術用語

- API名、クラス名、メソッド名、コマンド、ファイルパスなどは原文（英語）のまま使用してよい
- 例: `Spring Boot`, `REST API`, `UC-XX-01`, `EntityName`

### 3.2 固有名詞

- プロダクト名、サービス名、フレームワーク名などは原文のまま使用してよい
- 例: `Spring Cloud Gateway`, `PlantUML`, `Gradle`

### 3.3 コードブロック

- コードブロック内の内容は原文のまま
- 例: PlantUMLコード、SQL文、コマンドラインなど

### 3.4 自然な日本語

- 機械翻訳のような不自然な表現を避け、自然な日本語で記載すること
- 例:
  - ❌ 「この機能はユーザーがデータを管理することを可能にする」
  - ✅ 「この機能はユーザーがデータを管理できるようにする」

### 3.5 漢字とひらがなのバランス

- 読みやすいバランスで表記すること
- 例:
  - 「管理する」（✅）
  - 「管理する」（✅）
  - 「菅理する」（❌ 誤字）

### 3.6 助詞の正しい使用

- 助詞の使い分けを正しく行うこと
- 例:
  - 「について」（✅）
  - 「对于」（❌ 中国語混入）

### 3.7 句読点の統一

- 句読点は日本語の「、」（読点）と「。」（句号）を使用すること
- 英語のコンマ（`,`）やピリオド（`.`）は使用しない

---

## 4. 二言語化ルールとの関係

一部のドキュメント（情報ER図、状態モデル図、UC複合図など）では、英語版と日本語版の両方を記載する二言語化ルールが適用されます。

二言語化ルールが適用される場合でも、以下の部分は日本語で記載します。

- ドキュメントのタイトル
- 目的セクション
- 一覧表の説明
- 参照情報

英語版の図やコードブロックは、原文のまま記載します。

---

## 5. チェックリスト

ドキュメント完成時、以下のチェックリストで確認してください。

- [ ] タイトルが日本語で書かれている
- [ ] 概要が自然な日本語で書かれている
- [ ] 詳細内容が日本語として読める
- [ ] 表の見出しと内容が日本語で書かれている
- [ ] 図のキャプションが日本語で書かれている
- [ ] 技術用語は適切に扱われている
- [ ] 機械翻訳のような不自然な表現がない
- [ ] 助詞の使い分けが正しい
- [ ] 句読点が統一されている
