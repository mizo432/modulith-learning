## 3. チェックリスト

RDRAの7フェーズに対応するチェックリストを以下に示します。各フェーズの完了時にこれらのチェックリストを使用して確認を行ってください。

### 共通確認項目（全フェーズで適用）

- [ ] 4つのレイヤーが厳格に区別されているか
    - システム価値レイヤー: 要求、アクター、外部システム
    - システム外部環境レイヤー: 業務、BUC、アクティビティ
    - システム境界レイヤー: ユースケース、画面、イベント
    - システムレイヤー: 情報、状態、条件、バリエーション
- [ ] 各レイヤー間の「Why」の依存関係が明確か
- [ ] 粒度が要件レベルで統一されているか
- [ ] AIが要求を一方的に決定していないか（ユーザーの確認を得ているか）
- [ ] 元の要件ドキュメントを変更していないか

---

### フェーズ1: 初期要望から要素を抽出する

本チェックリストは、RDRAのフェーズ1「初期要望から要素を抽出する」における確認項目をまとめたものです。
初期要望からRDRAモデルの全要素を抽出し、要件定義の基盤が構築されているかを確認します。

#### 初期要望分析

- [ ] 初期要望の内容を分析し構造を把握しているか
- [ ] RDRA構造と対比し、具体的に書かれていることと書かれていないことを分析しているか

#### 要求の抽出

- [ ] 機能要求を記載しているか
- [ ] 非機能要求を記載しているか

#### アクターの抽出

- [ ] システムを利用する人や組織の役割（アクター）をリストアップしているか
- [ ] アクターは役割として命名されているか（個人名ではない）
- [ ] アクターは顧客（社外の価値受益者）と提供者（価値を提供するアクター）に分かれているか

#### 外部システムの抽出

- [ ] 連携が必要な既存システムや外部サービス（外部システム）をリストアップしているか
- [ ] 外部システムは役割に応じて分類されているか
- [ ] 外部システム名は役割が分かる名前か

#### 業務の抽出

- [ ] システム化の対象となる「業務」を洗い出しているか
- [ ] 業務を構成する「ビジネスユースケース (BUC)」を洗い出しているか
- [ ] BUCには必ず一人の価値を得るアクターがいるか
- [ ] 事業領域一覧が作成されているか
- [ ] 業務領域一覧が作成されているか

#### 情報の抽出

- [ ] 業務で扱う「情報」をリストアップしているか
- [ ] 情報はユニークなIDを持ち、一意に識別できるか
- [ ] 情報一覧が作成されているか

#### 状態の抽出

- [ ] 状態モデルを洗い出しているか
- [ ] 状態モデルは複数の状態を持つか
- [ ] ステート一覧が作成されているか

#### ビジネスパラメータの抽出

- [ ] ビジネス上必要になる区分、分類、種別などのパラメータを洗い出しているか
- [ ] システムの仕組み上の区分、分類、種別は含めていないか

#### ビジネスポリシーの抽出

- [ ] ビジネスに関するポリシー（方針）を洗い出しているか

---

### フェーズ2: 要素を再整理し詳細化する

本チェックリストは、RDRAのフェーズ2「要素を再整理し詳細化する」における確認項目をまとめたものです。
フェーズ1で抽出した業務・情報・状態を再整理・詳細化し、条件とバリエーションを派生させているかを確認します。

#### 業務の詳細化

- [ ] フェーズ1の業務をベースにアクティビティとUCにブレークダウンしているか
- [ ] 要求に関わるアクティビティとUCを洗い出しているか
- [ ] 価値受益アクターと価値提供アクターをアクティビティ/UC毎に分割しているか
- [ ] UCは価値受益アクターか価値提供アクターのどちらかと結びついているか

#### 情報の詳細化

- [ ] フェーズ1の情報をベースに属性と関連情報を定義しているか
- [ ] 機能要求/非機能要求を実現するために必要な情報を洗い出しているか
- [ ] 情報が持つべき属性を洗い出しているか
- [ ] 情報同士の関連を関連情報として洗い出しているか

#### 状態の詳細化

- [ ] フェーズ1の状態モデルをベースに状態遷移に分解しているか
- [ ] 機能要求/非機能要求を実現するために必要な状態モデルを追加しているか
- [ ] 状態遷移を複数行として出力しているか
- [ ] 最初の状態と最後の状態を正しく表現しているか

#### 条件の派生

- [ ] ビジネスポリシーから条件（ビジネスルール）を派生させているか
- [ ] 条件の説明が明確か
- [ ] 条件の利用場面が定義されているか

#### バリエーションの派生

- [ ] ビジネスパラメータからバリエーションを派生させているか
- [ ] バリエーション内の取り得る複数の値が定義されているか
- [ ] バリエーションの説明が明確か

---

### フェーズ3: 要素を再整理する

本チェックリストは、RDRAのフェーズ3「要素を再整理する」における確認項目をまとめたものです。
フェーズ2で詳細化したBUC・アクター・情報を、他の要素との関係性を考慮して再整理しているかを確認します。

#### BUCの再整理

- [ ] フェーズ2の業務をベースにBUCを再整理しているか
- [ ] UCにつながる情報、条件、外部システムを紐付けているか
- [ ] 外部システムはフェーズ1で定義されたものだけを使用しているか
- [ ] 情報はフェーズ2で定義されたものだけを使用しているか
- [ ] 条件はフェーズ2で定義されたものだけを使用しているか

#### アクターの再整理

- [ ] 業務から新たなアクターを追加しているか
- [ ] 初期要望に記述がなく業務にも該当しないアクターは除外しているか
- [ ] 価値受益アクターに主担当業務を設定しているか
- [ ] アクターをアクター群としてグループ化しているか

#### 情報の再整理

- [ ] 情報をコンテキストで分類しているか
- [ ] 状態モデルを関連付けているか
- [ ] バリエーションを関連付けているか
- [ ] 状態モデルは「状態.tsv」に定義されているものだけを使用しているか
- [ ] バリエーションは「バリエーション.tsv」に定義されているものだけを使用しているか

---

### フェーズ4: 要素を関連付ける

本チェックリストは、RDRAのフェーズ4「要素を関連付ける」における確認項目をまとめたものです。
フェーズ3で再整理したBUC・バリエーション・条件・状態を、最終的なRDRA Sheet形式に変換しているかを確認します。

#### BUCの関連モデル形式への変換

- [ ] フェーズ3のBUCをベースに関連モデル形式に変換しているか
- [ ] カラム内の値が複数ある場合、複数行に展開しているか
- [ ] 情報はフェーズ2で定義されたものだけを使用しているか
- [ ] 条件はフェーズ2で定義されたものだけを使用しているか
- [ ] アクターはフェーズ3で定義されたものだけを使用しているか
- [ ] 外部システムはフェーズ1で定義されたものだけを使用しているか
- [ ] 画面名はUCとアクターをつなげた適切な名前か
- [ ] イベント名はUCと外部システムをつなげた適切な名前か

#### バリエーションのコンテキスト紐付け

- [ ] フェーズ2のバリエーションをベースにコンテキストを紐付けているか
- [ ] フェーズ3の情報からコンテキストを取得しているか
- [ ] 情報に対応しないバリエーションは役割からコンテキストを導出しているか

#### 条件のコンテキスト・バリエーション・状態モデル紐付け

- [ ] フェーズ2の条件をベースにコンテキストを紐付けているか
- [ ] 表形式の条件はバリエーションと状態モデルを紐付けているか
- [ ] 条件のコンテキストは条件に関わる情報のコンテキストを使用しているか

#### 状態のコンテキスト・遷移UC紐付け

- [ ] フェーズ2の状態をベースにコンテキストを紐付けているか
- [ ] 遷移UCはフェーズ3のBUC.tsvのUCから設定しているか
- [ ] 新たにUCを生成していないか
- [ ] 状態モデルのコンテキストはフェーズ3の情報から取得しているか

### フェーズ5: システム概要を定義する

本チェックリストは、RDRAのフェーズ5「システム概要を定義する」における確認項目をまとめたものです。
初期要望からシステム名とシステム概要を抽出し、JSON形式で出力しているかを確認します。

#### システム名の抽出

- [ ] 初期要望からシステム名を1つ抽出・決定しているか
- [ ] システム名は自然な日本語か
- [ ] システムの目的や対象業務を反映した適切な名前か

#### システム概要の生成

- [ ] 初期要望の内容を要約してシステム概要を生成しているか
- [ ] 具体性を保ちつつ簡潔にまとめているか
- [ ] システムが解決する課題や提供する価値が明確か

#### 出力形式

- [ ] JSON形式で出力しているか
- [ ] 出力先が `1_RDRA/システム概要.json` であるか
- [ ] JSONの形式が `{"system_name":"システム名","system_overview":"システム概要"}` に準拠しているか

### フェーズ6: 仕様を生成する

本チェックリストは、RDRAのフェーズ6「仕様を生成する」における確認項目をまとめたものです。
RDRA定義から具体的な仕様(論理データモデル、ビジネスルール、画面一覧)を生成しているかを確認します。

#### 論理データ生成

- [ ] RDRAの「情報」から論理データモデルを生成しているか
- [ ] 情報の属性で構造を持っているものは別論理データとして抜き出しているか
- [ ] 親子関係がある情報は親と子の論理データに分割しているか
- [ ] データはユニークな主キーを持っているか
- [ ] バリエーションは「enum」タイプとして定義しているか
- [ ] ER図をMermaid Diagramで作成しているか
- [ ] 出力ファイルが「2_RDRASpec/論理データモデル.md」であるか

#### ビジネスルール生成

- [ ] RDRAの「条件」をビジネスルールとして出力しているか
- [ ] 名前の付いた計算式は条件名と計算式のペアで表現しているか
- [ ] 2次元のマトリックスは縦横の組合せで規定されているか
- [ ] 状態モデルが関係する場合は縦軸または横軸に設定しているか
- [ ] バリエーションが関係する場合は縦軸または横軸に設定しているか
- [ ] 出力ファイルが「2_RDRASpec/ビジネスルール.md」であるか

#### 画面一覧生成

- [ ] RDRA定義から画面一覧(JSON)を生成しているか
- [ ] 画面項目(fields)が定義されているか
- [ ] 画面データ(screen_datas)が3件生成されているか
- [ ] 機能名(operation)が適切に設定されているか
- [ ] 出力ファイルが「2_RDRASpec/Phase1/画面一覧.json」であるか

#### BUC画面生成

- [ ] 画面と業務/BUC、アクターとの関係を定義しているか
- [ ] 画面は「画面一覧.json」で定義されているものを使用しているか
- [ ] 架空の画面を生成していないか
- [ ] 出力ファイルが「2_RDRASpec/phase1/BUC画面.json」であるか

#### アクター画面生成

- [ ] 画面とアクターの関係を定義しているか
- [ ] 画面は「画面一覧.json」で定義されているものを使用しているか
- [ ] 架空の画面を生成していないか
- [ ] 出力ファイルが「2_RDRASpec/phase1/アクター画面.json」であるか

### フェーズ7: 画面照会を生成する

本チェックリストは、RDRAのフェーズ7「画面照会を生成する」における確認項目をまとめたものです。
画面一覧.jsonにデータアクセス情報を追記し、BUC画面.jsonとアクター画面.jsonとまとめて画面照会.jsonを生成しているかを確認します。

#### 画面照会の生成

- [ ] 画面一覧.jsonの「screens」に「data_access」を追記しているか
- [ ] BUC画面.jsonの「businesses」をそのまま出力しているか
- [ ] アクター画面.jsonの「actorGroups」をそのまま出力しているか
- [ ] 3つを一つにまとめて「画面照会.json」として出力しているか

#### データアクセス（data_access）

- [ ] 画面の機能に必要なentityを「論理データモデル.md」から洗い出しているか
- [ ] 画面に必要な項目を満たす論理データ(entity)から関係を洗い出しているか
- [ ] 画面とEntityの関係は「画面 → UC → 情報」の関係を頼りに類推しているか
- [ ] 関係するentityとの関係をC,R,U,Dで示しているか
- [ ] isMainが適切に設定されているか（一つの画面に主となるEntityは一つ）

#### 出力ルール

- [ ] 出力ファイルが「2_RDRASpec/画面照会.json」であるか
- [ ] 関連データ.txtの「画面-アクター」定義を全て網羅しているか
- [ ] 同一画面に複数アクターがいる場合、全てのアクターが出力されているか
- [ ] businesses内のscreensが全ての画面を網羅しているか

### 要件組み立てフェーズ

本チェックリストは、抽出した要素同士を関連付け、ユースケースを中心に要件を具体化するフェーズにおける確認項目です。

#### ユースケースの導出

- [ ] 業務からユースケース (UC)を導き出しているか
- [ ] 画面（人と関わる入出力）が特定されているか
- [ ] イベント（外部システムとの連携）が特定されているか
- [ ] ユースケース一覧が作成されているか

#### 要素の関連付け

- [ ] 情報とユースケースを関連づけているか
- [ ] 状態とユースケースを関連づけているか
- [ ] アクターをユースケースに関連付けているか
- [ ] 外部システムをユースケースに関連付けているか
- [ ] UC複合図が作成されているか

#### 整合性確認

- [ ] 要素間の参照関係に誤りがないか確認しているか
- [ ] 未使用の要素がないか確認しているか
- [ ] ユースケースを軸に、アクター・外部システム・情報などの要素との関係を俯瞰的に確認しているか

#### RDRAモデルの出力と完了確認

**ファイル出力**

- [ ] 構築したRDRAモデルを `docs/22 要件定義書` ディレクトリに出力しているか
- [ ] 入力元として `docs/21 要望` ディレクトリ内のファイルを使用しているか
- [ ] 元の要件ドキュメントを変更していないか
- [ ] 出力ディレクトリ構造が適切か

**ユーザー確認**

- [ ] 構築したRDRAモデル（4レイヤー、ダイアグラム）をユーザーに提示しているか
- [ ] モデルの内容について質問・修正を促しているか
- [ ] 最終確認を得ているか
- [ ] AIが要求を一方的に決定していないか

**完了報告**

- [ ] 出力したファイルパスをユーザーに報告しているか
- [ ] 実装順序の推奨を提案しているか
- [ ] 次のステップを提案しているか
- [ ] GitHub Issuesは作成していないか（ユーザーの判断に委ねる）

#### 用語集の作成確認

- [ ] ユースケースに現れる名詞 / 名詞句を元に用語集を作成しているか
- [ ] サブドメイン毎に用語辞書を作成しているか
- [ ] 用語分類一覧が作成されているか
- [ ] 用語集のTSVファイルが作成されているか

#### 画面定義書確認

- [ ] 画面定義書が作成されているか
- [ ] 画面レイアウトが明確か
- [ ] 入力項目と出力項目が定義されているか
- [ ] バリデーションルールが定義されているか
- [ ] 画面とユースケースの関連付けが適切か

#### ユーザーストーリーマップ確認

- [ ] ユーザーストーリーマップが作成されているか
- [ ] ストーリーが適切にスライスされているか
- [ ] リリース計画との整合性が取れているか

#### トレースアビリティ確認

- [ ] トレースアビリティ（トレーサビリティ）が確保されているか
- [ ] 要求からユースケース、情報、状態へのトレーサビリティが明確か
- [ ] トレースアビリティのTSVファイルが作成されているか
