### 2.6 フェーズ6: 仕様を生成する

**目的**: RDRA定義から具体的な仕様を生成し、論理データモデル、ビジネスルール、画面一覧を作成する。

**対応レイヤー**: システムレイヤーとシステム境界レイヤーの仕様化。

フェーズ6では、フェーズ1~5で定義したRDRA要素を基に、具体的な仕様を生成します。論理データモデル(ER図)、ビジネスルール(テーブル形式)、画面一覧(JSON)の3つの仕様を作成し、後続の設計プロセスに引き継ぎます。

#### 論理データ生成

RDRAの「情報」から論理データモデル(ER図)を生成します。情報の属性構造や親子関係に基づいて正規化し、Mermaid ER図として出力します。

**論理データの構造**

論理データは以下のカラムから構成されます。

| カラム     | 説明                                                                                           |
|------------|------------------------------------------------------------------------------------------------|
| データ名   | entity名                                                                                       |
| 項目名     | カラム名                                                                                       |
| タイプ     | 「string」or「number」or「enum」or「boolean」                                                    |
| isKey      | boolean (true: 主キー、false: 主キー以外)                                                       |
| 説明       | 項目名の説明                                                                                   |

**情報から論理データへの変換ルール**

- 情報の属性で構造を持っているものは別論理データとして抜き出す
  - 例: 住所は{郵便番号, 都道府県, 市区町村}で構成される場合は、住所を別論理データとする
- 親子関係がある情報は親と子の論理データに分割する
  - 例: 受注情報は受注と受注明細に分け、受注明細に外部キー「受注ID」を持つ
  - 例: 会員情報は会員と個人情報に分け、会員に外部キー「個人情報ID」を持つ

**論理データ作成ルール**

- データはユニークな主キーを必ず持ち、項目名は「データ名＋"_ID"」とする
- 項目がバリエーションの場合は、バリエーション名を項目名にする
- タイプの「enum」はRDRAのバリエーションに対応する
- データ名_IDはユニークな数字で0からシーケンスにアップする
- 他データを参照する項目名はデータ名にIDを付けた名前にする「データ名_ID」
- 論理データの構造は「情報」の関連情報を参考に正規化に従って作成する
- 親子関係は子エンティティに親のIDを保持する
- 状態モデルの状態を管理する項目を持つ

**出力ルール**

- 論理データを元にER図を「Mermaid Diagram」で作成する
- Diagramの前後は必ず「```mermaid」と「```」で囲む
- 出力ファイル: 「2_RDRASpec/論理データモデル.md」

#### ビジネスルール生成

RDRAの「条件」をビジネスルールとしてMarkdownのテーブル形式で出力します。

**ビジネスルールの表現形式**

ビジネスルールの出力は2種類に分かれます。

1. **名前の付いた計算式**: 条件名と計算式のペアで表現
   - 例: 消費税: 金額 × 0.1

2. **2次元のマトリックス**: 縦横の組合せで規定される
   - 条件に状態モデルが関係しているときは、縦軸か横軸に状態モデルの各状態を結びつける
   - 条件にバリエーションが関係しているときは、縦軸か横軸にバリエーションの各値を結びつける
   - 条件に状態モデルとバリエーションの両方が設定されているときは縦軸と横軸で組み合わせる
   - マトリックスの縦軸と横軸の組合せの中の値は、条件の役割から導かれる値を設定する

**出力ルール**

- 出力ファイル: 「2_RDRASpec/ビジネスルール.md」
- 各ビジネスルールは目的と使われ方を説明する
- ビジネスルールはMarkdownのテーブル形式で出力する

#### 画面一覧生成

RDRA定義から画面一覧(JSON)を生成します。画面項目(fields)、画面データ(screen_datas)、機能(operation)を定義します。

**画面の項目を洗い出す**

- 画面に必要な項目は画面につながるUCに必要な項目から決まる
- 画面の項目は以下の観点で洗い出す
  - 画面と関係する情報の項目: 画面 → UC → 情報
  - 画面につながるアクターの役割から必要な項目
  - 画面につながるUCの役割から必要な入力項目
- 画面の項目typeの決め方
  - バリエーションや分類、状態モデル、状態などの複数の値を持つ場合は「enum」を設定する
  - 名前や住所などの場合は「string」を設定する
  - 金額や数量などの場合は「number」を設定する
  - 上記以外は「string」を設定する

**機能名の種類**

| 機能名 | 説明                                                                                           |
|--------|------------------------------------------------------------------------------------------------|
| 一覧   | 一覧形式でデータを表示する                                                                     |
| 照会   | 現在の状況の把握。データを表示する                                                             |
| 登録   | 画面から情報を入力し新たな情報を追加、更新、削除する                                           |
| 分析   | データを分析する機能をもつ                                                                     |
| 申請   | ワークフローで申請する情報を入力する                                                           |
| 承認   | ワークフローで登録されたデータを承認/却下する                                                  |

**画面データ**

- 画面毎に3件のダミーデータを生成する
- dummy_dataはfieldsの項目名に対応する項目を持つ

**出力フォーマット**

```json
{
  "screens": [{
    "screen_name": "画面名",
    "fields": [{
        "field_name": "項目名",
        "type": "string|number|enum",
        "tooltip": "項目の説明"
    }],
    "screen_datas": [{
        "display_name": "表示用のデータ",
        "dummy_data": [{"field_name": "項目名", "value": "値"}]
    }],
    "operation": "機能名",
  }]
}
```

- 出力ファイル: 「2_RDRASpec/Phase1/画面一覧.json」

#### BUC画面生成

画面と業務/BUC、アクターとの関係をJSON形式で定義します。

**構造**

- 関連データから全「業務」を抽出
- 各業務に関連する「BUC」を抽出
- BUCに関連する「アクター」を抽出 (業務 → BUC → アクティビティ → UC → 画面 → アクター)
- アクターにつながる「画面」を抽出
- 画面は「画面一覧.json」で定義されているものを使用し、架空の画面を生成しない

**出力フォーマット**

```json
{
  "businesses": [{
    "business_name": "業務名",
    "BUCs": [{
        "buc_name": "BUC名",
        "actors": [{
            "actor_name": "アクター名",
            "screen_names": ["画面名"]
        }]
    }]
  }]
}
```

- 出力ファイル: 「2_RDRASpec/phase1/BUC画面.json」

#### アクター画面生成

画面とアクターの関係をJSON形式で定義します。

**構造**

- 関連データから全「アクター群」を抽出
- 各アクター群に関連する「アクター」を抽出
- アクターにつながる画面を配置
- 画面は「画面一覧.json」で定義されているものを使用し、架空の画面を生成しない

**出力フォーマット**

```json
{
  "actorGroups": [{
    "group_name": "アクター群",
    "actors": [{
      "actor_name": "アクター名",
      "screen_names": ["画面名"]
    }]
  }]
}
```

- 出力ファイル: 「2_RDRASpec/phase1/アクター画面.json」
