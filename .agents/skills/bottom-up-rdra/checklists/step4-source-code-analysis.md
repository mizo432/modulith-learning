# ステップ4: ソースコードから分析 チェックリスト

**目的**: ソースコードとフォルダー構成から仕様として取り出せるものを探す。

---

## フォルダーの分析

- [ ] フォルダー構成やプログラムの分割単位を分析する
- [ ] トップダウンで分析したBUCやUCなどの名前とフォルダーの対応関係を整理する
- [ ] ソースコードへのインデックスとして使用する

### フォルダー分析の手順

- [ ] プロジェクトのディレクトリ構造を把握する
- [ ] パッケージ名・モジュール名から業務領域を推測する
- [ ] クラス名・メソッド名からUCやアクティビティを推測する
- [ ] トップダウンで分析したBUC・UCとフォルダーの対応関係を整理する

---

## ソースコードの分析

- [ ] フォルダー分析の結果をもとにソースコードを分析する
- [ ] トップダウンで分析したUC・画面・イベント・情報とソースコードの対応を整理する

### ソースコード分析の手順

- [ ] コントローラー/ハンドラーから画面・イベントとの対応を特定する
- [ ] サービス層からUCのロジックを特定する
- [ ] リポジトリ/DAO層から情報（エンティティ）との対応を特定する
- [ ] 状態遷移のロジックから状態モデルを特定する
- [ ] バリデーション・ビジネスルールから条件を特定する
