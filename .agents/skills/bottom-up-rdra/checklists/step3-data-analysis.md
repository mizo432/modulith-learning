# ステップ3: データから整理 チェックリスト

**目的**: DBスキーマとファイルからビジネス上の情報を洗い出す。

---

## DBスキーマから整理

### DBのスキーマ情報を出力する

- [ ] データベースのスキーマ情報を出力する
- [ ] テーブル一覧・カラム情報・制約情報を収集する

### ビジネスにつながるデータを洗い出す

- [ ] DBのテーブルをそのまま情報とはしない
- [ ] ビジネスで管理しているIDを洗い出す
- [ ] IDが識別できるデータ（情報）をRDRAの「情報」モデルに変換する

### 情報の属性と関連を整理する

- [ ] テーブルのカラムから情報の属性を抽出する
- [ ] 外部キー制約から情報同士の関連を抽出する
- [ ] 親子関係がある場合は親と子の情報に分割する

---

## ファイルから整理

- [ ] ファイル一覧を分類し、役割別（情報）に整理する
- [ ] ファイルフォーマットの資料から属性を抽出する

---

## 情報とUCをつなぐ（④）

- [ ] 抽出した情報がどのUCで操作されるかを特定する
- [ ] 「画面 → UC → 情報」の関係を頼りに類推する
- [ ] 情報同士の関連を関連情報として定義する

---

## 情報から状態を洗い出す（⑤）

- [ ] 情報から状態モデルを洗い出す
- [ ] 状態遷移にUCを当てはめる
- [ ] 状態遷移にUCが適用できない場合は、欠けているUCを洗い出す

### 状態モデルの抽出手順

- [ ] 情報に状態を示すカラム（ステータス・フラグなど）があるか確認する
- [ ] 状態の集合を状態モデルとして定義する
- [ ] 状態間の遷移を整理する
- [ ] 各遷移をトリガーするUCを特定する
