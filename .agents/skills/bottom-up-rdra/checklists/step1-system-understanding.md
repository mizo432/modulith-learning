# ステップ1: 分析対象システムの把握 チェックリスト

**目的**: 分析対象のシステム構成と利用可能な資料を把握し、分析計画を立てる。

---

## システム構成の把握

- [ ] 分析対象のシステムアーキテクチャを確認する
- [ ] アプリケーションサーバー・データベースサーバーを特定する
- [ ] 外部システムとの連携箇所を特定する
- [ ] ミドルウェア（API Gateway、メッセージキューなど）を特定する

---

## 利用可能な資料の収集・評価

- [ ] 画面一覧・画面のハードコピーを収集する
- [ ] 外部とのインターフェース一覧を収集する
- [ ] DBのスキーマ情報を収集する
- [ ] ファイルフォーマットの資料を収集する
- [ ] 機能一覧・機能詳細を収集する
- [ ] 契約書などの外部企業との資料を収集する
- [ ] バッチ処理/APIのドキュメントを収集する
- [ ] 収集した資料の信頼性を評価する

### 資料の種類とRDRAとの対応関係

| 資料の種類 | RDRAとの対応関係 | 信頼性評価のポイント |
|-----------|----------------|-------------------|
| 機能一覧 | 業務・BUC・UC | 大中小の分類を業務・BUC・UCに当てはめる |
| 画面一覧 | 画面・UC・アクター | 現在使われている画面をベースに整理 |
| インターフェース一覧 | イベント・外部システム | なければ外部企業との資料から整理 |
| テーブル一覧・ER図 | 情報・状態 | スキーマ情報から整理 |
| 機能詳細 | UC・条件・バリエーション | 条件や区分を洗い出すのに利用 |
| 契約書 | 条件（ビジネスルール） | ビジネスルールを条件として抽出 |

---

## ヒアリング可能な関係者の特定

- [ ] ヒアリングできる人が使っている資料は信頼性が高いことを確認する
- [ ] 資料の信頼性を関わる人の役割から把握する
- [ ] その資料を中心に全体を形づくっていく
