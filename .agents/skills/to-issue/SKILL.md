## Purpose

このSkillは、非機能要望を整理し、以下の2つの処理を行います。

1. 要望をIPAが定める6大カテゴリー毎にまとめる (Markdown形式)
2. 既に登録されているissueと重複チェックし、重複しないissueをGitHubに新規登録する

---

## IPA 非機能要件 6大カテゴリー

IPA (情報処理推進機構) が定める非機能要件の6大カテゴリーは以下の通りです。

| カテゴリー                   | 説明                                                                                           |
|------------------------------|------------------------------------------------------------------------------------------------|
| **可用性**                   | システムサービスを継続的に利用できるようにするための要件（稼働率、目標復旧時間、計画停止など） |
| **性能・拡張性**             | 処理速度や同時アクセス数、将来的なCPU・メモリなどのリソース増強に関する要件                    |
| **運用・保守性**             | 日々のシステム運用管理、バックアップ計画、障害時の対応、サポート体制に関する要件               |
| **移行性**                   | 現行システムからのデータ移行スケジュール、方式、移行対象に関する要件                           |
| **セキュリティ**             | 情報漏えい対策、アクセス制限、脆弱性診断、マルウェア対策などの安全性に関する要件               |
| **システム環境・エコロジー** | 設置場所の物理的条件、周辺機器、法的規制や環境負荷低減に関する要件                             |

## Workflow

### Step 1: 非機能要望の読み込み

プロジェクト内の非機能要望ドキュメントを読み込みます。

- 対象ディレクトリ: `docs/11 Requests/非機能要望/`
- 各 `.md` ファイルには `REQ-XXXXX` 形式の一意の識別子を持つ要望が記載されています。

### Step 2: カテゴリー分類

読み込んだ各要望をIPA 6大カテゴリーのいずれかに分類します。
分類結果をMarkdown形式でまとめます。

### Step 3: 既存issueとの重複チェック

GitHub API を使用して、既存のissue一覧を取得し、各要望が既にissueとして登録されていないか確認します。

- 重複判定基準: issueのタイトルまたは本文に `REQ-XXXXX` 識別子が含まれている場合、または同じ内容のissueが存在する場合
- 既に登録されているissueはスキップします。

### Step 4: 新規issueの登録

重複していない要望について、GitHub issueとして新規登録します。

- **タイトル**: `非機能要件: {要望の要約}`
- **本文**:
    - 元のREQ識別子 (例: `REQ-00001`)
    - カテゴリー (IPA 6大カテゴリーのいずれか)
    - 要望の詳細な説明
    - ラベル: `non-functional-requirement`, `{カテゴリー名}`

## Output Format

分類結果は以下のMarkdown形式で出力します。

```markdown

## 可用性

| REQ ID | 要望 | 対応issue |
|---|---|---|
| REQ-XXXXX | 要望の説明 | #XXX (新規登録) / #XXX (既存) |

## 性能・拡張性

| REQ ID | 要望 | 対応issue |
|---|---|---|

## 運用・保守性

| REQ ID | 要望 | 対応issue |
|---|---|---|

## 移行性

| REQ ID | 要望 | 対応issue |
|---|---|---|

## セキュリティ

| REQ ID | 要望 | 対応issue |
|---|---|---|

## システム環境・エコロジー

| REQ ID | 要望 | 対応issue |
|---|---|---|
```

## Notes

- 各要望は1つのカテゴリーにのみ分類します。複数のカテゴリーにまたがる場合は、最も関連性の高いものを選択します。
- GitHub issueの登録は、ユーザーの明示的な指示がある場合のみ実行します。
- 重複チェックはissueのタイトルと本文の両方を確認します。
