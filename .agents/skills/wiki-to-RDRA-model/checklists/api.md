# API 契約定義チェックリスト (API Contract Checklist)

## API の基本情報

- [ ] リソース名（URI パス）が明確に定義されているか
  - 例: `/api/v1/customers`, `/api/v1/sales`
- [ ] HTTP メソッド（GET / POST / PUT / DELETE / PATCH）が適切に指定されているか
- [ ] リソースの階層構造が RESTful 規約に従っているか

## リクエスト

- [ ] リクエストボディの形式（JSON スキーマ）が定義されているか
- [ ] 必須フィールドとオプションフィールドが明確になっているか
- [ ] クエリパラメータ（検索・フィルタ・ソート・ページネーション）が定義されているか
- [ ] パスパラメータ（リソースID等）が定義されているか
- [ ] リクエストのバリデーションルールが記載されているか

## レスポンス

- [ ] レスポンスボディの形式（JSON スキーマ）が定義されているか
- [ ] 正常系（200/201）のレスポンス形式が定義されているか
- [ ] 異常系（400/404/500等）のレスポンス形式が定義されているか
- [ ] ページネーション時のレスポンス形式が定義されているか

## ステータスコード

- [ ] 各エンドポイントで返すHTTPステータスコードが明示されているか
  - 200 OK: 取得成功
  - 201 Created: 作成成功
  - 204 No Content: 削除成功等
  - 400 Bad Request: バリデーションエラー
  - 401 Unauthorized: 認証失敗
  - 403 Forbidden: 権限不足
  - 404 Not Found: リソース不存在
  - 500 Internal Server Error: サーバーエラー

## 認証・認可

- [ ] 認証が必要なエンドポイントが明示されているか
- [ ] 認可（ロールベースのアクセス制御）が必要なエンドポイントが明示されているか

## 補足

- [ ] API のバージョン管理方針が記載されているか
- [ ] レートリミットやタイムアウトの制約がある場合、それが記載されているか
- [ ] Frontend と Backend の双方で API 契約に合意しているか
