# Issue作成チェックリスト (フェーズ3: 整合性・網羅性を確認し精度を高める)

本チェックリストは、RDRAのフェーズ3「整合性・網羅性を確認し精度を高める」における確認項目をまとめたものです。
要素間の参照関係の誤りや、定義された要素が実際のユースケースで使用されていないといった問題を早期に発見し、要件定義の整合性と網羅性を高めているかを確認します。

---

## Step7: システムが動く「条件」を整理する

### システムレイヤーの詳細化

- [ ] システムがどんなときに動くのか、という「条件」を整理しているか
- [ ] 条件（ビジネスルール）をユースケースに関連付けているか
- [ ] 単価表、承認ルールなどの条件が明確か
- [ ] バリエーション/条件図が作成されているか

---

## Step8: 「条件」を成り立たせる「バリエーション」を洗い出す

- [ ] 「条件」を成り立たせるための「バリエーション」を洗い出しているか
- [ ] 取引先、商品種類、顧客タイプなどのバリエーションが特定されているか
- [ ] バリエーションが条件と適切に関連付けられているか

---

## Step9: 条件とバリエーションを詳細化し、実装レベルにする

- [ ] それぞれの条件とバリエーションについて具体的な要素を洗い出しているか
- [ ] 実装に必要なレベルまで詳細にしているか
- [ ] RDRAモデル全体の整合性を確認しているか

### 不整合の検出

- [ ] 要素間の参照関係に誤りがないか確認しているか
- [ ] 未使用の要素がないか確認しているか
- [ ] 定義された要素が実際のユースケースで使用されているか

### 全体俯瞰

- [ ] ユースケースを軸に、アクター・外部システム・情報などの要素との関係を俯瞰的に確認しているか
- [ ] 情報モデル図が作成されているか
- [ ] 状態モデル図が作成されているか

---

## RDRAモデルの出力と完了確認

### ファイル出力

- [ ] 構築したRDRAモデルを `docs/22 要件定義書` ディレクトリに出力しているか
- [ ] 入力元として `docs/21 要望` ディレクトリ内のファイルを使用しているか
- [ ] 元の要件ドキュメントを変更していないか
- [ ] 出力ディレクトリ構造が適切か:
    - [ ] `11.事業領域`: 事業領域一覧 (MD/TSV) — `docs/11.事業領域/` に配置
    - [ ] `12 業務領域`: 業務領域一覧 (MD/TSV)、各業務領域毎にデータベース定義 (MD/TSV) —
      `docs/12 業務領域/` に配置
        - [ ] `03 非機能要件大項目`: 非機能要件大項目一覧 (MD/TSV)
            - [ ] `04 情報`: 関連付けと開発運用の2つのカテゴリ
                - [ ] `02.関連付け`: 各業務領域毎の情報一覧 (TSV)
                - [ ] `03.開発運用`: 開発運用関連の情報一覧 (TSV)
                - [ ] `05 非機能要件`: 非機能要件大項目毎の非機能要件定義 (TSV)
                    - [ ] `01.セキュリティ`、`02.パフォーマンス`、`03.可用性`、`04.信頼性`、`05.保守性`、
                      `06.移植性`、
                      `07.データベース定義`
            - [ ] `06 機能要件`: 関連付けと開発運用の2つのカテゴリ
                - [ ] `02.関連付け`: 各業務領域毎のRDRA 4レイヤー詳細定義
                - [ ] `03.開発運用`: 開発運用関連のRDRA 4レイヤー詳細定義
            - [ ] `07 用語集`: 用語分類一覧 (TSV) と各業務領域毎の用語集 (MD)

### ユーザー確認

- [ ] 構築したRDRAモデル（4レイヤー、ダイアグラム）をユーザーに提示しているか
- [ ] モデルの内容について質問・修正を促しているか
- [ ] 最終確認を得ているか
- [ ] AIが要求を一方的に決定していないか

### 完了報告

- [ ] Wikiに出力したファイルパスまたはページURLをユーザーに報告しているか
- [ ] 実装順序の推奨を提案しているか
- [ ] 次のステップを提案しているか
- [ ] GitHub Issuesはこのスキルでは作成していないか（ユーザーの判断に委ねる）

## トレースアビリティ確認

- [ ] トレースアビリティ（トレーサビリティ）が確保されているか

## 共通確認項目

- [ ] 4つのレイヤーが厳格に区別されているか
- [ ] 各レイヤー間の「Why」の依存関係が明確か
- [ ] 粒度が要件レベルで統一されているか
- [ ] AIが要求を一方的に決定していないか（ユーザーの確認を得ているか）
- [ ] 元の要件ドキュメントを変更していないか
- [ ] ダイアグラムがコミュニケーションツールとして適切に使用されているか
