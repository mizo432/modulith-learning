# ユースケース記述品質チェックリスト (Use Case 3.0)

本チェックリストは、Ivar JacobsonのUse Case 3.0に基づいたユースケース記述の品質を確認するためのものです。
ユースケース記述を作成・レビューする際に、以下の項目を確認してください。

---

## 基本情報

- [ ] ユースケース名は簡潔で記述的か（動詞+名詞の形式）
- [ ] アクターは役割として命名されているか（個人名ではない）
- [ ] 主要アクターと補助アクターが明確か
- [ ] 目標はアクターが達成する機能目標として記述されているか

---

## 前提条件とトリガー

- [ ] 前提条件はユースケース開始前に満たされている条件として記述されているか
- [ ] トリガーはユースケースのイベントフローを開始するイベントとして記述されているか

---

## 基本フロー

- [ ] 基本フローは番号付きのステップリストとして記述されているか
- [ ] 各ステップは「アクター/システム + 動詞 + 目的語」の形式か
- [ ] 能動態で使用されているか
- [ ] 設計詳細（色、フィールド位置、ボタン名など）は含まれていないか
- [ ] ビジネスルールは別途管理されているか
- [ ] 終了ステップでユースケースの完了が明確か

---

## 代替フロー

- [ ] 代替フローは名前としてリストされているか
- [ ] 代替フローは必要に応じて詳細化されているか

---

## 後件条件と制約

- [ ] 後件条件はユースケース完了後のシステム状態として記述されているか
- [ ] 制約は適用される制約条件として記述されているか

---

## サポート情報

- [ ] サポート情報は用語定義やビジネスルールを含んでいるか

---

## 記述品質

- [ ] 読みやすさが優先されているか
- [ ] 過度な詳細化は避けられているか
- [ ] ファイル名が「UC-{番号} ユースケース名.md」の形式か

---

## 段階的な詳細化

- [ ] Basic Flowを先に記述しているか
- [ ] Alternate FlowsをBasic Flow記述過程中に発見してメモしているか
- [ ] 必要に応じてAlternate Flowsの詳細を追加しているか
- [ ] テストケースが定義されているか

---

## 共通確認項目

- [ ] 4つのレイヤーが厳格に区別されているか
- [ ] 各レイヤー間の「Why」の依存関係が明確か
- [ ] 粒度が要件レベルで統一されているか
    - UC: それを実行することで実行した人に何かうれしいことがある
    - 情報モデル: エンティティレベル以上
- [ ] AIが要求を一方的に決定していないか（ユーザーの確認を得ているか）
- [ ] 元の要件ドキュメントを変更していないか
