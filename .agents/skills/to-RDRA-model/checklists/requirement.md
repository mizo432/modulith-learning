# 要件分析チェックリスト (フェーズ1: 枠組みを作る)

本チェックリストは、RDRAのフェーズ1「枠組みを作る」における確認項目をまとめたものです。
システム化対象となる業務全体とシステム化の範囲を早期に可視化し、関係者間で共通認識を形成するための「議論の土台」が整っているかを確認します。

---

## Step1: アクター/外部システムと業務を洗い出す

### システム価値レイヤー

- [ ] 機能要求を記載しているか
- [ ] 非機能要求を記載しているか
- [ ] システムを利用する人や組織の役割（アクター）をリストアップしているか
- [ ] 連携が必要な既存システムや外部サービス（外部システム）をリストアップしているか
- [ ] アクターは役割として命名されているか（個人名ではない）
- [ ] 外部システムの定義が明確か（システム名、連携内容、連携方法）

### システム外部環境レイヤー

- [ ] システム化の対象となる「業務」を洗い出しているか
- [ ] 業務を構成する「ビジネスユースケース (BUC)」を洗い出しているか
- [ ] 1つの「業務」が部署や課やチームなどの組織単位で担われるまとまりとして適切か
- [ ] 事業領域一覧が作成されているか
- [ ] 業務領域一覧が作成されているか

---

## Step2: 業務の流れを把握し、アクティビティを見える化する

- [ ] ビジネスユースケースを構成する「アクティビティ」を洗い出しているか
- [ ] アクティビティが業務フローの中で実行される個々の作業や行動として適切か
- [ ] 1つのビジネスユースケースが業務フローを一連の目的を持った流れとして過不足なく表しているか
- [ ] BUCが大きすぎる場合は分割しているか
- [ ] BUCが細かすぎる場合は統合しているか
- [ ] 業務フロー図が作成されているか

---

## Step3: 業務で扱う情報を明らかにする

### システムレイヤー

- [ ] 業務で扱う「情報」をリストアップしているか
- [ ] システムで管理すべき情報を特定しているか
- [ ] 情報が複数のユースケース間の連携を表すものとして適切か
- [ ] 情報一覧（データ一覧）が作成されているか
- [ ] 情報の属性定義が明確か

---

## Step4: 業務の中で「状態」を洗い出す

- [ ] 業務の中で「こういう状態になる」というものを洗い出しているか
- [ ] 「状態」をリストアップしているか（例: 「xx済」「xx待ち」「xx中」）
- [ ] 状態の遷移がユースケースが実現すべき情報の変化を表すものとして適切か
- [ ] ステート一覧が作成されているか
- [ ] ステートマシン図が作成されているか

---

## 共通確認項目

- [ ] 4つのレイヤーが厳格に区別されているか
    - システム価値レイヤー: 要求、アクター、外部システム
    - システム外部環境レイヤー: 業務、BUC、アクティビティ
    - システム境界レイヤー: ユースケース、アクター
    - システムレイヤー: 情報、状態、条件、バリエーション、画面、イベント、帳票
- [ ] 各レイヤー間の「Why」の依存関係が明確か
- [ ] 粒度が要件レベルで統一されているか
- [ ] AIが要求を一方的に決定していないか（ユーザーの確認を得ているか）
- [ ] 元の要件ドキュメントを変更していないか
