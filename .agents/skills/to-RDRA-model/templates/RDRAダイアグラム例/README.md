## RDRAの4レイヤーとダイアグラムの対応

| レイヤー                 | ダイアグラム                             | 説明                                               |
|--------------------------|------------------------------------------|----------------------------------------------------|
| システム価値レイヤー     | -                                        | 要求、アクター、外部システム                       |
| システム外部環境レイヤー | 利用シーン図                             | 業務フローをユースケースとして可視化               |
| システム境界レイヤー     | ユースケース複合図                       | ユースケース・画面・イベント・情報・条件を関連付け |
| システムレイヤー         | ステートマシン図、バリエーション・条件図 | 状態遷移とビジネスルール                           |

## ダイアグラムの種類

### 1. 利用シーン図（ユースケース図）

業務フローをユースケースとして可視化し、誰がどの業務に参加するかを明確にします。
アクターとビジネスユースケース（BUC）の関係を表現します。

### 2. バリエーション・条件図

表形式でビジネスルールを定義します。

- **バリエーション**: ビジネス上に登場する値（本種別、遅延日数、会員種別など）
- **条件**: バリエーションの組み合わせで決まるルール（貸出制限、遅延料金など）
- **名前つけられた式**: 再利用可能な計算式（貸出期限、取置期限など）

### 3. ユースケース複合図

ユースケース、画面（boundary）、情報（entity）、条件（control）を関連づけて表現します。
システム境界レイヤーとシステムレイヤーをまたいで、要素間の関係性を視覚的に表現します。

### 4. ステートマシン図（状態遷移図）

情報の状態遷移を可視化します。
各状態間の遷移と、その遷移をトリガーするユースケースを明記します。

### 5. 用語集

システムで使用する用語を定義し、共通認識を形成します。
用語の定義を統一することで、要件定義の整合性を保ちます。

## PlantUML の使い方

各ダイアグラムは PlantUML で記述されています。
PlantUML を使用してダイアグラムをレンダリングするには、以下の方法があります。

1. **IDE プラグイン**: IntelliJ IDEA の PlantUML プラグインを使用
2. **コマンドライン**: `java -jar plantuml.jar diagram.puml`
3. **オンライン**: [PlantText](https://www.planttext.com/) でプレビュー

## 補足

- RDRAではダイアグラムよりもモデル要素間のつながりを重視します。
- ダイアグラムはコミュニケーションツールとして使用し、ドキュメントとして保持するものではありません。
- プロジェクトの状況に応じてダイアグラムを使い分けます。
