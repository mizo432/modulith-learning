# バリエーション・条件図 - 図書館システム例

本ファイルは、Qiita記事「PlantUML で始めるリレーションシップ駆動要件分析 (RDRA)」を参考にした、
RDRAのバリエーション・条件図の例です。

バリエーション・条件図は図とありますが、実体は表形式で表現します。

- **バリエーション** はビジネス上に登場する値であり、重要なビジネスルールの基準になるような情報です。
- **条件** は単純なものは「名前つけられた条件」としてまとめ、バリエーションの組み合わせで条件が決まるものは条件ごとに表形式で表現します。

表形式なので Markdown のテーブルやスプレッドシートなどで作成して、それを実体とします。
ユースケース複合図で参照するときは、エイリアスを `control` のアイコンで表現して関連付けます。

## 1. バリエーション

### 本種別

| バリエーション名   | 説明                     |
|--------------------|--------------------------|
| 書籍               | 一般的な書籍             |
| 館内閲覧用専用書籍 | 館内でのみ閲覧可能な書籍 |
| DVD                | DVD 媒体                 |
| CD                 | CD 媒体                  |

### 遅延日数

| バリエーション名 | 説明          |
|------------------|---------------|
| 遅延日数 < 3日   | 3日未満の遅延 |
| 遅延日数 < 7日   | 7日未満の遅延 |
| 上記以外         | 7日以上の遅延 |

### 会員種別

| バリエーション名 | 説明     |
|------------------|----------|
| 大人             | 成人会員 |
| 子供             | 子供会員 |

## 2. 名前つけられた式

| 名前     | 式                   | 説明                   |
|----------|----------------------|------------------------|
| 貸出期限 | 貸出日 + 14日        | 本を返却すべき期限     |
| 取置期限 | 貸出準備完了日 + 7日 | 予約図書を置きおく期限 |

## 3. 条件

### 貸出制限: 条件

2軸の組み合わせであれば以下のような表になります。

| 遅延日数 \ 会員種別 | 大人             | 子供             |
|---------------------|------------------|------------------|
| 遅延日数 < 3日      | 1人5冊まで       | 1人7冊まで       |
| 遅延日数 < 7日      | 本の貸し出し不可 | 1人4冊まで       |
| 上記以外            | 本の貸し出し不可 | 本の貸し出し不可 |

### 遅延料金: 条件

| 遅延日数 \ 本種別 | 書籍          | DVD            | CD             |
|-------------------|---------------|----------------|----------------|
| 遅延日数 < 3日    | 1日あたり10円 | 1日あたり50円  | 1日あたり30円  |
| 遅延日数 < 7日    | 1日あたり20円 | 1日あたり100円 | 1日あたり50円  |
| 上記以外          | 1日あたり50円 | 1日あたり200円 | 1日あたり100円 |

### 貸出可能期間: 条件

| 本種別 \ 会員種別  | 大人     | 子供     |
|--------------------|----------|----------|
| 書籍               | 14日     | 14日     |
| 館内閲覧用専用書籍 | 館内のみ | 館内のみ |
| DVD                | 7日      | 7日      |
| CD                 | 7日      | 7日      |

## 4. 予約貸出通知メッセージ: 条件

予約図書の準備が完了した際に送信するメッセージの内容を定義します。

| 通知方法 | メッセージ内容                                                               |
|----------|------------------------------------------------------------------------------|
| メール   | 「ご予約の『{蔵書名}』の準備ができました。{取置期限}までにお越しください。」 |
| SMS      | 「予約図書『{蔵書名}』の準備完了。{取置期限}迄にお越しください。」           |

## 5. 補足

- バリエーション・条件図は、RDRAの「システムレイヤー」で使用する表形式のモデルです。
- 条件はユースケース複合図で `control` アイコンとして参照されます。
- 3軸以上の組み合わせでもマトリックス形式で表現可能です。
