# フェーズ5: 整合性確認 チェックリスト

**目的**: 要件定義と詳細設計の整合性を確認し、漏れ・矛盾を特定する。

---

## UCのカバー率確認

- [ ] 全UCがAPIまたはバッチとして定義されているか確認する
- [ ] 画面経由のUCはREST APIとして導出されているか確認する
- [ ] 外部システム経由のUCはバッチまたはAPIとして導出されているか確認する
- [ ] 未カバーのUCがないか確認する

---

## 情報のカバー率確認

- [ ] 全情報がテーブルとして定義されているか確認する
- [ ] 全属性がカラムとして定義されているか確認する
- [ ] 情報間の関連が外部キーとして定義されているか確認する
- [ ] 未定義の情報・属性がないか確認する

---

## 画面のカバー率確認

- [ ] 全画面がフロントエンド設計として定義されているか確認する
- [ ] 画面項目がUIコンポーネントとして定義されているか確認する
- [ ] 画面操作がAPI連携ポイントとして定義されているか確認する
- [ ] 未定義の画面がないか確認する

---

## 状態・バリエーションの確認

- [ ] 全状態モデルが列挙型カラムとして定義されているか確認する
- [ ] 全バリエーションが列挙型カラムとして定義されているか確認する
- [ ] 状態遷移がAPIまたはバッチとしてカバーされているか確認する
- [ ] 列挙値が正しく定義されているか確認する

---

## 条件の確認

- [ ] 全条件がビジネスルールとして実装計画に含まれているか確認する
- [ ] 条件がAPIのバリデーションルールまたはバッチの処理ロジックとして反映されているか確認する
- [ ] 未反映の条件がないか確認する

---

## 非機能要件の確認

- [ ] 非機能要件が詳細設計に反映されているか確認する
- [ ] ADRで決定された事項が設計に反映されているか確認する
- [ ] セキュリティ要件がAPI設計に反映されているか確認する
- [ ] パフォーマンス要件がデータベース設計に反映されているか確認する

---

## 命名規則の確認

- [ ] テーブル名・カラム名の命名規則が一貫しているか確認する
- [ ] APIパスの命名規則が一貫しているか確認する
- [ ] スキーマ名が正しいか確認する
- [ ] 事業領域コード・業務領域コードが正しいか確認する

---

## 最終確認

- [ ] 要件定義と詳細設計の整合性が取れているか確認する
- [ ] 漏れ・矛盾・不整合がないか確認する
- [ ] 全フェーズのチェックリストが完了しているか確認する
- [ ] 詳細設計書のindex.mdが更新されているか確認する
