# バッチ設計チェックリスト (Batch Design Checklist)

バッチ処理の設計時・実装時に以下の項目を確認してください。

### 1. パッケージ構成

- [ ] バッチ処理が `internal/batch` 配下に配置されている
- [ ] パッケージ構成（config/reader/processor/writer/dto/operator）が守られている
- [ ] 外部API連携が必要な場合は `client` パッケージに分離されている

### 2. Job / Step の設計

- [ ] Job名・Step名が定数として定義されている
- [ ] チャンクサイズが適切に設定されている（デフォルト50）
- [ ] 大量レコードの場合はチャンクサイズを100〜500の範囲で調整している
- [ ] 複数Stepの連鎖は `.start()` → `.next()` で明確に定義されている
- [ ] Tasklet Step で `@StepScope` を使用してJobParametersにアクセスしている

### 3. エラー処理とフォールトトレランス

- [ ] `.faultTolerant()` が設定されている
- [ ] `.skip()` と `.skipLimit()` が設定されている（デフォルト: 10）
- [ ] `.retry()` と `.retryLimit()` が設定されている（デフォルト: 3）
- [ ] Processorで不正なデータはログに記録してnullを返す（スキップ）
- [ ] エラーログに機密情報が含まれていない

### 4. Reader 設計

- [ ] Readerがストリーミング方式で実装されている（全データをメモリに読み込まない）
- [ ] CSV Reader で Super CSV を使用している
- [ ] CSVヘッダーの日本語/英語両方に対応している
- [ ] ExecutionContext をサポートしてチェックポイント機能を有効化している
- [ ] ZIPファイル内のCSV読み込みの場合は ZipFile を使用している

### 5. Processor 設計

- [ ] 入力検証が適切に行われている（nullチェック、必須フィールド検証）
- [ ] 既存データとの整合性が確認されている（新規作成 vs 更新）
- [ ] 日付パースが複数の形式に対応している
- [ ] パース失敗時はデフォルト値を使用し、ログに警告を記録している
- [ ] スキップしたレコードの詳細を `log.warn()` で記録している

### 6. Writer 設計

- [ ] Writerが一括保存（saveAll）を使用している
- [ ] 不要な中間データを保持していない
- [ ] チャンク単位の処理のみを行い、N+1問題を防いでいる

### 7. CSV DTO 設計

- [ ] DTOがSerializableを実装している
- [ ] DTOのフィールドが @Nullable として宣言されている
- [ ] フィールド名がCSVのヘッダー名に対応するcamelCaseである
- [ ] DTOはデータ保持に特化し、変換ロジックはProcessorに委譲している

### 8. Job Operator 設計

- [ ] OperatorでJobParametersが適切に構築されている
- [ ] timestamp パラメータを追加して重複実行を防いでいる
- [ ] スケジューリングが `@Scheduled` で設定されている
- [ ] cron式がプロパティで外部化されている
- [ ] スケジュール実行時の例外をキャッチしてログに記録している

### 9. 外部API連携

- [ ] APIクライアントが `client` パッケージに分離されている
- [ ] API設定が `@ConfigurationProperties` で外部化されている
- [ ] ダウンロードStepでファイルの完全性（チェックサム）を確認している
- [ ] インポート履歴が追跡可能になっている

### 10. テスト

- [ ] Processorの単体テストが境界値・異常系を網羅している
- [ ] 統合テストがReader → Processor → Writerのフルフローを検証している
- [ ] テスト用のCSVファイルが `src/test/resources/data/` に配置されている
- [ ] テストデータが境界値を含む（空フィールド、特殊文字、長い文字列）
- [ ] テストメソッド名が `should` で開始している

### 11. テストパフォーマンス最適化

- [ ] Testcontainersが静的フィールドで共有されている（テストクラス間で1回だけ起動）
- [ ] 不要な `@BeforeEach` と `deleteAll()` が削除されている
- [ ] テストが独立してJobを実行し、テスト間の依存性がない
- [ ] テストの並列実行が考慮されている（必要に応じて）
