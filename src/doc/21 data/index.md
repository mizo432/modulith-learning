# TM（T字形ER）モデル作成の手順【要約】

## 🔢 手順一覧

| 手順 | 内容の要点                      |
|----|----------------------------|
| ①  | モノを集める（語彙収集・仕訳）            |
| ②  | モノを分類する（イベント／リソース）         |
| ③  | モノを並べる（時系列／関与順）            |
| ④  | 関係を構成する（E-R, E-E, R-R, 再帰） |
| ⑤  | 集合（セット）を作る（サブセットの分離）       |
| ⑥  | 多値を扱う（OR関係／AND関係）          |
| ⑦  | クラスで整える（性質の切り出し）           |
| ⑧  | まとめ／検証（L-真網羅性・F-真対応）       |

## 各手順のポイント

### ① モノを集める

- 画面・帳票などから**語彙（項目）**を抜き出す
- 「番号・コード」は左（個体指定子）、「属性」は右に仕訳
- 「ユーザー言語」を勝手に変形しない

---

### ② モノを分類する

- イベント（E）：出来事・行為・取引。日付が伴う
- リソース（R）：物理／論理的な存在。イベント以外

例：受注（E）、顧客／商品（R）

### ③ モノを並べる

- イベントは時系列（全順序）で並べる
- リソースは関与順（半順序）で十分

---

### ④ 関係を構成する

- 関係 = 関数（f(a, b)）で表現
- 種類：
    - E-R（受注 → 顧客・商品）
    - E-E（受注 → 請求など）
    - R-R（従業員 ⇔ 部門などの対照）
    - 再帰（部品構成、赤黒伝票など）

### ⑤ 集合（セット）を作る

- 区分コードによるサブセット（部分集合）
- 例：顧客 → 会員/非会員、従業員 → 正社員/パート
- AND関係や階層関係がある場合は「対照表」で表現

---

### ⑥ 多値の取り扱い

- 多値OR（MO）：正価・割引など複数候補（→ 正規化）
- 多値AND（MA）：受注と複数明細（→ ヘッダ・ディテール分割）

---

### ⑦ クラスで整える

- 混ざった属性（リソースにイベント性質など）を切り出し
- 右側クラス（条件・分類）は構造とは独立し文脈依存

### ⑧ まとめと検証

- 構文論（L-真）：矛盾のない構造を保証
- 意味論（F-真）：現実と一致しているか検証
- 「関係の網羅性」「束縛の網羅性」を満たすことが目的

---

## 🧪 活用例（受注モデル）

| モノ   | 分類 | 個体指定子     | 備考            |
|------|----|-----------|---------------|
| 顧客   | R  | 顧客番号      | 会員区分でサブセット化   |
| 商品   | R  | 商品コード     | 複数価格（MO）対応    |
| 受注   | E  | 受注番号      | ヘッダ・明細に分割（MA） |
| 出荷   | E  | 出荷番号      | 受注に1:1対応      |
| 地域・便 | R  | 地域コード／便番号 | 多対多（対照表）      |
