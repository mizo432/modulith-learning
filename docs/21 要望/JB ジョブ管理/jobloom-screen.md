# Jobloom：必要な画面一覧

Jobloom のアクターとユースケースをもとに、必要な画面を整理します。業務処理や業務担当者向けのファイルアップロード画面は個別業務システム側の責務とし、Jobloom
はジョブの実行管理・監視・運用に専念する構成です。

## 1. 画面一覧

画面を機能別に分類し、画面 ID、画面名、主な利用者、用途を整理しました。

### A. ダッシュボード・実行監視

| 画面 ID | 画面名               | 主な利用者                             | 主な機能                                                           |
|---------|----------------------|----------------------------------------|--------------------------------------------------------------------|
| SCR-001 | ダッシュボード       | 運用管理者、システム管理者             | 実行中・成功・失敗件数、異常発生状況、要対応ジョブを表示           |
| SCR-002 | ジョブ実行状況一覧   | 運用管理者                             | 実行中・待機中・異常終了などを検索・一覧表示                       |
| SCR-003 | ジョブ実行詳細       | 運用管理者                             | 実行状態、実行先、実行時間、パラメータ、処理件数、エラー情報を表示 |
| SCR-004 | 実行ログ・エラー詳細 | 運用管理者                             | ログ、エラー内容、発生箇所、関連イベントを確認                     |
| SCR-005 | ジョブ実行履歴一覧   | 運用管理者、会社運用担当者、店舗担当者 | 期間・ジョブ・会社・店舗・状態などで履歴を検索                     |
| SCR-006 | ジョブ実行履歴詳細   | 運用管理者、会社運用担当者、店舗担当者 | 実行結果、実行時間、処理件数、再実行履歴を参照                     |

### B. ジョブ定義・スケジュール管理

| 画面 ID | 画面名                 | 主な利用者                 | 主な機能                                               |
|---------|------------------------|----------------------------|--------------------------------------------------------|
| SCR-007 | ジョブ定義一覧         | システム管理者、運用管理者 | 登録済みジョブの検索、状態、バージョン、配備状況の確認 |
| SCR-008 | ジョブ定義詳細         | システム管理者、運用管理者 | ジョブ仕様、パラメータ、同時実行数、通知設定を確認     |
| SCR-009 | ジョブ定義登録・編集   | システム管理者             | ジョブコード、パラメータ仕様、実行制約などを登録・変更 |
| SCR-010 | スケジュール一覧       | システム管理者、運用管理者 | スケジュールの検索、有効・無効状態の確認               |
| SCR-011 | スケジュール登録・編集 | システム管理者             | 実行日時、繰り返し条件、対象ジョブ、有効期間を設定     |

### C. 手動起動・障害復旧

| 画面 ID | 画面名             | 主な利用者                 | 主な機能                                                 |
|---------|--------------------|----------------------------|----------------------------------------------------------|
| SCR-012 | ジョブ手動起動画面 | 運用管理者                 | 対象ジョブ、実行パラメータ、対象会社・店舗を指定して起動 |
| SCR-013 | 再実行確認画面     | 運用管理者                 | 元の実行内容、再実行条件、影響、実行理由を確認           |
| SCR-014 | 途中再開確認画面   | 運用管理者                 | 再開可否、チェックポイント、再開位置を確認               |
| SCR-015 | キャンセル確認画面 | 運用管理者                 | 対象実行とキャンセルの影響を確認して要求                 |
| SCR-016 | 復旧操作履歴一覧   | 運用管理者、システム管理者 | 再実行・再開・キャンセルの操作者、理由、日時を確認       |

※ SCR-013〜015 は、独立したページではなく、実行詳細画面から開くダイアログとして実装しても構いません。

## 4. MVP（初期リリース）で優先する画面

初期段階では、ジョブを安全に実行し、状況を確認し、障害から手動復旧できることを優先します。

| 優先度 | 画面                          | 理由                                     |
|--------|-------------------------------|------------------------------------------|
| 必須   | SCR-001 ダッシュボード        | 異常や対応が必要な実行を把握する         |
| 必須   | SCR-002 実行状況一覧          | 実行中・待機中・失敗を確認する           |
| 必須   | SCR-003 実行詳細              | 実行結果やエラーを調査する               |
| 必須   | SCR-005〜006 実行履歴         | 過去の結果と復旧経緯を確認する           |
| 必須   | SCR-007〜009 ジョブ定義       | ジョブの登録と実行条件を管理する         |
| 必須   | SCR-012 手動起動              | 運用管理者が任意に起動する               |
| 必須   | SCR-013〜014 復旧確認         | 再実行・途中再開を安全に行う             |
| 必須   | SCR-017〜019 サーバー・配備   | 実行可能なサーバーとバージョンを確認する |
| 必須   | SCR-023〜026 権限・監査       | 操作権限と追跡可能性を確保する           |
| 次段階 | SCR-010〜011 スケジュール管理 | 定期実行を画面から設定する               |
| 次段階 | SCR-021〜022 通知管理         | 通知条件や宛先を運用する                 |

スケジュール起動そのものが初期リリースの要件であれば、スケジュール登録・編集画面も必須に繰り上げます。

推奨方針： 画面を作り始める前に、SCR-001〜026 をユースケース ID と
API・権限・データ項目に対応付けると、画面の重複や責務漏れを防ぎやすくなります。
