Jobloom：アクターとユースケース
Jobloom の責務を「ジョブの実行管理・監視・運用」に限定し、業務処理そのものは各業務アプリケーションが担当する前提で整理します。
1. アクター一覧
   ID	アクター	主な役割
   A01	システム管理者	ジョブ定義、サーバー配備情報、ユーザー、権限などを管理する
   A02	運用管理者	ジョブの手動起動、実行状況の監視、障害調査、再実行・再開を行う
   A03	会社運用担当者	自社に属するジョブの実行状況・履歴を参照する
   A04	店舗担当者	権限を付与された店舗のジョブ実行状況・履歴を参照する
   A05	個別業務システム	API を通じて Jobloom にジョブの起動を要求し、実行結果を照会する
   A06	スケジューラ	設定された実行日時・条件に従って起動要求を生成する
   A07	業務アプリケーションサーバー	ジョブ起動 API を提供し、業務ジョブを実行する
   A08	通知受信者	ジョブの成功・異常終了などの通知を受け取る
   アクターの補足
- PostgreSQL、S3 / MinIO はシステム内部のインフラであり、アクターには含めません。
- 業務担当者向けの業務画面やファイルアップロード画面は個別業務システムが提供します。
- スケジューラは Jobloom 内部のコンポーネントとして実装してもよく、その場合は外部アクターではなく内部機能として扱います。
2. ユースケースの全体分類

UC01〜UC05：定義・構成管理
ジョブ定義、配備先、実行条件、ユーザー、権限を管理する。




UC06〜UC10：起動・実行制御
手動起動、API 起動、スケジュール起動、実行先選択、同時実行制御を行う。




UC11〜UC14：監視・実行情報管理
実行状況、履歴、ログ、エラー情報を確認する。




UC15〜UC18：障害対応・運用
キャンセル、再実行、途中再開、通知、監査ログを管理する。




UC19〜UC20：会社・店舗別の参照
会社や店舗の権限に応じて、実行状況・履歴を参照する。

5. 重要なユースケースの概要
   特に設計を具体化すべきユースケースは次のとおりです。
   UC07：API からジョブ起動を要求する
   主アクター：個別業務システム
   事前条件：起動対象が登録済み

1. 個別業務システムが Jobloom の起動 API を呼び出す。
2. Jobloom は要求内容、権限、パラメータを検証する。
3. Jobloom は実行 ID を発行し、起動要求と実行履歴を記録する。
4. 実行制御に従って対象サーバーへ起動を依頼する。
5. Jobloom は受付結果を返し、処理の完了後に状態・結果を照会できるようにする。
   例外： 同じ要求の重複、実行枠不足、対象サーバー不在、通信タイムアウト。結果不明の場合は状態確認を行い、無条件で再実行しない。

UC16：異常終了したジョブを再実行する
主アクター：運用管理者
事前条件：対象実行の状態・再実行可否を確認できる

1. 運用管理者が実行履歴とエラー情報を確認する。
2. 再実行の可否と影響を確認する。
3. 再実行理由を入力して操作する。
4. Jobloom は権限と実行条件を検証し、新しい実行 ID を発行する。
5. 元の実行 ID と関連付け、新しい実行履歴を作成する。
6. 実行先サーバーに起動を依頼する。
   制約： 元の履歴は上書きしません。自動リトライは行わず、重複した業務処理が発生しないことを業務ジョブ側でも考慮します。

UC17：チェックポイントからジョブを再開する
主アクター：運用管理者
事前条件：ジョブが途中再開に対応している

1. 運用管理者が実行履歴と処理済み範囲を確認する。
2. Jobloom が再開可能なチェックポイントの有無を確認する。
3. 運用管理者が再開位置と理由を確認して操作する。
4. Jobloom が新しい実行 ID を発行し、元の実行と関連付ける。
5. 業務アプリケーションがチェックポイントから処理を再開する。
   制約： チェックポイントの保存、処理済みデータの重複防止、再開の安全性は業務ジョブ側の責務です。


6. ユースケース図を作成する際の境界
   Jobloom のシステム境界内に置くのは、ジョブ定義、起動受付、実行制御、監視、履歴、通知、復旧、権限管理です。
   一方、業務データの加工、業務ルールの判定、業務画面でのファイル登録などは個別業務システムの責務として、Jobloom のユースケースには含めません。
   この整理をベースに、次の段階では ユースケースごとの事前条件・基本フロー・代替フロー・事後条件を定義し、API・画面・DB設計に対応付ける と、実装に直結する要件定義に発展させられます。
