# NT 通知要望

Notification（NT）モジュールに関する要望を整理します。

## 1. 概要

NTモジュールは、メール・Slack・Webhookなどの通知チャネルを通じて、システムイベントの通知を送信する共通モジュールです。
JBジョブ管理など他のモジュールからNTモジュールの通知送信APIを参照する仕組みと、NTモジュール自体の拡張要望を記載します。

## 2. JBジョブ管理からのNT参照要望

### 2.1 通知送信API

**要望:** JBジョブ管理からNTモジュールの通知送信APIを利用したい。

**背景:**
- ジョブ実行結果（成功・失敗・結果不明）に応じて通知を送信したい
- 通知設定（チャネル・対象・条件・テンプレート）はJBジョブ管理で管理する
- 実際の通知送信処理はNTモジュールで一元化管理したい
- 複数チャネル（メール・Slack・Webhook）に対応したい

**具体的な要望:**
- 通知送信APIを提供してほしい
- 以下のパラメータを受け付けること
  - チャネルタイプ（email, slack, webhook）
  - チャネル設定（宛先メールアドレス、Slack webhook URL、Webhook URL）
  - 件名テンプレート
  - 本文テンプレート
  - テンプレート変数（ジョブ名、ステータス、開始時刻、終了時刻、メッセージなど）
- 非同期で通知を送信してほしい
- 送信結果（成功・失敗）を返してほしい

### 2.2 通知履歴参照API

**要望:** JBジョブ管理からNTモジュールの通知履歴を参照したい。

**背景:**
- 通知一覧画面（SCR-JB-021）で通知の送信履歴を確認したい
- 未読・既読の管理をしたい
- 通知の再送信機能を検討中

**具体的な要望:**
- 通知履歴の一覧取得APIを提供してほしい
- 以下の検索条件に対応してほしい
  - 期間検索
  - 通知タイプ検索（成功、失敗、結果不明）
  - ジョブコード検索
  - 未読/既読検索
- 通知詳細取得APIを提供してほしい
- 既読にするAPIを提供してほしい

## 3. NTモジュール拡張要望

### 3.1 通知テンプレート機能

**要望:** テンプレート変数を置換して通知本文を生成する機能を追加したい。

**具体的な要望:**
- テンプレート変数の置換機能（{{variableName}} 形式）
- 標準テンプレートの提供（ジョブ実行結果通知など）
- カスタムテンプレートの登録機能

### 3.2 通知チャネル管理

**要望:** 複数の通知チャネルを管理する機能を追加したい。

**具体的な要望:**
- メールチャネル（SMTP設定管理）
- Slackチャネル（Webhook URL管理）
- Webhookチャネル（外部システム連携）
- チャネルごとの送信テスト機能

### 3.3 通知配信制御

**要望:** 通知の配信タイミングを制御する機能を追加したい。

**具体的な要望:**
- 通知期間の設定（開始時刻・終了時刻）
- 通知の重複抑制（同じ内容の通知を一定期間送信しない）
- 通知のバッチ送信（大量通知時の一括送信）

## 4. 非機能要望

### 4.1 パフォーマンス

- 通知送信は非同期で処理し、JBジョブ管理の処理をブロックしないこと
- 大量通知時のキューイング機能を備えること
- 送信失敗時のリトライ機能を備えること

### 4.2 信頼性

- 通知送信の失敗をログに記録すること
- 送信失敗時の再送機能を備えること
- 通知履歴の永続化を行うこと

### 4.3 権限管理

- 通知送信APIの適切な権限チェックを希望
- 通知履歴の参照権限を制御すること

## 5. 優先度

| 要望 | 優先度 |
|------|--------|
| 通知送信API | 高 |
| 通知履歴参照API | 中 |
| 通知テンプレート機能 | 中 |
| 通知チャネル管理 | 中 |
| 通知配信制御 | 低 |
| 非同期処理 | 高 |
| 送信失敗リトライ | 高 |
