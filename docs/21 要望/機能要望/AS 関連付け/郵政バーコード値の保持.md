# 郵政バーコード値の保持

## 概要
郵送する郵便物に宛先毎に付与するカスタマバーコードの値を保持する機能について整理する。

## 関連Issue
- Issue #431: 住所情報にカスタマバーコード値を保持する（**取り消し**）
- PR #432: https://github.com/mizo432/modulith-learning/pull/432（**取り消し**）

## 結論: 実装を取り消した

住所レジストリ（Address Registry）は、国から提供される**住所レジストリデータ**に基づいて設計されており、**「字（aza）」情報**、つまり**行政上の地域区分名**のマスターデータを管理するものです。

一方、**カスタマバーコード**は**実際の郵便物の宛先住所**に付与するもので、都道府県 + 市区町村 + 町域名 + **番地・号** + **建物名** + **部屋番号**といった**完全な住所**が必要です。

### 概念的な乖離

| 項目 | 住所レジストリ | カスタマバーコード |
|------|----------------|-------------------|
| 目的 | 行政上の地域区分マスター管理 | 郵便物宛先の機械読取 |
| データ | 字（aza）の名称とコード | 完全な住所 + 郵便番号 |
| 番地・号 | ❌ 含まない | ✅ 必須 |
| 建物名 | ❌ 含まない | ✅ 必要 |

**`ChouAza`エンティティに`customerBarcode`フィールドを追加することは概念的に誤り**です。

### 取り消した実装

以下の実装を削除しました：
1. `CustomerBarcodeService.java` — 要望外の生成ロジック
2. `CustomerBarcodeServiceTest.java` — 要望外のテスト
3. `V20261107110600__add_customer_barcode_to_chou_aza.sql` — 概念的に誤ったマイグレーション
4. `ChouAza.java` の `customerBarcode` フィールド — 住所レジストリに不要

## 正しいアプローチ

カスタマバーコードは、**実際の宛先住所**を管理するエンティティ（例えば、顧客や従業員の住所情報）に保持すべきものです。住所レジストリは、住所の**検証**や**標準化**に利用するマスターデータとして機能すべきです。

2. **詳細設計** — 要件定義に基づき詳細設計を行うIssueを作成
3. **実装** — 詳細設計に基づきコードを実装するIssueを作成

カスタマバーコード機能は、住所レジストリとは別のエンティティ（顧客・従業員の宛先住所情報）に対して実装する必要があります。
