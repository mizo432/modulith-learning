# Agiloom：支援サブドメイン一覧

## 1. 目的と定義

本書では、Agiloomのコアサブドメイン（価値発見、バックログ、スプリント実行、品質検証、成果適応）を、使いやすく継続的に運用できるよう支える
**支援サブドメイン**を整理します。

支援サブドメインはAgiloomの業務文脈に関係しますが、プロダクトの主要な競争力を直接決める中核ではありません。チーム導入、状況共有、業務調整、レポート、設定など、コア業務の周辺にあるニーズを扱います。

| SUP-04 | ステークホルダー・従業員参加     | チーム外従業員の情報提供、レビュー、トラッキング参加を支援する | PO、従業員、トラッキング担当 | MVP          |

## 3. サブドメインの詳細

### SUP-01：プロジェクト・チーム運営設定

プロジェクト、チーム、スプリントの基本情報と運用上の設定を整えます。

| 項目     | 内容                                                                         |
|----------|------------------------------------------------------------------------------|
| 主な業務 | プロジェクト作成、チーム参加設定、スプリント期間、タイムゾーン、既定値の管理 |
| 主な概念 | Project、Team、Membership、Sprint Cadence、Project Setting                   |
| 支援対象 | スプリント実行、トラッキング、チーム協働                                     |
| 境界     | プロダクトの目標やバックログ内容を決めるのではなく、運用の枠組みを設定する   |

### SUP-02：ワークフロー・項目設定

チームが使う項目種別、状態、ラベル、優先度などをプロジェクトの運用に合わせて設定します。

| 項目     | 内容                                                           |
|----------|----------------------------------------------------------------|
| 主な業務 | 項目タイプ、状態遷移、ラベル、テンプレート項目、必須入力の設定 |
| 主な概念 | Workflow、Work Item Type、Status、Field、Label                 |
| 支援対象 | バックログ管理、作業の可視化、レポート                         |
| 境界     | 設定の自由度を高めすぎず、共通の意味と集計可能性を保つ         |

### SUP-03：テンプレート・再利用

チームや組織で繰り返し使うプロジェクト構成、バックログ項目、イベント準備物をひな形として共有します。

| 項目     | 内容                                                                              |
|----------|-----------------------------------------------------------------------------------|
| 主な業務 | プロジェクトテンプレート、Story例、チェックリスト、イベント準備テンプレートの管理 |
| 主な概念 | Template、Template Version、Checklist、Reusable Configuration                     |
| 支援対象 | 初期設定、オンボーディング、運用の一貫性                                          |
| 境界     | ひな形を強制的な標準プロセスにせず、チームが適応できるようにする                  |

### SUP-04：ステークホルダー・従業員参加

チームメンバー以外の従業員が、課題や業務知識を提供したり、レビューに参加したりできるよう支援します。

| 項目     | 内容                                                                             |
|----------|----------------------------------------------------------------------------------|
| 主な業務 | 課題・要望受付、レビュー参加依頼、質問回答、トラッキング担当の参照範囲設定       |
| 主な概念 | Stakeholder、Employee Feedback、Review Participant、Tracking Access              |
| 支援対象 | Discovery、レビュー、プロジェクトトラッキング                                    |
| 境界     | チーム外参加者がチームのSprint Backlogや作業計画を直接変更しないよう権限を分ける |

### SUP-05：プロジェクトトラッキング・報告

チーム外の従業員が、プロジェクトの状態を把握し、必要な調整や意思決定を行えるようにします。

| 項目     | 内容                                                                   |
|----------|------------------------------------------------------------------------|
| 主な業務 | マイルストーン、目標進捗、リスク、依存関係、判断待ちの確認             |
| 主な概念 | Project Snapshot、Milestone、Risk Summary、Status Update               |
| 支援対象 | プロジェクト横断の状況理解と関係者調整                                 |
| 境界     | 状況報告を個人監視やチームランキングに使わず、透明性と適切な支援に使う |

### SUP-06：イベント運営・記録支援

スクラムイベントの準備、記録、フォローアップを助けます。イベントの目的や責任そのものをツールで代替するものではありません。

| 項目     | 内容                                                                                |
|----------|-------------------------------------------------------------------------------------|
| 主な業務 | Planningの準備、Reviewの成果・フィードバック記録、Retrospectiveの改善アクション追跡 |
| 主な概念 | Event、Event Outcome、Decision、Action Item                                         |
| 支援対象 | Sprint Planning、Review、Retrospective等の運営                                      |
| 境界     | 会議出席や議事録作成をイベントの成果と混同せず、検査・適応を支える                  |

### SUP-07：チームオンボーディング・ガイド

新規参加者が、プロダクト、チーム、Agiloomの利用方法を理解するための導入支援を提供します。

| 項目     | 内容                                                                     |
|----------|--------------------------------------------------------------------------|
| 主な業務 | 役割説明、チームの作業ルール、用語、アクセス手順、プロジェクト背景の案内 |
| 主な概念 | Onboarding Checklist、Role Guide、Team Agreement、Glossary               |
| 支援対象 | チーム参加の立ち上がり、知識継承                                         |
| 境界     | スクラムの理解やコーチングを静的な文書だけで完結させない                 |

### SUP-08：ナレッジ・意思決定共有

業務手順、プロダクト背景、アーキテクチャ判断、運用上の学びを適切な範囲で共有します。

| 項目     | 内容                                                               |
|----------|--------------------------------------------------------------------|
| 主な業務 | ナレッジ記事、FAQ、意思決定記録、運用手順、変更理由の整理と更新    |
| 主な概念 | Knowledge Article、Decision Record、Runbook、Revision              |
| 支援対象 | Discovery、開発、運用、引継ぎ                                      |
| 境界     | 要求やバックログの正式な状態・順序をナレッジ記事内だけで管理しない |

### SUP-09：リスク・課題・依存関係の横断調整

複数チーム、部門、外部サービスにまたがる課題を可視化し、調整の担当と次の対応を明確にします。

| 項目     | 内容                                                           |
|----------|----------------------------------------------------------------|
| 主な業務 | 依存関係の登録、影響範囲の確認、担当者の調整、エスカレーション |
| 主な概念 | Cross-Team Dependency、Impediment、Risk、Escalation            |
| 支援対象 | Sprint実行、Release Planning、組織的な障害解消                 |
| 境界     | リスク一覧を作ること自体ではなく、対応と意思決定につなげる     |

### SUP-10：レポート・データ出力

関係者が必要な進捗や成果を理解できるよう、権限に応じたビューやデータ出力を提供します。

| 項目     | 内容                                                                             |
|----------|----------------------------------------------------------------------------------|
| 主な業務 | プロジェクト状況レポート、マイルストーン報告、データ出力、定期共有               |
| 主な概念 | Report、Dashboard View、Export Job、Data Scope                                   |
| 支援対象 | トラッキング、意思決定、組織内共有                                               |
| 境界     | 指標の定義や業務上の意味はコアの成果計測領域で管理し、レポートは表示・配布を担う |

### SUP-11：外部ツール連携の業務設定

外部ツールとの接続そのものではなく、Agiloomの項目やイベントと外部の成果物を業務上関連づけます。

| 項目     | 内容                                                                    |
|----------|-------------------------------------------------------------------------|
| 主な業務 | StoryとIssue／Commit／Build／Test Runの対応づけ、同期ルール、エラー確認 |
| 主な概念 | Integration Mapping、External Reference、Sync Rule                      |
| 支援対象 | 開発・テスト・性能検証の追跡性                                          |
| 境界     | API認証、再試行、Webhook配送などの共通接続基盤は汎用サブドメインに置く  |

### SUP-12：アーカイブ・プロジェクト終了支援

完了したプロジェクトの状態を整理し、後から学びや監査のために参照できるようにします。

| 項目     | 内容                                                                   |
|----------|------------------------------------------------------------------------|
| 主な業務 | 終了状態への移行、未完了項目の整理、成果・学びの要約、参照権限の変更   |
| 主な概念 | Project Closure、Archive、Final Summary、Retention Policy              |
| 支援対象 | プロジェクト終了、組織学習、後続プロジェクトへの引継ぎ                 |
| 境界     | データの物理保存・削除やバックアップは汎用サブドメインの責務と連携する |

## 4. コア・支援・汎用の境界

| 業務領域                                    | 区分 | 例                                      |
|---------------------------------------------|------|-----------------------------------------|
| ユーザー課題から価値仮説を作る              | コア | Discovery、Product Goal                 |
| バックログの内容と優先順位を決める          | コア | Product Backlog、Kano評価、優先順位判断 |
| Sprint Goalに向けてインクリメントを作る     | コア | Sprint実行、品質、受入・性能検証        |
| プロジェクト設定やワークフローを整える      | 支援 | チーム設定、テンプレート、項目設定      |
| チーム外の従業員が状況を把握する            | 支援 | トラッキング画面、ステータス報告        |
| 外部ツールの共通通信を行う                  | 汎用 | API認証、Webhook配送、再試行            |
| 外部ツールの成果物をAgiloom項目へ結びつける | 支援 | StoryとBuild／Test Runのマッピング      |
| ログイン・通知・ファイルを提供する          | 汎用 | 認証、メール配信、ストレージ            |

## 5. 実装の推奨順序

| 段階 | 支援サブドメイン                                                 | 理由                                                     |
|------|------------------------------------------------------------------|----------------------------------------------------------|
| 1    | プロジェクト・チーム設定、従業員参加、トラッキング、イベント記録 | コア機能をチームと関係者が利用するための最小限の運用支援 |
| 2    | ワークフロー設定、テンプレート、リスク・依存関係調整             | 複数チームやプロジェクトへの展開を助ける                 |
| 3    | ナレッジ、オンボーディング、レポート、アーカイブ                 | 利用定着、知識継承、組織的な学びを強化する               |
| 4    | 高度な外部連携設定、カスタムレポート                             | 実際の導入環境や運用ニーズが明確になってから拡張する     |

## 6. 結論

Agiloomの支援サブドメインは、プロジェクトとチームの設定、ワークフロー、テンプレート、従業員参加、プロジェクトトラッキング、イベント記録、オンボーディング、ナレッジ共有、横断調整、レポート、連携設定、アーカイブです。

これらはコアの価値発見・開発・検証・適応を現場で運用しやすくします。コアの業務判断を支援機能へ埋め込まず、認証・通知・保存などの汎用機能とも責務を分けることで、Agiloomの業務モデルを保ちながら導入先に合わせて拡張できます。
