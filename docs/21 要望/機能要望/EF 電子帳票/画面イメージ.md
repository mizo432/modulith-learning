電子帳票システムの25 Featureをもとに、実際の業務で利用する画面を想定し、テキスト形式のワイヤーフレームとして整理します。

シングルテナント構成で、複数の業務システムが共通の電子帳票基盤を利用する前提です。

# 1. 画面全体の構成

画面は大きく5つの領域に分けます。

| 画面領域    | 主な利用者       | 目的                  |
| ------- | ----------- | ------------------- |
| 利用者向け画面 | 業務担当者・帳票利用者 | 帳票の検索・閲覧・ダウンロード     |
| 承認画面    | 承認者         | 帳票の確認・承認            |
| 管理画面    | システム管理者     | 帳票定義・組織・権限・業務システム管理 |
| 運用画面    | 運用管理者       | アーカイブ・復元・エラーの管理     |
| 分析画面    | 管理者・監査担当者   | 帳票利用状況・監査情報の確認      |

# 9. 画面設計で重要な考え方

今回のシステムでは、特に次の3点を重視したいです。

1. 業務システムを意識させない共通利用 利用者は複数の業務システムの帳票を、共通の検索・閲覧画面から扱えるようにする。ただし、権限に応じて表示対象を制限する。
2. プレビューを中心にした帳票利用 ダウンロードを必須とせず、PDF・Office文書をブラウザで確認できるようにする。
3. アーカイブを利用者に意識させない アーカイブ済み帳票でも、通常の帳票と同じように閲覧要求でき、自動復元後にプレビューできるようにする。

次の画面設計では、まず利用者が日常的に使う「ダッシュボード → 帳票検索 → 帳票詳細・プレビュー」の3画面を詳しく設計するのがよいと考えます。
