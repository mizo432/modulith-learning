# 認証・認可に関する非機能要件

## 概要

本ドキュメントでは、システムの認証・認可機能に関する非機能要件を定義します。

## 要件一覧

### シングルサインオン・マルチテナント

| 要件ID    | 要件内容                 | 優先度 |
|-----------|--------------------------|--------|
| REQ-00001 | 認証はシングルサインオン | 高     |
| REQ-00002 | 認証はmulti tenant       | 高     |

### API Gateway 認証

| 要件ID    | 要件内容               | 優先度 |
|-----------|------------------------|--------|
| REQ-00003 | api-gateway で認証する | 高     |

### 認証データ保管

| 要件ID    | 要件内容                                                               | 優先度 |
|-----------|------------------------------------------------------------------------|--------|
| REQ-00004 | 機微な情報は通常業務と違うデータベースに"authentication#に保管すること | 高     |

### 初期設定・ログインフロー

| 要件ID    | 要件内容                                                                                                      | 優先度 |
|-----------|---------------------------------------------------------------------------------------------------------------|--------|
| REQ-00005 | frontendの画面が立ち上がる際にログインする                                                                    | 高     |
| REQ-00007 | 初期で会社情報を登録する                                                                                      | 高     |
| REQ-00008 | 認可データベースにユーザーが登録されていない場合システム管理者ユーザー (admin)を登録する パスワードは空とする | 高     |
| REQ-00009 | フロントエンド画面を起動しようとした時に、パスワード設定を行う                                                | 高     |

### OAuth 2.0 認証フロー

| 要件ID    | 要件内容                                                         | 優先度 |
|-----------|------------------------------------------------------------------|--------|
| REQ-00010 | 認証はOAuth 2.0 Authorization Code with PKCEフローを使用すること | 高     |
| REQ-00011 | authorizationモジュールをOAuth 2.0認可サーバーとして構成すること | 高     |

### JWT トークン管理

| 要件ID    | 要件内容                                                              | 優先度 |
|-----------|-----------------------------------------------------------------------|--------|
| REQ-00012 | アクセストークンはJWT (JSON Web Token) 形式で発行すること             | 高     |
| REQ-00013 | アクセストークンの有効期間は15分以内とする                            | 高     |
| REQ-00014 | リフレッシュトークンを使用してアクセストークンの再発行を行うこと      | 高     |
| REQ-00015 | リフレッシュトークンの有効期間は7日以内とする                         | 高     |
| REQ-00016 | トークンの署名にはRS256 (RSA with SHA-256) アルゴリズムを使用すること | 高     |

### API Gateway リソースサーバー

| 要件ID    | 要件内容                                                                             | 優先度 |
|-----------|--------------------------------------------------------------------------------------|--------|
| REQ-00017 | api-gatewayはOAuth 2.0リソースサーバーとして動作し、アクセストークンの検証を行うこと | 高     |

### セキュリティ

| 要件ID    | 要件内容                                                                             | 優先度 |
|-----------|--------------------------------------------------------------------------------------|--------|
| REQ-00018 | 認可エンドポイント、トークンエンドポイントはHTTPSのみで提供すること                  | 高     |
| REQ-00019 | クライアントIDとクライアントシークレットは安全に保管し、平文でコードに記述しないこと | 高     |
| REQ-00020 | OAuth 2.0認可サーバーは、ユーザーの同意画面を表示する機能を持つこと                  | 中     |

### JWT 検証

| 要件ID    | 要件内容                                                                                                                                        | 優先度 |
|-----------|-------------------------------------------------------------------------------------------------------------------------------------------------|--------|
| REQ-00021 | リソースサーバーはJWTの署名を検証し、署名が無効なトークンは拒否すること                                                                         | 高     |
| REQ-00022 | リソースサーバーはJWTの有効期限 (expクレーム)を検証し、期限切れのトークンは拒否すること                                                         | 高     |
| REQ-00023 | リソースサーバーはJWTの発行者 (issクレーム)を検証し、信頼された認可サーバーから発行されたトークンのみを許可すること                             | 高     |
| REQ-00024 | リソースサーバーはJWTの発行時刻 (iatクレーム)と有効期限 (expクレーム)の差を検証し、アクセストークンの有効期間が15分以内であることを確認すること | 高     |
| REQ-00025 | リソースサーバーはJWTのオーディエンス (audクレーム)を検証し、自身が対象のリソースサーバーであることを確認すること                               | 高     |
| REQ-00026 | JWTのサブジェクト (subクレーム)は認証されたユーザーの一意の識別子を含むこと                                                                     | 高     |

### JWKS エンドポイント

| 要件ID    | 要件内容                                                                                                 | 優先度 |
|-----------|----------------------------------------------------------------------------------------------------------|--------|
| REQ-00027 | リソースサーバーはJWKSエンドポイントから公開鍵を取得し、署名検証に使用すること                           | 高     |
| REQ-00028 | JWKSエンドポイントのレスポンスはキャッシュし、過度なネットワーク呼び出しを避けること                     | 中     |
| REQ-00029 | JWTのキャッシュ有効期間は5分以内とする                                                                   | 中     |
| REQ-00030 | nbfクレーム (Not Before)が設定されている場合、リソースサーバーはその時刻以前のトークン使用を拒否すること | 高     |

## 実装方針

1. **authorizationモジュール**: OAuth 2.0 認可サーバーとして実装
2. **api-gateway**: OAuth 2.0 リソースサーバーとして実装
3. **frontend**: OAuth 2.0 Authorization Code with PKCE フローを使用
4. **トークン管理**: JWT形式でRS256署名を使用
