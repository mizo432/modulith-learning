# REQ-00001

認証はシングルサインオン

# REQ-00002

認証はmulti tenant

# REQ-00003

api-gateway で認証する

# REQ-00004

機微な情報は通常業務と違うデータベースに"authentication#に保管すること

# REQ-00005

frontendの画面が立ち上がる際にログインする

# REQ-00007

初期で会社情報を登録する

# REQ-00008

認可データベースにユーザーが登録されていない場合システム管理者ユーザー (admin)を登録する
パスワードは"password"とする。

# REQ-00009

フロントエンド画面を起動しようとした時に、パスワード設定を行う。

# REQ-00010

認証はOAuth 2.0 Authorization Code with PKCEフローを使用すること。

# REQ-00011

authorizationモジュールをOAuth 2.0認可サーバーとして構成すること。

# REQ-00012

アクセストークンはJWT (JSON Web Token) 形式で発行すること。

# REQ-00013

アクセストークンの有効期間は15分以内とする。

# REQ-00014

リフレッシュトークンを使用してアクセストークンの再発行を行うこと。

# REQ-00015

リフレッシュトークンの有効期間は7日以内とする。

# REQ-00016

トークンの署名にはRS256 (RSA with SHA-256) アルゴリズムを使用すること。

# REQ-00017

api-gatewayはOAuth 2.0リソースサーバーとして動作し、アクセストークンの検証を行うこと。

# REQ-00018

認可エンドポイント、トークンエンドポイントはHTTPSのみで提供すること。

# REQ-00019

クライアントIDとクライアントシークレットは安全に保管し、平文でコードに記述しないこと。

# REQ-00020

OAuth 2.0認可サーバーは、ユーザーの同意画面を表示しない。

# REQ-00021

リソースサーバーはJWTの署名を検証し、署名が無効なトークンは拒否すること。

# REQ-00022

リソースサーバーはJWTの有効期限 (expクレーム)を検証し、期限切れのトークンは拒否すること。

# REQ-00023

リソースサーバーはJWTの発行者 (issクレーム)を検証し、信頼された認可サーバーから発行されたトークンのみを許可すること。

# REQ-00024

リソースサーバーはJWTの発行時刻 (iatクレーム)と有効期限 (expクレーム)
の差を検証し、アクセストークンの有効期間が15分以内であることを確認すること。

# REQ-00025

リソースサーバーはJWTのオーディエンス (audクレーム)を検証し、自身が対象のリソースサーバーであることを確認すること。

# REQ-00026

JWTのサブジェクト (subクレーム)は認証されたユーザーの一意の識別子を含むこと。

# REQ-00027

リソースサーバーはJWKSエンドポイントから公開鍵を取得し、署名検証に使用すること。

# REQ-00028

JWKSエンドポイントのレスポンスはキャッシュし、過度なネットワーク呼び出しを避けること。

# REQ-00029

JWTのキャッシュ有効期間は5分以内とする。

# REQ-00030

nbfクレーム (Not Before)が設定されている場合、リソースサーバーはその時刻以前のトークン使用を拒否すること。
