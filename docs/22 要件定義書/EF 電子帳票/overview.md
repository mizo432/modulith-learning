# 概要

本ドキュメントは、EF 電子帳票（Electronic Form）事業領域の要件定義の概要です。

EF 電子帳票（Electronic Form）は、シングルテナント構成で複数の業務システムから共通利用する電子帳票基盤モジュールです。帳票の定義、生成、保管、閲覧、アーカイブ、監査など、電子帳票のライフサイクル全体を管理します。

## 事業領域情報

- 事業領域コード: EF
- 事業領域名: 電子帳票
- 事業領域英名: Electronic Form
- 区分: 基盤

## 業務領域一覧

EF モジュールは以下の5つの業務領域に分離して管理します。

### 1. 帳票基盤管理 (EF-01)

システム環境、業務システム、ストレージ、アクセス制御、組織・利用者、外部API、システム設定の管理を担当します。

**主な責務:**
- システム利用環境の管理
- 業務システムの登録・管理
- ストレージ接続の管理
- アクセス制御ポリシーの管理
- 組織・利用者の管理
- 外部APIキーの管理
- システム設定の管理

### 2. 帳票管理 (EF-02)

帳票定義、帳票生成、帳票登録・取込、帳票情報・バージョンの管理を担当します。

**主な責務:**
- 帳票定義の管理
- 帳票生成の管理
- 帳票登録・取込の管理
- 帳票情報・バージョンの管理

### 3. 帳票利用 (EF-03)

帳票配信、プレビュー、検索、承認・確認を担当します。

**主な責務:**
- 帳票配信の管理
- 帳票プレビューの提供
- 帳票検索の提供
- 承認・確認の管理

### 4. 保管・アーカイブ (EF-04)

保存期間、廃棄、アーカイブポリシー・対象・処理・復元を担当します。

**主な責務:**
- 保存期間の管理
- 廃棄管理
- アーカイブポリシーの管理
- アーカイブ対象の管理
- アーカイブ処理の管理
- 帳票自動復元の管理

### 5. 運用・監査 (EF-05)

通知設定、監査ログ、運用管理、帳票分析、アーカイブ運用を担当します。

**主な責務:**
- 通知設定の管理
- 監査ログの管理
- 運用管理
- 帳票分析・統計
- アーカイブ運用管理

## RDRA 4レイヤー

1. システム価値レイヤー: 要求、アクター、外部システム
2. 外部環境レイヤー: 業務、BUC、アクティビティ
3. システム境界レイヤー: ユースケース、画面、イベント
4. システムレイヤー: 情報、状態、条件、バリエーション

## 他の事業領域との関係

EF モジュールは以下の事業領域から参照されます。

- **AG アジルーム**: プロジェクト関連の帳票出力
- **JB ジョブ管理**: ジョブ実行結果の帳票出力
- **AR 承認申請**: 承認関連の帳票出力

## 非機能要件

EF モジュールの非機能要件は [01 非機能要件](./01%20非機能要件/index.md) を参照してください。

主な非機能要件は以下の通りです。

- **シングルテナント**: 1企業・組織が複数の業務システムから共通利用する基盤
- **データベース**: PostgreSQL
- **ストレージ**: Amazon S3（本番）、MinIO（開発）
- **帳票プレビュー**: PDF.js
- **Office変換**: LibreOffice等を候補とする
- **アーカイブ方式**: アプリケーションによる移行制御
- **復元方式**: 利用者の閲覧要求による自動復元
- **保存期間**: 帳票種類ごとに設定
