# UC-JB-019 ジョブを再実行する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-JB-019 |
| ユースケース名 | ジョブを再実行する |
| 英語名 | Re-execute Job |
| 説明 | 異常終了したジョブを最初から再実行する |
| 関連アクター | AC-01（運用管理者） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-JB-05 |
| 外部システム | ES-01（業務アプリケーションサーバー）、ES-02（PostgreSQL） |
| 関連画面 | SCR-JB-013（再実行確認画面） |

## 前置条件

- 運用管理者がシステムにログインしていること
- 再実行対象の異常終了ジョブが存在すること
- 再実行可否判定（RL-JB-04）が通過すること

## 基本フロー

1. 運用管理者が「再実行確認画面」（SCR-JB-013）にアクセスする
2. 再実行対象のジョブを選択する
3. 元の実行内容、再実行条件、影響を確認する
4. 「再実行」ボタンをクリックする
5. システムが再実行可否判定（RL-JB-04）と結果不明時復旧ルール（RL-JB-06）を確認する
6. システムがジョブ実行（INF-JB-04）をPostgreSQL（ES-02）に記録する
7. 業務アプリケーションサーバー（ES-01）に再実行を依頼する
8. 再実行完了メッセージを表示する

## 代替フロー

- **5a. 再実行不可の場合**
  - 再実行できない理由を表示する
  - ユーザーは処理を中止する

## 後置条件

- 新しいジョブ実行（INF-JB-04）がシステムに登録される
- イベント「EVT-JB-017 ジョブが再実行された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-JB-04 | ジョブ実行 | 作成対象の情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-JB-017 | ジョブが再実行された | 基本フローステップ6完了後 |
| EVT-JB-012 | ジョブ実行が開始された | 基本フローステップ7完了後 |

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 再実行可否 | 再実行可能な状態か判定 |
| 2 | 結果不明時復旧 | 結果不明時に無条件で再実行しない |
