# UC-JB-008 ジョブを手動起動する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-JB-008 |
| ユースケース名 | ジョブを手動起動する |
| 英語名 | Manually Launch Job |
| 説明 | 対象ジョブ、パラメータ、会社・店舗を指定して起動する |
| 関連アクター | AC-03（システム管理者） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-JB-02 |
| 外部システム | ES-01（業務アプリケーションサーバー）、ES-02（PostgreSQL） |
| 関連画面 | SCR-JB-012（ジョブ手動起動画面） |

## 前置条件

- システム管理者がシステムにログインしていること
- 起動対象のジョブ定義が存在すること
- ジョブ手動起動画面（SCR-JB-012）にアクセスできること

## 基本フロー

1. システム管理者が「ジョブ手動起動画面」（SCR-JB-012）にアクセスする
2. 起動対象のジョブを選択する
3. 実行パラメータを指定する（対象会社・店舗は本実装の範囲外。下記「実装方針」参照）
4. 「起動」ボタンをクリックする
5. システムが重複起動防止（RL-JB-01）と同時実行枠制御（RL-JB-02）を確認する
6. システムがジョブ実行（INF-JB-04）をPostgreSQL（ES-02）に記録する
7. 業務アプリケーションサーバー（ES-01）に実行を依頼する
8. 起動完了メッセージを表示する

## 代替フロー

- **5a. 重複起動の場合**
  - 既に実行中のジョブの場合、エラーメッセージを表示する
  - ユーザーは処理を中止する

- **5b. 同時実行枠超過の場合**
  - 同時実行枠を超過する場合、エラーメッセージを表示する
  - ユーザーは処理を中止するか、待機する

## 後置条件

- ジョブ実行（INF-JB-04）がシステムに登録される
- イベント「EVT-JB-007 ジョブが手動起動された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-JB-01 | ジョブ定義 | 起動対象のジョブ情報 |
| INF-JB-04 | ジョブ実行 | 作成対象の情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-JB-007 | ジョブが手動起動された | 基本フローステップ6完了後 |
| EVT-JB-012 | ジョブ実行が開始された | 基本フローステップ7完了後 |

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 重複起動防止 | 実行IDを冪等性キーとして二重起動を抑止 |
| 2 | 同時実行枠 | 同時に実行できるジョブの上限数を制御 |
| 3 | 実行権限 | ジョブ実行の権限を確認 |

## 実装方針（2026-11-26決定、Issue #747）

本ユースケースの実装範囲と方式を次のとおり定める。

- 主アクターはシステム管理者とする（当初の運用管理者から変更）
- ジョブ定義と実バッチの対応付けは、ジョブ定義のジョブコード＝Spring Batch の Job 名（JOB_NAME）とする。ジョブコードで Job を解決できない定義は起動不可とする
- 実行パラメータは key=value（1行に1件）形式のテキストで受け取り、JobParameters に渡す。ParameterSpec は画面に仕様として表示するのみとし、構造化検証は行わない（将来課題）
- 対象会社・店舗と実行先サーバーは本実装の範囲外とする（実バッチに対応概念がなく、単一サーバー構成のため）
- 同時実行枠制御（RL-JB-02）は定義の maxConcurrentExecutions（未設定時は1）で判定し、同一ジョブコードで待機中・実行中の実行が上限に達していれば起動を拒否する
- 実行は同一プロセス内で非同期に行い、起動サービスが状態（待機中→実行中→成功／失敗）を更新する。失敗時はエラー情報を記録する
- 実行権限は、AdminEmployeeChanged イベントの射影で保持する ADMIN ロール保持者のみ許可する
