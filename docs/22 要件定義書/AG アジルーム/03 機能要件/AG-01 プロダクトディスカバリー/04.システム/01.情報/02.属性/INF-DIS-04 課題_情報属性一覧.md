# 情報属性一覧

課題の属性をリストアップします。

## 情報概要

| 項目 | 内容 |
|------|------|
| 情報ID | INF-DIS-04 |
| 情報名 | 課題 |
| 情報種類 | リソース |
| 説明 | 業務上の困りごとや繰り返し発生する問題を定義する情報 |

## 属性一覧

ER（エンティティ関係）モデルに基づき、主キー（個体指定子）と属性を定義します。

| 番号 | 属性名 | 個体指定子 | 型 | 必須 | 説明 |
|------|--------|------------|----|------|------|
| 1 | id | ✓ | Long | 必須 | 課題の一意な識別子 |
| 2 | title | | String | 必須 | 課題のタイトル |
| 3 | background | | String | 任意 | 課題の背景 |
| 4 | impact | | String | 任意 | 課題が与える影響 |
| 5 | issueState | | Enum | 必須 | 課題の状態（未着手、調査中、解決済み、却下） |
| 6 | reporter | | String | 任意 | 報告者 |
| 7 | createdDate | | DateTime | 必須 | 作成日時 |
| 8 | updatedDate | | DateTime | 必須 | 更新日時 |

## 属性の型

属性の型は以下から選択します：

- **String**: 文字列
- **Integer**: 整数
- **Long**: 長整数
- **Double**: 浮動小数点
- **Boolean**: 真偽値
- **Date**: 日付
- **DateTime**: 日時
- **Enum**: 列挙型（対照表を参照）

## 単一性・同一性・カテゴリ

エンティティの3大要素について定義します：

| 要素 | 定義 |
|------|------|
| 単一性 (Oneness) | 1つの課題は、タイトル・背景・影響の組み合わせで1つの課題を構成する |
| 同一性 (Sameness) | idが同じ場合、同じ課題であると判断する |
| カテゴリ (Category) | 業務上の問題を表す課題情報 |

## 状態遷移

この情報が持つ状態と遷移を定義します（該当する場合）。

| 状態名 | 説明 | 遷移元 | 遷移先 | トリガーとなるユースケース |
|--------|------|--------|--------|--------------------------|
| 未着手 | 課題が登録されたがまだ調査されていない状態 | - | 調査中 | 課題を調査開始する |
| 調査中 | 課題の調査が進行中の状態 | 未着手 | 解決済み、却下 | 課題を解決する、課題を却下する |
| 解決済み | 課題が解決された状態 | 調査中 | - | - |
| 却下 | 課題が却下された状態 | 調査中 | - | - |
