# UC-SP-010 障害を更新する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-SP-010 |
| ユースケース名 | 障害を更新する |
| 英語名 | Update Impediment |
| 説明 | 障害の解消状況・担当を修正する |
| 関連アクター | ACT-03（スクラムマスター）、ACT-04（開発チーム） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-SP-03 |
| 外部システム | - |
| 関連画面 | SCR-015（Sprint Board / タスクボード） |

## 前置条件

- ユーザーがシステムにログインしていること
- 障害（INF-SP-04）が既に存在すること

## 基本フロー

1. ユーザーが「Sprint Board / タスクボード」画面（SCR-015）にアクセスする
2. 更新対象の障害を選択する
3. 「編集」ボタンをクリックする
4. 解消状況、担当を修正する
5. 変更を保存する
6. システムが障害（INF-SP-04）を更新する
7. 更新完了メッセージを表示する

## 代替フロー

- **4a. 入力が不完全な場合**
  - 必須項目が未入力の場合、エラーメッセージを表示する
  - ユーザーは入力を修正して再試行する

## 後置条件

- 障害（INF-SP-04）が更新される
- イベント「EVT-SP-009 障害が更新された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-SP-04 | 障害 | 更新対象の情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-SP-009 | 障害が更新された | 基本フローステップ6完了後 |

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 必須項目 | 解消状況は必須入力 |
