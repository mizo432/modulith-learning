# UC-SR-02 Sprint Reviewを準備する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-SR-02 |
| ユースケース名 | Sprint Reviewを準備する |
| 英語名 | Prepare Sprint Review |
| 説明 | Sprint Goal、Sprint Backlog、完了・未完了Story、デモ対象、参加者、議題を準備する |
| 関連アクター | ACT-02（プロダクトオーナー）、ACT-03（スクラムマスター）、ACT-04（開発者） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-LR-01 |
| 外部システム | - |
| 関連画面 | SR-02（Sprint Review準備） |

## 前置条件

- ユーザーがシステムにログインしていること
- Sprint Reviewが開始されていること（UC-SR-01完了）

## 基本フロー

1. ユーザーが「Sprint Review準備」画面（SR-02）にアクセスする
2. Sprint Goalを確認する
3. Sprint Planning時点の計画内容を確認する
4. 完了Story・未完了Storyを確認する
5. デモ対象となるインクリメントを選択する
6. デモ内容・説明を登録する
7. 参加者を登録する（UC-SR-03）
8. Review議題を登録する（UC-SR-04）
9. 前回Reviewのフィードバックを確認する
10. 準備内容を保存する
11. システムがSprint Review準備情報を保存する

## 代替フロー

- **4a. 未完了Storyが存在する場合**
  - システムが未完了Storyとその理由、残作業を表示する
  - ユーザーは未完了理由を記録する

- **5a. デモ対象がない場合**
  - システムがデモ対象がないことを通知する
  - ユーザーはデモなしで進めるか確認する

## 後置条件

- Sprint Reviewの準備情報が保存される
- Sprint Reviewの状態が「準備完了」になる
- イベント「EVT-SR-002 Sprint Reviewが準備された」が発行される

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 計画との比較 | Sprint Planning時点の計画と実際の結果を比較できること |
| 2 | 未完了Story | 未完了Storyは完了扱いにせず、理由を記録すること |
| 3 | Definition of Done | DoDを満たしていない作業を完成したインクリメントとして扱わない |
