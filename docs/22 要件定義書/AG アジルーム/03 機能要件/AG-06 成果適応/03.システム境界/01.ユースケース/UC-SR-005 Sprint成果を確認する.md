# UC-SR-05 Sprint成果を確認する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-SR-05 |
| ユースケース名 | Sprint成果を確認する |
| 英語名 | Confirm Sprint Outcomes |
| 説明 | Sprint Goalと達成状況、完了・未完了Story、完成したインクリメントを確認する |
| 関連アクター | ACT-01（従業員）、ACT-02（プロダクトオーナー）、ACT-03（スクラムマスター）、ACT-04（開発者）、ACT-05（ステークホルダー） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-LR-01 |
| 外部システム | - |
| 関連画面 | SR-03（Sprint Review実施） |

## 前置条件

- ユーザーがシステムにログインしていること
- Sprint Reviewが準備されていること（UC-SR-02完了）

## 基本フロー

1. ユーザーが「Sprint Review実施」画面（SR-03）にアクセスする
2. Sprint Goalと達成状況を確認する
3. 完了Storyと未完了Storyを確認する
4. 完成したインクリメントを確認する
5. 実際の動作をデモする（UC-SR-06）
6. ステークホルダーと成果について議論する
7. 質問やフィードバックを記録する（UC-SR-07）
8. システムが成果確認の内容を記録する

## 代替フロー

- **3a. 未完了Storyが存在する場合**
  - システムが未完了Storyとその理由を表示する
  - ユーザーは未完了理由を確認し、議論する

- **4a. インクリメントがない場合**
  - システムがインクリメントがないことを通知する
  - ユーザーは他の成果を確認する

## 後置条件

- Sprint成果確認の内容が記録される
- イベント「EVT-SR-005 Sprint成果が確認された」が発行される

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | Definition of Done | DoDを満たしていない作業を完成したインクリメントとして扱わない |
| 2 | 未完了Story | 未完了Storyは完了扱いにせず、Product Backlogに戻して再検討する |
| 3 | 計画との比較 | Sprint Planning時点の計画と実際の結果を比較できること |
