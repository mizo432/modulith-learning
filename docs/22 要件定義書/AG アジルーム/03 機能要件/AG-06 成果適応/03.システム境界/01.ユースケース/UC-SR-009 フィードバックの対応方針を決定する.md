# UC-SR-09 フィードバックの対応方針を決定する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-SR-09 |
| ユースケース名 | フィードバックの対応方針を決定する |
| 英語名 | Decide Feedback Disposition |
| 説明 | フィードバックの対応方針（バックログに追加、既存Storyを変更、調査する等）を決定し、判断理由を記録する |
| 関連アクター | ACT-02（プロダクトオーナー） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-LR-01 |
| 外部システム | - |
| 関連画面 | SR-04（フィードバック評価） |

## 前置条件

- ユーザーがシステムにログインしていること
- フィードバックが記録されていること（UC-SR-07完了）

## 基本フロー

1. ユーザーが「フィードバック評価」画面（SR-04）にアクセスする
2. 未評価のフィードバックを確認する
3. 内容と背景を確認する
4. プロダクトの価値やProduct Goalへの影響を検討する
5. 優先順位や実現コストを検討する
6. 対応方針を選択する（バックログに追加、既存Storyを変更、調査する、保留、対応しない、追加情報を確認）
7. 判断理由を記録する
8. 対応方針を保存する
9. システムがフィードバックの対応方針（INF-SR-06）を保存する
10. 保存完了メッセージを表示する

## 代替フロー

- **6a. 対応しないを選択した場合**
  - ユーザーは対応しない理由を必須で入力する
  - システムが理由を記録して保存する

- **6b. 追加情報を確認を選択した場合**
  - ユーザーが確認対象者と確認事項を記録する
  - システムが保留状態として保存する

## 後置条件

- フィードバックの対応方針（INF-SR-06）が保存される
- 判断理由が記録される
- イベント「EVT-SR-009 フィードバックの対応方針が決定された」が発行される

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 自動登録禁止 | フィードバックはバックログに自動登録せず、POが対応方針を判断する |
| 2 | 判断理由 | フィードバックの採用・保留・却下には判断理由を記録する |
| 3 | 権限 | POのみが対応方針を決定できる |
