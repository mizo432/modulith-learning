# UC-SR-10 フィードバックからバックログ候補を作成する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-SR-10 |
| ユースケース名 | フィードバックからバックログ候補を作成する |
| 英語名 | Create Backlog Candidate from Feedback |
| 説明 | フィードバックから新規Story、Feature、Epicのバックログ候補を作成し、元のフィードバックとの関連を保持する |
| 関連アクター | ACT-02（プロダクトオーナー） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-LR-01 |
| 外部システム | - |
| 関連画面 | SR-04（フィードバック評価） |

## 前置条件

- ユーザーがシステムにログインしていること
- フィードバックの対応方針が「バックログに追加」に決定されていること（UC-SR-09完了）

## 基本フロー

1. ユーザーが「フィードバック評価」画面（SR-04）にアクセスする
2. 対象フィードバックを選択する
3. 新規Story、Feature、Epicのいずれが適切かを判断する
4. バックログ候補を作成する
5. バックログ候補の詳細情報を入力する
6. 元のフィードバックとの関連を保持する
7. 優先順位を設定する
8. バックログ候補を保存する
9. システムがバックログ候補（INF-SR-07）を登録する
10. 登録完了メッセージを表示する

## 代替フロー

- **3a. Featureとして作成する場合**
  - ユーザーがFeatureの情報を入力する
  - システムがFeatureバックログ候補を作成する

- **3b. Epicとして作成する場合**
  - ユーザーがEpicの情報を入力する
  - システムがEpicバックログ候補を作成する

## 後置条件

- バックログ候補（INF-SR-07）が登録される
- フィードバックとバックログ候補のトレーサビリティが確保される
- イベント「EVT-SR-010 バックログ候補が作成された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-SR-05 | Reviewフィードバック | 元となる情報 |
| INF-SR-07 | バックログ候補 | 作成対象の情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-SR-010 | バックログ候補が作成された | 基本フローステップ9完了後 |

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | トレーサビリティ | フィードバックとバックログ候補の関連は必須で保持する |
| 2 | 優先順位 | バックログ候補の優先順位を設定する |
| 3 | 権限 | POのみがバックログ候補を作成できる |
