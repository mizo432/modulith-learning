# UC-SR-11 既存Storyを更新する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-SR-11 |
| ユースケース名 | 既存Storyを更新する |
| 英語名 | Update Existing Story |
| 説明 | フィードバックに基づいて既存のEpic・Feature・Storyの要件を変更する |
| 関連アクター | ACT-02（プロダクトオーナー） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-LR-01 |
| 外部システム | - |
| 関連画面 | SR-04（フィードバック評価） |

## 前置条件

- ユーザーがシステムにログインしていること
- フィードバックの対応方針が「既存Storyを変更」に決定されていること（UC-SR-09完了）

## 基本フロー

1. ユーザーが「フィードバック評価」画面（SR-04）にアクセスする
2. 対象フィードバックを選択する
3. 関連する既存のEpic・Feature・Storyを指定する
4. 変更内容を入力する
5. 変更理由にフィードバックを紐付ける
6. 変更を保存する
7. システムが既存Storyを更新する
8. 変更履歴を記録する
9. 更新完了メッセージを表示する

## 代替フロー

- **3a. 複数のStoryを更新する場合**
  - ユーザーが複数のStoryを選択する
  - 各Storyについて変更内容を入力する
  - システムが選択したStoryを一括更新する

## 後置条件

- 既存Storyが更新される
- 変更履歴が記録される
- イベント「EVT-SR-011 既存Storyが更新された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-SR-05 | Reviewフィードバック | 変更の元となる情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-SR-011 | 既存Storyが更新された | 基本フローステップ8完了後 |

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 紐付け | フィードバックは複数のEpic・Feature・Storyに紐付けられる |
| 2 | 変更履歴 | 変更履歴は必須で記録する |
| 3 | 権限 | POのみが既存Storyを更新できる |
