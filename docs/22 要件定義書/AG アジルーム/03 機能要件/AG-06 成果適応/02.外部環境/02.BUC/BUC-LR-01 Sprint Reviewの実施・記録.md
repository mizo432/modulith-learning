# BUC-LR-01 Sprint Reviewの実施・記録

ビジネスユースケース（BUC）の詳細を定義します。

## 概要

| 項目             | 内容 |
|------------------|------|
| BUC ID           | BUC-LR-01 |
| BUC名            | Sprint Reviewの実施・記録 |
| 説明             | インクリメントと成果を確認し、フィードバックを記録する |
| 関連業務         | 成果計測・フィードバックによる適応 |
| 関連ユースケース | UC-LR-001, UC-LR-002, UC-SR-001, UC-SR-002, UC-SR-003, UC-SR-004, UC-SR-005, UC-SR-006, UC-SR-007, UC-SR-008, UC-SR-009, UC-SR-010, UC-SR-011, UC-SR-012, UC-SR-013, UC-SR-014 |

## ビジネスアクター

| 番号 | アクターID | アクター名 | 役割 |
|------|------------|------------|------|
| 1    | ACT-01     | 従業員     | レビューに参加し、利用者視点のフィードバックを提供 |
| 2    | ACT-02     | プロダクトオーナー（PO） | 成果・フィードバックを検査し、目標・バックログを更新 |
| 3    | ACT-03     | スクラムマスター（SM） | レトロスペクティブを支援し、改善アクションを追跡 |
| 4    | ACT-04     | 開発者     | 改善を実行し、効果を確かめる |

> **注意**: ビジネスユースケースとビジネスアクターの関連付けは必須です。各BUCに対応するビジネスアクターを必ず指定してください。

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1    | Sprint Reviewの開催頻度 | Sprintの終了時に必ず開催する必要がある |
| 2    | 参加者の必須要件 | Scrum Team全員とステークホルダーの参加が望ましい |
| 3    | フィードバックの記録義務 | 収集したフィードバックは必ず記録し、分類する必要がある |
| 4    | 対応方針の決定 | フィードバックに対して対応方針を決定し、判断理由を記録する必要がある |
