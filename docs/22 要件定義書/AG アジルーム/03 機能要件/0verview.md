# 概要

本ドキュメントは、Agiloomの機能要件の概要を定義します。

Agiloomは、アジャイル開発チームがプロダクトの方向性策定から成果の検証・適応までを統合的に管理するためのプラットフォームです。6つの業務領域にまたがる機能を提供し、Product Visionの策定からリリース後の効果測定まで、一貫したトレーサビリティを保ちながら価値あるプロダクトを継続的に提供することを支援します。

## 目的

Agiloomは、以下の目的を実現します。

- プロダクトの方向性（Vision・Goal）を全関係者と共有・追跡できる基盤を提供する
- 課題・要望を実行可能な要求へ変換し、価値順に管理する
- Kano分類、価値・コスト・リスクを踏まえた優先順位決定を支援する
- チームの協働とスプリント実行を通じて、完成の定義を満たすインクリメントを継続的に形成する
- 要求・受入条件・品質基準を満たすかを検証し、安全で有用な成果を届ける
- リリース後の利用結果と学びを次の判断へ結びつけ、継続的な改善を促進する

## RDRA 4レイヤー

Agiloomの機能要件は、RDRA（Relationship Driven Requirement Analysis）の4レイヤーで構造化されます。

1. **システム価値レイヤー**: Agiloomが提供する価値と、システムと相互作用するアクターを定義する
2. **外部環境レイヤー**: 業務、ビジネスユースケース、外部システムを定義する
3. **システム境界レイヤー**: ユースケース、ユースケース図、アクターとシステムの境界を定義する
4. **システムレイヤー**: 情報モデル、ステートマシン、画面、イベントを定義する

## 業務領域

Agiloomの機能要件は、6つのコアサブドメインに基づいて業務領域に分割されます。

| ID    | 業務領域名                         | 概要                                                     | 優先度 |
|-------|------------------------------------|----------------------------------------------------------|--------|
| AG-01 | プロダクトディスカバリー           | ユーザー課題を理解し、価値ある機会・目標・仮説を定める   | 中核   |
| AG-02 | 要求・プロダクトバックログ管理     | 課題や仮説を実行可能な項目に変換し、価値順に管理する     | 中核   |
| AG-03 | 価値・要求の優先順位決定           | 価値、Kano品質、リスク、コストを踏まえて投資順を決める   | 中核   |
| AG-04 | スプリント実行とインクリメント形成 | チームの計画と協働を通じて、利用可能な成果を継続的に作る | 中核   |
| AG-05 | プロダクト品質・受入・性能検証     | 期待価値と品質を検証し、安全に利用できる成果を届ける     | 中核   |
| AG-06 | 成果計測・フィードバックによる適応 | 利用結果と学びを目標・バックログ・戦略へ戻す             | 中核   |

### 業務領域の詳細

#### AG-01 プロダクトディスカバリー

ユーザーや従業員の課題・機会を理解し、検証可能な仮説と明確なプロダクト目標を形成する業務領域です。Product Vision、Product Goal、課題、仮説、ステークホルダー、ペルソナ、ユーザージャーニー、成功指標、Kano評価、実験計画などを一元的に管理します。

- **ユースケース数**: 26
- **外部システム連携**: なし

#### AG-02 要求・プロダクトバックログ管理

課題や仮説を実行可能な要求へ変換し、Product Goalとのつながりを保ちながら価値順に管理する業務領域です。Epic、Feature、User Story、欠陥などのバックログ項目を階層的に管理し、受入条件、優先順位、依存関係、変更履歴を追跡します。

- **ユースケース数**: 25
- **外部システム連携**: なし

#### AG-03 価値・要求の優先順位決定

限られた開発リソースを価値、ユーザー満足、リスク、コスト、学習効果に応じて配分する業務領域です。Kano分類、価値・コスト・リスク評価、Product Goalへの寄与度などを総合的に考慮し、POが判断理由を説明できるバックログ順序と投資判断を支援します。

- **ユースケース数**: 10
- **外部システム連携**: なし

#### AG-04 スプリント実行とインクリメント形成

チームがスプリント目標を共有し、作業計画を日々適応させながら、完成の定義を満たすインクリメントを形成する業務領域です。Sprint Goal、Sprint Backlog、作業ボード、障害・依存関係管理、イベント記録、イテレーションダッシュボードなどを統合し、チームの協働と価値ある成果の継続的な提供を支援します。

- **ユースケース数**: 34 (UC-SP-001~019 + UC-IDB-001~015)
- **外部システム連携**: なし

#### AG-05 プロダクト品質・受入・性能検証

開発成果が要求・受入条件・品質基準を満たし、ユーザーにとって安全で有用かを検証する業務領域です。Definition of Done、テストケース、受入テスト、シナリオテスト、欠陥管理、性能検証、セキュリティ・品質リスクなどを統合し、要求と関連づいた検証結果を判断へつなぐ基盤を提供します。

- **ユースケース数**: 19
- **外部システム連携**: ES-08 (Gatling)

#### AG-06 成果計測・フィードバックによる適応

リリースや利用から得られた結果を評価し、Product Goal、要求、優先順位、戦略を更新する業務領域です。Sprint Review、Sprint Retrospective、改善アクション、成果指標、フィードバック管理、ダッシュボード、レポートなどを統合し、ユーザー・事業成果とチームの学習を次の判断へ結びつけます。

- **ユースケース数**: 21
- **外部システム連携**: ES-07 (監視・ログ基盤)

## アクター

Agiloomと相互作用するアクターを定義します。

| ID     | アクター名               | 説明                                                 |
|--------|--------------------------|------------------------------------------------------|
| ACT-01 | 従業員                   | レビューに参加し、利用者視点のフィードバックを提供   |
| ACT-02 | プロダクトオーナー（PO） | 成果・フィードバックを検査し、目標・バックログを更新 |
| ACT-03 | スクラムマスター（SM）   | レトロスペクティブを支援し、改善アクションを追跡     |
| ACT-04 | 開発者                   | 改善を実行し、効果を確かめる                         |
| ACT-05 | トラッキング担当         | 進捗・成果・リスク・改善状況を参照                   |
| ACT-06 | システム管理者           | セキュリティリスクを管理                             |

## 外部システム

Agiloomが連携する外部システムを定義します。

| ID    | 外部システム名       | 連携内容                                       | 関連業務領域         |
|-------|----------------------|------------------------------------------------|----------------------|
| ES-07 | 監視・ログ基盤       | 稼働状況・エラー・ログを取得                   | AG-06                |
| ES-08 | Gatling              | 性能テストの実行条件やレポートを取り込み       | AG-05                |
