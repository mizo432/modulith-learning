# UC-PR-002 優先順位を更新する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-PR-002 |
| ユースケース名 | 優先順位を更新する |
| 英語名 | Update Priority |
| 説明 | 変更された状況に応じて項目の順序を再調整する |
| 関連アクター | ACT-02（プロダクトオーナー） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-PR-01 |
| 外部システム | - |
| 関連画面 | SCR-012（受入条件・受入テスト） |

## 前置条件

- ユーザーがシステムにログインしていること
- 優先順位（INF-PR-01）が既に設定されていること

## 基本フロー

1. ユーザーが「受入条件・受入テスト」画面（SCR-012）にアクセスする
2. 優先順位を更新する項目を選択する
3. 「優先順位を更新」ボタンをクリックする
4. 価値、リスク、コストを再評価する
5. 優先順位を修正する
6. 変更を保存する
7. システムが優先順位（INF-PR-01）を更新する
8. 更新完了メッセージを表示する

## 代替フロー

- **4a. 入力が不完全な場合**
  - 必須項目が未入力の場合、エラーメッセージを表示する
  - ユーザーは入力を修正して再試行する

## 後置条件

- 優先順位（INF-PR-01）が更新される
- イベント「EVT-PR-002 優先順位が更新された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-PR-01 | 優先順位 | 更新対象の情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-PR-002 | 優先順位が更新された | 基本フローステップ7完了後 |

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 必須項目 | 価値、リスク、コストは必須評価 |
| 2 | 優先度範囲 | 1-10の範囲で設定 |
