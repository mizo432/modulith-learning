# UC-QL-010 受入テストを実行する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-QL-010 |
| ユースケース名 | 受入テストを実行する |
| 英語名 | Execute Acceptance Test |
| 説明 | 業務シナリオに沿った期待結果と確認結果を記録する |
| 関連アクター | ACT-01（従業員）、ACT-02（プロダクトオーナー）、ACT-04（開発チーム） |
| 優先度 | 中 |
| ビジネスユースケース | BUC-QL-03 |
| 外部システム | - |
| 関連画面 | SCR-020（シナリオテスト管理） |

## 前置条件

- ユーザーがシステムにログインしていること
- テストケース（INF-QL-02）が既に存在すること

## 基本フロー

1. ユーザーが「シナリオテスト管理」画面（SCR-020）にアクセスする
2. 実行対象のテストケースを選択する
3. 「受入テストを実行」ボタンをクリックする
4. テスト手順を実行し、確認結果を入力する
5. 期待結果と確認結果を比較する
6. 結果を保存する
7. システムがテスト実行結果（INF-QL-03）を登録する
8. 実行完了メッセージを表示する

## 代替フロー

- **5a. 期待結果と確認結果が一致しない場合**
  - テストが失敗したと判定する
  - UC-QL-004（欠陥を登録する）を実行する

## 後置条件

- テスト実行結果（INF-QL-03）がシステムに登録される
- イベント「EVT-QL-007 受入テストが実行された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-QL-02 | テストケース | 実行対象の情報 |
| INF-QL-03 | テスト実行結果 | 作成対象の情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-QL-007 | 受入テストが実行された | 基本フローステップ7完了後 |

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 必須項目 | 確認結果は必須入力 |
