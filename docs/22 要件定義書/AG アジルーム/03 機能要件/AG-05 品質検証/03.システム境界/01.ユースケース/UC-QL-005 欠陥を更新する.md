# UC-QL-005 欠陥を更新する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-QL-005 |
| ユースケース名 | 欠陥を更新する |
| 英語名 | Update Defect |
| 説明 | 欠陥の状態・対応状況・解決方法を修正する |
| 関連アクター | ACT-01（従業員）、ACT-02（プロダクトオーナー）、ACT-04（開発チーム） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-QL-04 |
| 外部システム | - |
| 関連画面 | SCR-020（シナリオテスト管理） |

## 前置条件

- ユーザーがシステムにログインしていること
- 欠陥（INF-QL-04）が既に存在すること

## 基本フロー

1. ユーザーが「シナリオテスト管理」画面（SCR-020）にアクセスする
2. 更新対象の欠陥を選択する
3. 「編集」ボタンをクリックする
4. 状態、対応状況、解決方法を修正する
5. 変更を保存する
6. システムが欠陥（INF-QL-04）を更新する
7. 更新完了メッセージを表示する

## 代替フロー

- **4a. 入力が不完全な場合**
  - 必須項目が未入力の場合、エラーメッセージを表示する
  - ユーザーは入力を修正して再試行する

## 後置条件

- 欠陥（INF-QL-04）が更新される
- イベント「EVT-QL-004 欠陥が更新された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-QL-04 | 欠陥 | 更新対象の情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-QL-004 | 欠陥が更新された | 基本フローステップ6完了後 |

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 必須項目 | 状態は必須入力 |
| 2 | 状態遷移 | 定義された状態遷移ルールに従う |
