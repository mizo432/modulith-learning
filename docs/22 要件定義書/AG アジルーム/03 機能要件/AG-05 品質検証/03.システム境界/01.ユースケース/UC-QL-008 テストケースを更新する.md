# UC-QL-008 テストケースを更新する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-QL-008 |
| ユースケース名 | テストケースを更新する |
| 英語名 | Update Test Case |
| 説明 | テストケースの詳細・手順を修正する |
| 関連アクター | ACT-02（プロダクトオーナー）、ACT-04（開発チーム） |
| 優先度 | 中 |
| ビジネスユースケース | BUC-QL-02 |
| 外部システム | - |
| 関連画面 | SCR-020（シナリオテスト管理） |

## 前置条件

- ユーザーがシステムにログインしていること
- テストケース（INF-QL-02）が既に存在すること

## 基本フロー

1. ユーザーが「シナリオテスト管理」画面（SCR-020）にアクセスする
2. 更新対象のテストケースを選択する
3. 「編集」ボタンをクリックする
4. 詳細、手順、期待結果を修正する
5. 変更を保存する
6. システムがテストケース（INF-QL-02）を更新する
7. 更新完了メッセージを表示する

## 代替フロー

- **4a. 入力が不完全な場合**
  - 必須項目が未入力の場合、エラーメッセージを表示する
  - ユーザーは入力を修正して再試行する

## 後置条件

- テストケース（INF-QL-02）が更新される
- イベント「EVT-QL-006 テストケースが更新された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-QL-02 | テストケース | 更新対象の情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-QL-006 | テストケースが更新された | 基本フローステップ6完了後 |

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 必須項目 | テストケース名、手順、期待結果は必須入力 |
| 2 | 文字数制限 | 手順は2000文字以内 |
