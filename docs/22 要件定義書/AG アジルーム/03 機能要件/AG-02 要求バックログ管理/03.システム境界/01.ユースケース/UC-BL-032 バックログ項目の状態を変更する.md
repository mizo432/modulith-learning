# UC-BL-032 バックログ項目の状態を変更する

要求・プロダクトバックログ管理業務領域のユースケースを定義します。

## 概要

| 項目             | 内容 |
|------------------|------|
| ユースケースID   | UC-BL-032 |
| ユースケース名   | バックログ項目の状態を変更する |
| 説明             | バックログ項目の状態を7つの状態間で遷移させる |
| プライマリアクター | プロダクトオーナー、スクラムマスター、開発者 |
| 関連BUC          | BUC-BL-08 |
| 優先度           | 高 |

## 前提条件

- バックログ項目が存在すること
- 操作者が該当スクラムチームのメンバーであること
- 遷移種別に応じた権限があること

## 基本イベントフロー

1. アクターが状態を変更するバックログ項目を選択する
2. システムが現在の状態を表示する
3. アクターが遷移先状態を選択する
4. システムが遷移の妥当性を検証する
   - 許可された遷移パスであること
   - 操作者に権限があること
   - 前提条件が満たされていること
5. システムが状態を変更する
6. システムが BacklogItemStatusChanged イベントを発行する
7. システムが変更結果を通知する

## 例外フロー

### 4a. 許可されていない遷移の場合
- システムがエラーメッセージを表示する
- 状態は変更されない
- ユースケースは終了する

### 4b. 権限がない場合
- SUGGESTED→ACCEPTED/FROZEN を試みたがPO/SMでない場合
- FROZEN→SUGGESTED を試みたがPOでない場合
- ACCEPTED→READY、READY→SUGGESTED/ESTIMATED、ESTIMATED→READY、ESTIMATED→IN_PROGRESS、IN_PROGRESS→DONE を試みたがチームメンバーでない場合
- システムが権限エラーメッセージを表示する
- 状態は変更されない
- ユースケースは終了する

### 4c. 前提条件が満たされていない場合
- SUGGESTED→ACCEPTED 時にValueが未設定の場合
- READY→ESTIMATED 時にStoryPointが未設定の場合
- ESTIMATED→IN_PROGRESS 時にスプリントに割り当てられていない場合
- システムが前提条件エラーメッセージを表示する
- 状態は変更されない
- ユースケースは終了する

## 状態遷移ルール

| 遷移 | 権限 | 前提条件 |
|------|------|----------|
| SUGGESTED → ACCEPTED | PO/SM | Valueが設定されていること |
| SUGGESTED → FROZEN | PO/SM | - |
| FROZEN → SUGGESTED | POのみ | - |
| ACCEPTED → READY | チームメンバー全員 | - |
| READY → SUGGESTED | チームメンバー全員 | - |
| READY → ESTIMATED | チームメンバー全員 | StoryPointが設定されていること |
| ESTIMATED → READY | チームメンバー全員 | - |
| ESTIMATED → IN_PROGRESS | チームメンバー全員 | スプリントに割り当てられていること |
| IN_PROGRESS → DONE | チームメンバー全員 | - |

## 関連情報

| 情報名 | 説明 |
|--------|------|
| バックログ項目 | 状態変更の対象となるバックログ項目 |
| 状態 | バックログ項目の7つの状態区分 |

## 関連イベント

| イベント名 | 説明 |
|------------|------|
| バックログ項目の状態が変更された | 状態遷移が発生したことを通知するイベント |

## 関連ビジネスルール

| ルール名 | 説明 |
|----------|------|
| 状態遷移の制約 | バックログ項目は定義された状態遷移のみ許可 |

## 補足

- IN_PROGRESS と DONE への通常遷移は定義済み（ESTIMATED→IN_PROGRESS→DONE）
- スプリント割当の操作では状態は変更しない（ESTIMATED→IN_PROGRESS の前提条件のみ）
- DONE は終端状態であり、戻す遷移は設けない
- 分割操作（UC-BL-010）で元項目が DONE になる遷移は別ユースケースで扱う
- 状態遷移の履歴はロングタームイベントパターン（BacklogItemStatusChangedイベント）で担保
- UC-BL-008（バックログ項目を更新する）は内容更新を担当し、状態変更は本UCが担当
