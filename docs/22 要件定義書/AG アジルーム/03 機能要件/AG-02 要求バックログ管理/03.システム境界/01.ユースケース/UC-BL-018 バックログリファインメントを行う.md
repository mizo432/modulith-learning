# UC-BL-018 バックログリファインメントを行う

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-BL-018 |
| ユースケース名 | バックログリファインメントを行う |
| 英語名 | Refine Backlog |
| 説明 | 項目の説明・分割・受入条件・依存関係・準備状況を整える |
| 関連アクター | ACT-02（プロダクトオーナー）、ACT-04（開発チーム） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-BL-03 |
| 外部システム | - |
| 関連画面 | SCR-010（Product Backlog） |

## 前置条件

- ユーザーがシステムにログインしていること
- バックログ項目（INF-BL-01）が既に存在すること

## 基本フロー

1. ユーザーが「Product Backlog」画面（SCR-010）にアクセスする
2. リファインメント対象の項目を選択する
3. 「リファインメント」ボタンをクリックする
4. 説明、分割、受入条件、依存関係、準備状況を確認・修正する
5. 変更を保存する
6. システムがバックログ項目（INF-BL-01）を更新する
7. リファインメント完了メッセージを表示する

## 代替フロー

- **4a. 分割が必要な場合**
  - 項目が大きい場合、分割して小さな項目を作成する
  - UC-BL-010（バックログ項目を分割する）を実行する

## 後置条件

- バックログ項目（INF-BL-01）が更新される
- イベント「EVT-BL-020 バックログリファインメントが完了した」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-BL-01 | バックログ項目 | リファインメント対象の情報 |

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-BL-020 | バックログリファインメントが完了した | 基本フローステップ6完了後 |
