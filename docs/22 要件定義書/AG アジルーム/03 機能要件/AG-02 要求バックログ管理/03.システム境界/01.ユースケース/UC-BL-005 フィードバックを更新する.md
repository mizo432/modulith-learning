# UC-BL-005 フィードバックを更新する

ユースケースの詳細を定義します。

## 概要

| 項目 | 内容 |
|------|------|
| ユースケースID | UC-BL-005 |
| ユースケース名 | フィードバックを更新する |
| 英語名 | Update Feedback |
| 説明 | フィードバックの対応状況と判断理由を追跡する |
| 関連アクター | ACT-01（従業員）、ACT-02（プロダクトオーナー） |
| 優先度 | 高 |
| ビジネスユースケース | BUC-BL-05 |
| 外部システム | - |
| 関連画面 | SCR-010（Product Backlog） |

## 前置条件

- ユーザーがシステムにログインしていること
- フィードバック（INF-BL-03）が既に存在すること

## 基本フロー

1. ユーザーが「Product Backlog」画面（SCR-010）にアクセスする
2. 既存のフィードバックを選択する
3. 「編集」ボタンをクリックする
4. 対応状況、判断理由を修正する
5. 変更を保存する
6. システムがフィードバック（INF-BL-03）を更新する
7. 更新完了メッセージを表示する

## 代替フロー

- **4a. 入力が不完全な場合**
  - 必須項目が未入力の場合、エラーメッセージを表示する
  - ユーザーは入力を修正して再試行する

## 後置条件

- フィードバック（INF-BL-03）が更新される
- イベント「EVT-BL-004 フィードバックが更新された」が発行される

## 関連情報

| 情報ID | 情報名 | 使用目的 |
|--------|--------|----------|
| INF-BL-03 | フィードバック | 更新対象の情報 |

## 関連イベント

| イベントID | イベント名 | 発生タイミング |
|------------|------------|----------------|
| EVT-BL-004 | フィードバックが更新された | 基本フローステップ6完了後 |

## 制約事項

| 番号 | 制約事項 | 説明 |
|------|----------|------|
| 1 | 必須項目 | 対応状況は必須入力 |
| 2 | 文字数制限 | 判断理由は1000文字以内 |
