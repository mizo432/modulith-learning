# バリエーション条件図

Agiloomのシステムが動く「条件」と、それを成り立たせる「バリエーション」を表形式で定義します。

## バリエーション一覧

| ID      | バリエーション名   | 説明                                                     | 関連業務領域 |
|---------|--------------------|----------------------------------------------------------|--------------|
| VAR-001 | バックログ項目種別 | Epic、Feature、Story、Task                               | AG-02        |
| VAR-002 | 優先度レベル       | 高、中、低                                               | AG-02, AG-03 |
| VAR-003 | Kano品質カテゴリ   | 当たり前品質、一元品質、魅力的品質、無関心品質、逆品質   | AG-01, AG-03 |
| VAR-004 | スプリント状態     | 計画済み、実行中、完了、キャンセル                       | AG-04        |
| VAR-005 | 作業状態           | 未着手、作業中、レビュー中、完了                         | AG-04        |
| VAR-006 | 欠陥深刻度         | 致命的、重大、軽微、推奨                                 | AG-05        |
| VAR-007 | テスト種別         | 手動テスト、自動テスト、性能テスト                       | AG-05        |
| VAR-008 | テスト結果         | 合格、不合格                                             | AG-05        |
| VAR-009 | 改善アクション種別 | プロセス改善、ツール改善、スキル向上                     | AG-06        |
| VAR-010 | リスク種別         | 技術リスク、スケジュールリスク、リソースリスク           | AG-06        |
| VAR-011 | アクター種別       | 従業員、PO、SM、開発者、トラッキング担当、システム管理者 | 全体         |
| VAR-012 | 通知種別           | メンション、担当変更、期限、判断待ち                     | AG-04        |

| COND-003 | スプリント開始条件           | Sprint GoalとSprint Backlogが定義されていること            | VAR-004            | UC-SP-001             | ポリシー       |

| COND-006 | 欠陥深刻度に応じた対応ルール | 致命的・重大な欠陥は即座に対応する                         | VAR-006            | UC-QL-004             | ポリシー       |

| COND-010 | リスク対応ルール             | 許容範囲を超えるリスクは対応策を実行する                   | VAR-010            | UC-LR-011             | ポリシー       |

| COND-012 | Kano分類計算ルール           | 機能がある場合・ない場合の回答対から品質カテゴリを導出する | VAR-003            | UC-DIS-023, UC-PR-007 | 意思決定支援   |
| COND-013 | バックログ階層制約           | Product Goal > Epic > Feature > Story > Task の階層構造    | VAR-001            | UC-BL-011             | ポリシー       |
| COND-014 | ソース管理連携条件           | コミット・ブランチ・PRをバックログ項目と関連付ける         | VAR-001            | UC-BL-025, UC-SP-018  | オペレーション |
| COND-015 | 権限ベースの画面表示ルール   | ロールに応じた情報だけを表示する                           | VAR-011            | UC-LR-009             | ポリシー       |

## 条件とバリエーションの関連

| 条件ID   | 条件名                       | 関連バリエーションID | 詳細                                                   |
|----------|------------------------------|----------------------|--------------------------------------------------------|
| COND-001 | バックログ項目の準備完了条件 | VAR-001              | Epic・Feature・Storyそれぞれに異なる準備完了条件を適用 |
| COND-002 | 優先順位決定ルール           | VAR-002, VAR-003     | Kano分類結果を優先度レベルの判断に反映                 |
| COND-003 | スプリント開始条件           | VAR-004              | 計画済み状態から実行中状態への遷移条件                 |
| COND-004 | 作業完了条件                 | VAR-005              | 完了状態への遷移条件                                   |
| COND-006 | 欠陥深刻度に応じた対応ルール | VAR-006              | 深刻度ごとにスラッシュタイムを定義                     |
| COND-007 | テスト実行条件               | VAR-007              | テスト種別ごとに実行条件を定義                         |
| COND-008 | 性能テスト合格基準           | VAR-007              | 性能テストの合格基準を定義                             |
| COND-010 | リスク対応ルール             | VAR-010              | リスク種別ごとに対応策の優先度を定義                   |
| COND-011 | 通知送信ルール               | VAR-012              | 通知種別ごとに送信タイミングを定義                     |
| COND-015 | 権限ベースの画面表示ルール   | VAR-011              | アクター種別ごとに表示可能な情報を定義                 |
