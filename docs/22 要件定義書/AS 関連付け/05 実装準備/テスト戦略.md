# テスト戦略

AS関連付け（Association）事業領域のテスト戦略を定義します。

## 概要

本ドキュメントでは、AS関連付けの実装に対するテストの範囲、方針、テストレベル別の構成を定義します。

## テスト方針

1. **テストファースト**: ユースケース実装前にテストケースを定義
2. **レイヤー別テスト**: 各レイヤー（Repository、Service、Controller）ごとに適切なテストレベルを適用
3. **アグリゲート境界尊重**: DDDのアグリゲート境界を単位としてテストを設計
4. **外部依存のモック**: 外部システム連携はモックを使用してテスト

## テストレベル構成

| レベル | テスト種別 | 対象 | 説明 |
|--------|-----------|------|------|
| L1 | 単体テスト | エンティティ、リポジトリ、サービス | 各コンポーネントの動作検証 |
| L2 | 統合テスト | APIエンドポイント | リクエスト・レスポンスの検証 |
| L3 | 契約テスト | 外部システム連携 | API契約の検証 |

## テストカバレッジ目標

| レベル | カバレッジ目標 | 説明 |
|--------|--------------|------|
| 単体テスト | 80% 以上 | 行カバレッジ |
| 統合テスト | 主要APIエンドポイント100% | 全エンドポイントのテスト実施 |
| 契約テスト | 外部連携イベント100% | 全イベントの契約検証 |

## テスト実行戦略

### ビルド時テスト

| フェーズ | テスト種別 | 説明 |
|---------|-----------|------|
| ビルド時 | 単体テスト | `gradle test` で自動実行 |
| CI/CD | 統合テスト | `gradle integrationTest` で自動実行 |
| CI/CD | 契約テスト | `gradle contractTest` で自動実行 |

### テストデータ管理

- **単体テスト**: テストメソッド内でテストデータを生成
- **統合テスト**: SQLスクリプトでテストデータを準備
- **テストデータクリーンアップ**: @Transactional で自動ロールバック
