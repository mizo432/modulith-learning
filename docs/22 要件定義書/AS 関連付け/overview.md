# 概要

本ドキュメントは、AS 関連付け（Association）事業領域の要件定義の概要です。

AS 関連付け（Association）は、組織・部署・従業員・会社・店舗などの実体とその関連付けを管理するコア基盤モジュールです。Party Roleパターンを採用し、実体(Party)とロール(Role)を分離することで、柔軟な関連付け構造を実現します。

## 事業領域情報

- 事業領域コード: AS
- 事業領域名: 関連付け
- 事業領域英名: Association
- 区分: 支援

## Party Roleパターン

AS モジュールはParty Roleパターンを採用しています。このパターンでは、以下の4つの業務領域に分離して管理します。

### 1. パーティー (Party)

組織・人・会社・店舗などの実体を抽象化した基盤エンティティです。Party Roleパターンの中心となる概念で、具体的なロール(組織ロール・人ロール)はパーティーを基盤として構築されます。

**主な責務:**
- 実体の一意な識別
- 実体の基本情報管理
- 有効期間の管理
- ロールとの関連付け

### 2. パーティーロール (PartyRole)

パーティーに付与されるロールの定義を管理します。ロールの種類や属性を一元管理し、組織ロール・人ロールの共通基盤となります。

**主な責務:**
- ロール定義の管理
- ロール属性の管理
- ロール有効期間の管理

### 3. 人ロール (PersonRole)

個人(従業員)に特化したロール管理です。従業員の所属組織・部署との関連付けを管理し、人事情報との連携を可能にします。

**主な責務:**
- 従業員の所属管理
- 部署変更履歴の管理
- 会社・店舗との関連付け
- 権限範囲の管理

### 4. 組織ロール (OrganizationRole)

組織・部署・会社・店舗に特化したロール管理です。階層構造や権限範囲を管理し、組織図の構築を可能にします。

**主な責務:**
- 組織階層の管理
- 部署構造の管理
- 会社・店舗の管理
- 権限範囲の定義

## RDRA 4レイヤー

1. システム価値レイヤー: 要求、アクター、外部システム
2. 外部環境レイヤー: 業務、BUC、アクティビティ
3. システム境界レイヤー: ユースケース、画面、イベント
4. システムレイヤー: 情報、状態、条件、バリエーション

## 他の事業領域との関係

AS モジュールは以下の事業領域から参照されます。

- **JB ジョブ管理**: 会社・店舗別のジョブ実行権限フィルタリング、通知対象設定、監査ログの操作者情報
- **AG アジルーム**: プロジェクトメンバー管理、権限管理
- **AZ 認可**: ユーザー権限管理のための組織・従業員情報参照
