# DDDモデル候補

AS関連付け（Association）事業領域のRDRAモデルから抽出したDDDモデル候補です。

## 概要

本ドキュメントは、AS関連付けのRDRA要件定義書（フェーズ1〜3）を分析し、DDD（Domain-Driven Design）の概念に基づいてサブドメインとバウンデドコンテキストの候補を抽出したものです。

## 分析方法

RDRAモデルの以下の要素を分析して、DDDモデル候補を抽出します。

- **ユースケース**: システムが提供する機能
- **情報**: システムが管理するデータ
- **状態**: エンティティの状態遷移
- **条件**: ビジネスルール
- **バリエーション**: 条件の変数

## サブドメイン分類

サブドメインは、以下の3つのカテゴリに分類します。

| カテゴリ | 英語表記 | 説明 |
|----------|----------|------|
| **コアドメイン** | Core Domain | 事業の競争優位性を生み出す中核的な領域 |
| **サポートドメイン** | Supporting Domain | コアドメインを支える補助的な領域 |
| **ジェネリックドメイン** | Generic Domain | 汎用的な領域。外部サービスやフレームワークで実現可能 |

## サブドメイン候補一覧

| 番号 | サブドメインコード | サブドメーニン | 分類 | 説明 |
|------|-------------------|----------------|------|------|
| 01 | AS-PARTY | パーティー管理 | コアドメイン | 実体(Party)の一元管理。Party Roleパターンの基盤となる中核機能 |
| 02 | AS-PARTY-ROLE | ロール定義管理 | コアドメイン | ロール定義の管理。Party Roleパターンの中核機能 |
| 03 | AS-PERSON | 従業員管理 | サポートドメイン | 従業員の所属管理。コアドomainを支える補助機能 |
| 04 | AS-ORG | 組織管理 | サポートドメイン | 組織・部署・会社・店舗の管理。コアドメインを支える補助機能 |

### 分類の根拠

#### コアドメイン: パーティー管理 (AS-PARTY)

- **理由**: Party Roleパターンの中心となる概念であり、AS関連付け事業領域の競争優位性を生み出す中核機能
- **ユースケース数**: 8件
- **情報数**: 4件
- **特徴**: 実体の一意な識別、基本情報管理、有効期間管理、ロールとの関連付けなど、Party Roleパターンの基盤となる機能

#### コアドメイン: ロール定義管理 (AS-PARTY-ROLE)

- **理由**: Party Roleパターンにおいて、ロールの定義と管理は中核的な機能であり、柔軟な関連付け構造を実現する
- **ユースケース数**: 8件
- **情報数**: 4件
- **特徴**: ロール定義の管理、ロール属性の管理、ロール有効期間の管理など、Party Roleパターンの中核機能

#### サポートドメイン: 従業員管理 (AS-PERSON)

- **理由**: コアドメイン(Party, PartyRole)を支える補助的な機能。従業員の所属管理は重要だが、Party Roleパターンという中核概念を支える役割
- **ユースケース数**: 8件
- **情報数**: 4件
- **特徴**: 従業員の登録・更新・検索、所属変更、部署変更履歴など、人事管理に関連する機能

#### サポートドメイン: 組織管理 (AS-ORG)

- **理由**: コアドメイン(Party, PartyRole)を支える補助的な機能。組織・部署・会社・店舗の管理は重要だが、Party Roleパターンという中核概念を支える役割
- **ユースケース数**: 13件
- **情報数**: 7件
- **特徴**: 組織の登録・更新・検索、階層構造の管理、会社・店舗の管理など、組織管理に関連する機能

## バウンデドコンテキスト候補

バウンデドコンテキストは、サブドメインの境界を明確にし、モデルの独立性を保つために定義します。

| 番号 | コンテキストコード | コンテキスト名 | 包含するサブドメイン | 説明 |
|------|-------------------|---------------|---------------------|------|
| 01 | AS-BC-PARTY | パーティーコンテキスト | AS-PARTY, AS-PARTY-ROLE | Party Roleパターンの基盤となるコンテキスト |
| 02 | AS-BC-PERSON | 従業員コンテキスト | AS-PERSON | 従業員管理に特化したコンテキスト |
| 03 | AS-BC-ORG | 組織コンテキスト | AS-ORG | 組織管理に特化したコンテキスト |

### コンテキストの境界

#### パーティーコンテキスト (AS-BC-PARTY)

- **包含するサブドメイン**: AS-PARTY, AS-PARTY-ROLE
- **理由**: PartyとPartyRoleは密接に関連しており、Party Roleパターンの基盤となるため、同じコンテキストに包含
- **モデルの独立性**: 他のコンテキストから参照されるが、自律的に動作可能
- **共通言語**: Party, PartyRole, ロール付与、ロール解除など

#### 従業員コンテキスト (AS-BC-PERSON)

- **包含するサブドメイン**: AS-PERSON
- **理由**: 従業員管理はParty Roleパターンに基づき、PersonRoleとして管理されるが、業務的な観点から独立したコンテキストとして定義
- **モデルの独立性**: パーティーコンテキストを参照するが、自律的に動作可能
- **共通言語**: 従業員、所属組織、部署変更、入社日、退社日など

#### 組織コンテキスト (AS-BC-ORG)

- **包含するサブドメイン**: AS-ORG
- **理由**: 組織管理はParty Roleパターンに基づき、OrganizationRoleとして管理されるが、業務的な観点から独立したコンテキストとして定義
- **モデルの独立性**: パーティーコンテキストを参照するが、自律的に動作可能
- **共通言語**: 組織、部署、会社、店舗、階層構造、権限範囲など

## コンテキストマップ

コンテキストマップは、バウンデドコンテキスト間の関係を可視化します。

```
                    ┌─────────────────────────┐
                    │   パーティーコンテキスト   │
                    │   (AS-BC-PARTY)          │
                    │                          │
                    │  ┌────────────────────┐  │
                    │  │  パーティー管理      │  │
                    │  │  (AS-PARTY)        │  │
                    │  └────────────────────┘  │
                    │         ▲                 │
                    │         │ 依存            │
                    │  ┌────────────────────┐  │
                    │  │  ロール定義管理      │  │
                    │  │  (AS-PARTY-ROLE)   │  │
                    │  └────────────────────┘  │
                    └─────────────────────────┘
                              ▲
                              │ 依存
              ┌───────────────┴───────────────┐
              │                               │
    ┌────────────────────┐      ┌────────────────────┐
    │  従業員コンテキスト    │      │  組織コンテキスト     │
    │  (AS-BC-PERSON)    │      │  (AS-BC-ORG)      │
    │                    │      │                    │
    │  ┌──────────────┐  │      │  ┌──────────────┐  │
    │  │  従業員管理    │  │      │  │  組織管理      │  │
    │  │  (AS-PERSON) │  │      │  │  (AS-ORG)    │  │
    │  └──────────────┘  │      │  └──────────────┘  │
    └────────────────────┘      └────────────────────┘
```

### コンテキスト間の関係

| 関係タイプ | 説明 | 関係するコンテキスト |
|------------|------|---------------------|
| **依存関係** | 下流コンテキストが上流コンテキストに依存 | 従業員コンテキスト → パーティーコンテキスト |
| **依存関係** | 下流コンテキストが上流コンテキストに依存 | 組織コンテキスト → パーティーコンテキスト |

#### 依存関係の詳細

1. **従業員コンテキスト → パーティーコンテキスト**
   - 従業員(PersonRole)はPartyを参照
   - 従業員の登録時、PartyとPersonRoleを関連付け
   - 所属変更時、PartyRoleの情報を更新

2. **組織コンテキスト → パーティーコンテキスト**
   - 組織(OrganizationRole)はPartyを参照
   - 組織の登録時、PartyとOrganizationRoleを関連付け
   - 階層構造変更時、PartyRoleの情報を更新

## アグリゲート候補

各バウンデドコンテキスト内のアグリゲート候補を整理します。

### パーティーコンテキスト

| アグリゲートルート | 包含するエンティティ | 説明 |
|-------------------|-------------------|------|
| Party | Party, PartyRole | パーティーとそのロールの関連付けを管理 |

### 従業員コンテキスト

| アグリゲートルート | 包含するエンティティ | 説明 |
|-------------------|-------------------|------|
| PersonRole | PersonRole, 所属情報 | 従業員とその所属情報を管理 |

### 組織コンテキスト

| アグリゲートルート | 包含するエンティティ | 説明 |
|-------------------|-------------------|------|
| OrganizationRole | OrganizationRole, 階層情報 | 組織とその階層構造を管理 |
| Company | Company | 会社の情報を管理 |
| Store | Store | 店舗の情報を管理 |

## 実装上の推奨事項

1. **モジュール境界**: バウンデドコンテキストごとにモジュールを分離することを推奨
2. **ドメインサービス**: Party Roleパターンの関連付け処理はドメインサービスとして実装
3. **リポジトリ**: アグリゲートルートごとにリポジトリを定義
4. **ドメインイベント**: 状態変化（例: 従業員登録完了、組織登録完了）はドメインイベントとして発行
