# セキュリティ設計

AG-04スプリント実行の認証・認可設計を定義します。

## 1. 概要

JWT（JSON Web Token）による認証とRBAC（Role-Based Access Control）による認可を採用し、APIのセキュリティを確保します。

## 2. 認証方式

### 2.1 JWT認証

- **認証方式**: Bearer Token (JWT)
- **ヘッダー**: `Authorization: Bearer <token>`
- **トークン形式**: JSON Web Token (RFC 7519)
- **署名アルゴリズム**: RS256 (非対称暗号)

### 2.2 トークンの種類

| トークン | 有効期間 | 説明 |
|---------|---------|------|
| Access Token | 30分 | APIアクセスに使用 |
| Refresh Token | 7日間 | Access Tokenの更新に使用 |

### 2.3 Access Tokenのペイロード

```json
{
  "sub": "1",
  "userId": 1,
  "username": "tanaka",
  "roles": ["PRODUCT_OWNER", "DEVELOPER"],
  "productId": 1,
  "iat": 1704067200,
  "exp": 1704069000,
  "iss": "agiloom-api"
}
```

| クレーム | 説明 |
|---------|------|
| `sub` | サブジェクト（ユーザーID文字列） |
| `userId` | ユーザーID（数値） |
| `username` | ユーザー名 |
| `roles` | 役割リスト |
| `productId` | プロダクトID |
| `iat` | トークン発行時刻 |
| `exp` | トークン有効期限 |
| `iss` | トークン発行者 |

### 2.4 トークンフロー

```
1. ログイン
   POST /api/auth/login
   Request: { username, password }
   Response: { accessToken, refreshToken, expiresIn }

2. APIアクセス
   GET /api/v1/sprints
   Headers: Authorization: Bearer <accessToken>

3. トークン更新
   POST /api/auth/refresh
   Request: { refreshToken }
   Response: { accessToken, refreshToken, expiresIn }

4. ログアウト
   POST /api/auth/logout
   Headers: Authorization: Bearer <accessToken>
   Response: 204 No Content
```

## 3. 認可方式

### 3.1 RBAC（Role-Based Access Control）

ユーザーの役割に基づいてアクセス権限を制御します。

### 3.2 役割一覧

| 役割 | 説明 | 説明 |
|-----|------|------|
| PRODUCT_OWNER | プロダクトオーナー | プロダクトの方向性を決定し、スプリントの目標を設定 |
| SCRUM_MASTER | スクラムマスター | スプリントの進行を管理し、障害の解消を支援 |
| DEVELOPER | 開発者 | タスクの実行と状態更新を担当 |
| VIEWER | 閲覧者 | 参照のみ可能 |

### 3.4 リソース所有権ベースの認可

一部のエンドポイントでは、リソースの所有者のみが操作できるようにします。

| エンドポイント | 認可条件 |
|---------------|---------|
| `GET /notifications/{id}` | 通知の受信者（recipientId）と一致するユーザーのみ |
| `PATCH /notifications/{id}/read` | 通知の受信者（recipientId）と一致するユーザーのみ |
| `PUT /daily-scrums/{id}` | 記録の作成者（teamMemberId）と一致するユーザーのみ |
| `DELETE /daily-scrums/{id}` | 記録の作成者（teamMemberId）またはSCRUM_MASTERのみ |

## 4. Spring Security設定

### 4.1 SecurityFilterChain設定

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .sessionManagement(session -> 
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()
                .requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers("/api/v1/**").authenticated()
                .anyRequest().denyAll()
            )
            .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class)
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint(new JwtAuthenticationEntryPoint())
                .accessDeniedHandler(new JwtAccessDeniedHandler())
            );

        return http.build();
    }
}
```

### 4.2 JWT認証フィルター

```java
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain
    ) throws ServletException, IOException {
        String authHeader = request.getHeader("Authorization");

        if (authHeader != null && authHeader.startsWith("Bearer ")) {
            String token = authHeader.substring(7);
            try {
                Claims claims = jwtService.validateToken(token);
                List<SimpleGrantedAuthority> authorities = 
                    claims.get("roles", List.class)
                        .stream()
                        .map(role -> new SimpleGrantedAuthority("ROLE_" + role))
                        .collect(Collectors.toList());

                Authentication authentication = new UsernamePasswordAuthenticationToken(
                    claims.getSubject(),
                    null,
                    authorities
                );
                SecurityContextHolder.getContext().setAuthentication(authentication);
            } catch (JwtException e) {
                response.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Invalid token");
                return;
            }
        }

        filterChain.doFilter(request, response);
    }
}
```

## 5. CORS設定

### 5.1 許可されたオリジン

| 環境 | 許可されたオリジン |
|-----|-----------------|
| 開発 | `http://localhost:3000` |
| ステージング | `https://staging-agiloom.example.com` |
| 本番 | `https://agiloom.example.com` |

### 5.2 CORS設定

```java
@Configuration
public class CorsConfig {

    @Bean
    public WebMvcConfigurer corsConfigurer() {
        return new WebMvcConfigurer() {
            @Override
            public void addCorsMappings(CorsRegistry registry) {
                registry.addMapping("/api/**")
                    .allowedOrigins(
                        "http://localhost:3000",
                        "https://agiloom.example.com"
                    )
                    .allowedMethods("GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS")
                    .allowedHeaders("*")
                    .exposedHeaders("Authorization")
                    .allowCredentials(true)
                    .maxAge(3600);
            }
        };
    }
}
```

## 6. セキュリティヘッダー

| ヘッダー | 値 | 説明 |
|---------|-----|------|
| `X-Content-Type-Options` | `nosniff` | MIMEタイプスニッフィングの防止 |
| `X-Frame-Options` | `DENY` | クリックジャッキングの防止 |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | HTTPSの強制 |
| `X-XSS-Protection` | `1; mode=block` | XSS保護 |
| `Content-Security-Policy` | `default-src 'self'` | コンテンツセキュリティポリシー |

## 7. レートリミッティング

### 7.1 制限設定

| エンドポイント | 制限 | 期間 |
|---------------|------|------|
| `/api/auth/login` | 5回 | 1分 |
| `/api/auth/refresh` | 10回 | 1分 |
| `/api/v1/**` (GET) | 100回 | 1分 |
| `/api/v1/**` (POST/PUT/PATCH/DELETE) | 30回 | 1分 |

## 8. 入力サニタイズ

### 8.1 SQLインジェクション対策

- **PreparedStatement**: すべてパラメータ化されたクエリを使用
- **ORM**: JPA/Hibernateを使用し、ネイティブSQLを避ける
- **入力検証**: 数値フィールドは数値のみ、文字フィールドは正規表現で検証

### 8.2 XSS対策

- **出力エンコーディング**: HTMLエンコーディングを適用
- **CORS**: 許可されたオリジンのみからリクエストを受理
- **Content-Security-Policy**: スクリプトの実行を制限

### 8.3 CSRF対策

- **Stateless設計**: JWT認証によりセッションを使用しない
- **CSRF無効化**: APIはPOST/PUT/PATCHでCSRFトークンを不要とする

## 9. ログのセキュリティ

### 9.1 機密情報の除外

以下の情報はログに記録しません。

- 認証トークン（Access Token, Refresh Token）
- パスワード
- PII（個人識別情報）
- クレジットカード情報

### 9.2 監査ログ

重要な操作は監査ログに記録します。

| イベント | 記録内容 |
|---------|---------|
| ログイン | ユーザーID、IPアドレス、時刻 |
| ログアウト | ユーザーID、時刻 |
| トークン更新 | ユーザーID、時刻 |
| スプリント作成 | ユーザーID、スプリントID、時刻 |
| スプリント削除 | ユーザーID、スプリントID、時刻 |
| 権限エラー | ユーザーID、エンドポイント、時刻 |

### 10.2 セキュリティヘッダーフィルタ

```java
@Component
public class SecurityHeadersFilter implements GlobalFilter {

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        exchange.getResponse().getHeaders().add("X-Content-Type-Options", "nosniff");
        exchange.getResponse().getHeaders().add("X-Frame-Options", "DENY");
        exchange.getResponse().getHeaders().add("Strict-Transport-Security", 
            "max-age=31536000; includeSubDomains");
        return chain.filter(exchange);
    }
}
```

## 11. トークン管理のベストプラクティス

### 11.1 クライアント側

- **トークンの保存**: HttpOnly Cookieまたはメモリ上に保存（localStorageは避ける）
- **トークンの更新**: Access Tokenの期限切れ前に自動でRefresh Tokenを使用
- **ログアウト**: Refresh Tokenの無効化を行う

### 11.2 サーバー側

- **トークンの無効化**: ログアウト時にRefresh Tokenをブラックリストに登録
- **トークンのローテーション**: 毎回のトークン更新で新しいRefresh Tokenを発行
- **トークンの期限**: Access Tokenは短命に設定（30分）
