# エラーハンドリング設計

AG-04スプリント実行の統一されたエラーハンドリング設計を定義します。

## 1. 概要

すべてのAPIエンドポイントで統一されたエラーレスポンス形式を使用し、クライアントが一貫してエラーを処理できるようにします。

## 2. エラーレスポンス形式

すべてのエラーレスポンスは以下のJSON形式で返します。

```json
{
  "error": {
    "status": 400,
    "code": "VALIDATION_ERROR",
    "message": "リクエストの検証に失敗しました",
    "details": [
      {
        "field": "title",
        "message": "タイトルは必須です"
      }
    ],
    "timestamp": "2024-01-01T00:00:00Z",
    "path": "/api/v1/sprints"
  }
}
```

### 2.1 エラーレスポンスのフィールド

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `error.status` | integer | HTTPステータスコード |
| `error.code` | string | エラーコード（大文字・アンダースコア区切り） |
| `error.message` | string | ユーザー向けエラーメッセージ |
| `error.details` | array | 詳細エラー情報（フィールドレベルのエラー） |
| `error.details[].field` | string | エラーが発生したフィールド名 |
| `error.details[].message` | string | フィールドレベルのエラーメッセージ |
| `error.timestamp` | string (datetime) | エラー発生時刻（ISO 8601） |
| `error.path` | string | エラーが発生したエンドポイントのパス |

## 3. HTTPステータスコード一覧

| ステータスコード | 説明 | 使用シーン |
|-----------------|------|-----------|
| 200 | OK | 取得成功 |
| 201 | Created | 作成成功 |
| 204 | No Content | 削除成功 |
| 400 | Bad Request | バリデーションエラー、不正なリクエスト |
| 401 | Unauthorized | 認証失敗 |
| 403 | Forbidden | 認可失敗 |
| 404 | Not Found | リソースが見つからない |
| 409 | Conflict | 重複、状態遷移エラー |
| 422 | Unprocessable Entity | ビジネスロジックエラー |
| 500 | Internal Server Error | サーバー内部エラー |

## 5. バリデーションエラーの処理

### 5.1 Jakarta Validationとの連携

Jakarta Validationアノテーション（`@NotNull`, `@Size`, `@Email` など）によるバリデーションエラーは、`VALIDATION_ERROR` コードで返します。

```json
{
  "error": {
    "status": 400,
    "code": "VALIDATION_ERROR",
    "message": "リクエストの検証に失敗しました",
    "details": [
      {
        "field": "title",
        "message": "タイトルは必須です"
      },
      {
        "field": "startDate",
        "message": "開始日は未来の日付に設定できません"
      }
    ],
    "timestamp": "2024-01-01T00:00:00Z",
    "path": "/api/v1/sprints"
  }
}
```

### 5.2 カスタムバリデーション

ビジネスロジックに依存するバリデーション（例: 期間の重複チェック）は、カスタムバリデーターで実装し、適切なエラーコードで返します。

```json
{
  "error": {
    "status": 409,
    "code": "SPRINT_DATE_OVERLAP",
    "message": "指定された期間は既存のスプリントと重複しています",
    "details": [
      {
        "field": "startDate",
        "message": "2024-01-15 は既存のスプリント期間と重複しています"
      }
    ],
    "timestamp": "2024-01-01T00:00:00Z",
    "path": "/api/v1/sprints"
  }
}
```

## 6. 例外ハンドリングアーキテクチャ

### 6.1 例外階層

```
AgiloomException (基底クラス)
├── ValidationException (400)
├── NotFoundException (404)
├── ConflictException (409)
├── ForbiddenException (403)
└── BusinessLogicException (422)
```

### 6.2 GlobalExceptionHandler

すべてのコントローラーで共通の例外ハンドラーを使用します。

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ValidationException.class)
    public ResponseEntity<ErrorResponse> handleValidationException(ValidationException ex) {
        return ResponseEntity.status(HttpStatus.BAD_REQUEST)
            .body(ErrorResponse.builder()
                .status(HttpStatus.BAD_REQUEST.value())
                .code(ex.getErrorCode())
                .message(ex.getMessage())
                .details(ex.getDetails())
                .timestamp(Instant.now())
                .path(request.getRequestURI())
                .build());
    }

    @ExceptionHandler(NotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFoundException(NotFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(ErrorResponse.builder()
                .status(HttpStatus.NOT_FOUND.value())
                .code(ex.getErrorCode())
                .message(ex.getMessage())
                .timestamp(Instant.now())
                .path(request.getRequestURI())
                .build());
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGenericException(Exception ex) {
        log.error("Unexpected error", ex);
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(ErrorResponse.builder()
                .status(HttpStatus.INTERNAL_SERVER_ERROR.value())
                .code("INTERNAL_ERROR")
                .message("サーバー内部エラーが発生しました")
                .timestamp(Instant.now())
                .path(request.getRequestURI())
                .build());
    }
}
```

## 7. エラーログ設計

### 7.1 ログレベル

| ログレベル | 使用シーン |
|-----------|-----------|
| ERROR | サーバー内部エラー、予期せぬ例外 |
| WARN | バリデーションエラー、ビジネスロジックエラー |
| INFO | 正常なリクエスト・レスポンスの概要 |
| DEBUG | 詳細なデバッグ情報 |

### 7.2 ログフォーマット

```
{timestamp} {level} {class} - {message}
```

例:
```
2024-01-01T00:00:00Z ERROR SprintController - Sprint not found: id=1
2024-01-01T00:00:00Z WARN SprintValidator - Validation failed: title is required
```

### 7.3 機密情報の除外

- 認証トークンはログに記録しない
- パスワードはログに記録しない
- PII（個人識別情報）はログに記録しない

## 8. クライアント側のエラー処理

### 8.1 axiosインターセプター例

```typescript
api.interceptors.response.use(
  (response) => response,
  (error) => {
    if (axios.isAxiosError(error)) {
      const status = error.response?.status;
      const code = error.response?.data?.error?.code;
      const message = error.response?.data?.error?.message;

      switch (status) {
        case 401:
          // トークン期限切れで再認証フロー
          window.location.href = '/login';
          break;
        case 403:
          // アクセス拒否のUI表示
          showErrorMessage('アクセスが拒否されました');
          break;
        case 404:
          // リソースNotFoundのUI表示
          showErrorMessage('リソースが見つかりません');
          break;
        case 400:
        case 409:
          // バリデーションエラーの詳細表示
          showValidationErrors(error.response.data.error.details);
          break;
        default:
          showErrorMessage(message || 'サーバーエラーが発生しました');
      }
    }
    return Promise.reject(error);
  }
);
```

## 9. エラーコードの拡張性

新しいエラーコードを追加する場合は、以下の手順に従います。

1. このドキュメントのエラーコード一覧に追加
2. 対応する例外クラスを作成または更新
3. GlobalExceptionHandlerにハンドラーを追加
4. OpenAPI仕様書にエラーレスポンスを追加
