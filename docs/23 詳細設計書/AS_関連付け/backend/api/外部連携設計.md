# 外部連携設計

## 概要

AS関連付け事業領域の外部システム連携設計を定義します。
本ドキュメントでは、JBジョブ管理・AGアジルームとの連携方法、イベント仕様、エラーハンドリングなどを定義します。

## 1. 連携概要

### 1.1 連携対象システム

| システム名 | 説明 | 連携方向 |
|-----------|------|----------|
| JBジョブ管理 | ジョブ実行管理システム | AS → JB（通知） |
| AGアジルーム | プロジェクト管理システム | AS → AG（通知） |

### 1.2 連携方法

AS関連付けは、以下の連携方法を採用します。

| 連携方法 | 説明 | 使用ケース |
|---------|------|-----------|
| 同期API連携 | HTTP APIを同期で呼び出し | 即時反映が必要な場合 |
| 非同期イベント連携 | メッセージキュー経由でイベント配信 | 遅延許容の場合 |

### 1.3 連携アーキテクチャ

```
┌─────────────┐     ┌──────────────────┐     ┌──────────────────┐
│  AS関連付け  │────>│  Message Queue   │────>│  JBジョブ管理    │
│  (Publisher)│     │  (RabbitMQ等)    │     │  (Subscriber)    │
└─────────────┘     └──────────────────┘     └──────────────────┘
       │                      │
       │                      ├────>┌──────────────────┐
       │                      │     │  AGアジルーム    │
       │                      │     │  (Subscriber)    │
       │                      │     └──────────────────┘
       │                      │
       │     ┌────────────────┘
       │     │
       └────>│  (同期API連携)
```

## 2. JBジョブ管理連携

### 2.1 連携概要

JBジョブ管理は、AS関連付けから会社・店舗・従業員の変更通知を受信します。

### 2.2 連携イベント一覧

| イベント名 | トピック | 発生条件 |
|-----------|---------|----------|
| 会社変更通知 | as.company.changed | 会社の登録・更新・廃止時 |
| 店舗変更通知 | as.store.changed | 店舗の登録・更新・廃止時 |
| 従業員変更通知 | as.employee.changed | 従業員の登録・更新・退社時 |

### 2.3 イベントペイロード

#### 会社変更通知

```json
{
  "eventId": "evt-001",
  "eventType": "as.company.changed",
  "timestamp": "2024-01-01T00:00:00Z",
  "data": {
    "companyId": 1,
    "companyCode": "CO001",
    "name": "株式会社サンプル",
    "changeType": "CREATE",
    "status": "ACTIVE"
  }
}
```

#### 店舗変更通知

```json
{
  "eventId": "evt-002",
  "eventType": "as.store.changed",
  "timestamp": "2024-01-01T00:00:00Z",
  "data": {
    "storeId": 1,
    "storeCode": "ST001",
    "companyId": 1,
    "name": "渋谷店",
    "changeType": "CREATE",
    "status": "ACTIVE"
  }
}
```

#### 従業員変更通知

```json
{
  "eventId": "evt-003",
  "eventType": "as.employee.changed",
  "timestamp": "2024-01-01T00:00:00Z",
  "data": {
    "employeeId": 1,
    "employeeCode": "EMP001",
    "lastName": "山田",
    "firstName": "太郎",
    "changeType": "CREATE",
    "status": "ACTIVE"
  }
}
```

### 2.4 配信方針

| 項目 | 値 |
|------|-----|
| 配信方法 | 非同期（メッセージキュー） |
| リトライポリシー | 最大3回、指数バックオフ |
| DLQ対応 | あり（3回失敗後にDLQへ） |
| 順序保証 | あり（パーティションキー: companyId/storeId/employeeId） |

## 3. AGアジルーム連携

### 3.1 連携概要

AGアジルームは、AS関連付けから会社・店舗・従業員の変更通知を受信します。

### 3.2 連携イベント一覧

| イベント名 | トピック | 発生条件 |
|-----------|---------|----------|
| 会社変更通知 | as.company.changed | 会社の登録・更新・廃止時 |
| 店舗変更通知 | as.store.changed | 店舗の登録・更新・廃止時 |
| 従業員変更通知 | as.employee.changed | 従業員の登録・更新・退社時 |

### 3.3 イベントペイロード

JBジョブ管理と同じペイロード形式を使用します。

### 3.4 配信方針

| 項目 | 値 |
|------|-----|
| 配信方法 | 非同期（メッセージキュー） |
| リトライポリシー | 最大3回、指数バックオフ |
| DLQ対応 | あり（3回失敗後にDLQへ） |
| 順序保証 | あり（パーティションキー: companyId/storeId/employeeId） |

## 4. エラーハンドリング

### 4.1 エラー種類

| エラー種類 | 説明 | 対応 |
|-----------|------|------|
| 一時的エラー | ネットワーク障害、一時的なシステム障害 | リトライ |
| 永続的エラー | 不正なペイロード、認証失敗 | DLQへ移行 |
| タイムアウト | 応答が返ってこない | リトライ後DLQへ移行 |

### 4.2 リトライポリシー

| 項目 | 値 |
|------|-----|
| 最大リトライ回数 | 3回 |
| リトライ間隔 | 指数バックオフ（1秒、2秒、4秒） |
| DLQ移行条件 | 3回失敗後 |

### 4.3 DLQ処理

| 項目 | 値 |
|------|-----|
| DLQモニタリング | 常時監視 |
| 再処理方法 | 手動再処理またはバッチ再処理 |
| アラート | DLQにメッセージが溜まった場合に通知 |

## 5. セキュリティ

### 5.1 認証・認可

| 項目 | 値 |
|------|-----|
| 認証方式 | JWT（JSON Web Token） |
| トークン有効期限 | 1時間 |
| トークン更新 | リフレッシュトークン使用 |

### 5.2 通信暗号化

| 項目 | 値 |
|------|-----|
| 通信プロトコル | HTTPS (TLS 1.2以上) |
| メッセージキュー | SSL/TLS暗号化 |

## 6. 監視・ログ

### 6.1 監視項目

| 項目 | 閾値 | アラート |
|------|------|---------|
| イベント配信失敗率 | 1% 超過 | 警告 |
| DLQメッセージ数 | 10件 超過 | 警告 |
| イベント配信遅延 | 1分 超過 | 警告 |

### 6.2 ログ記録

| 項目 | 説明 |
|------|------|
| イベント配信ログ | 配信成功・失敗の記録 |
| リトライログ | リトライ回数・結果の記録 |
| DLQログ | DLQ移行したメッセージの記録 |
