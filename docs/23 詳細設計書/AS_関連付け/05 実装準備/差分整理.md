1. **既存コードの流用**: `Party`, `Person`, `Org`, `PartyRole`の既存コードをベースに拡張 ✓

4. **コマンドサービスの拡張**: 既存コマンドサービスに新しいフィールドの処理を追加 ⚠ 未着手
5. **JPAエンティティの実装**: すべてのエンティティに`@Entity`アノテーションとマッピングを追加 ✓

### 8.3 実装順序

1. **フェーズ1**: コアドメイン（Party, PartyRole, PartyRoleMapping, PartyType, RoleType）✓
2. **フェーズ2**: サポートドメイン（Person, Employee, PersonRole, Affiliation, Org, Organization, OrganizationRole, OrganizationHierarchy, OrganizationType, Company, Store）✓

## 9. 注意事項

- 既存のSPIインターフェースは他のモジュールから参照されている可能性があるため、変更時は互換性を確認する
- `Person`と`Employee`の関係は詳細設計書では別テーブルだが、既存コードでは`Person`が従業員を兼ねている。実装時は継承またはコンポジションで対応する
- `Org`と`Organization`の関係も同様。既存の`Org`をベースに`Organization`を拡張する
- 履歴管理は`PptEntity`を継承することで対応する
- ステータス管理は列挙型で実装する（`ACTIVE`, `INACTIVE`）
