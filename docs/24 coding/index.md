# コーディングガイド

## VisibleForTesting アノテーションの使用原則

### プロダクションコードでの使用制限

`@VisibleForTesting` アノテーションは、 **テスト目的でしか使用すべきではないメソッド**に付与します。
しかし、このアノテーションが付与されたメソッドは
**プロダクションコードとして存在することが許容される**場合があります。

### 原則

1. **static メソッドであること**
    - `@VisibleForTesting` アノテーションが付与されたメソッドは必ず `static` でなければなりません。
    - これはテストコードから直接アクセスできるようにするためです。

2. **プロダクションコードでの使用が許容されるケース**
    - ドメインロジックの一部であり、テストから直接アクセスする必要がある場合
    - 再利用可能なユーティリティメソッドであり、テストから直接使用する場合
    - 例: `ValueObject.nonEmpty()` のようなバリデーションメソッド

3. **使用すべきでないケース**
    - テストのためにのみ存在するメソッドで、プロダクションコードでは不要な場合
    - カプセル化を壊すようなアクセスを提供する場合
    - プロダクションコードでは使用されないプライベートロジックを公開する場合

### 例

```java
public abstract class ValueObject {
  
  @VisibleForTesting
  public static boolean nonEmpty(String value) {
    return value != null && !value.isEmpty();
  }
}
```

### 検証

`ModulithTest` で `@VisibleForTesting` アノテーションが付与されたメソッドが `static`
であることを自動的に検証しています。
