# ADR-0009: 非機能要件 A-05（目標復旧時間・復旧時点）に対応する

## 日時

2026-10-27

## 状態

承認済み

## 背景

AgiloomシステムはクラウドベースのSaaS学習プロジェクトです。非機能要件
A-05（目標復旧時間・復旧時点）では、以下の要件が定義されています。

- RTO（復旧目標時間）：4 時間以内
- RPO（復旧目標時点）：1 時間以内
- 対象障害：大規模障害（システム全体が利用不能となる場合）

RTO/RPOの定義は、障害発生時の復旧目標を明確化し、ビジネス継続性を確保するために重要であるため、対応する方針とする。

## 決定

非機能要件 A-05（目標復旧時間・復旧時点）に対応する。

具体的には、以下の要件を実装する。

- RTOを4時間以内、RPOを1時間以内とする
- バックアップの頻度はRPOを満たすように設定する（1時間間隔以上）
- 定期的な検証によりRTO/RPOの達成可能であることを確認する

## 代替案

1. **RTO/RPOを緩和する**: 学習プロジェクトであるため、要件を低く設定する
2. **RTO/RPOの定義のみ文書化する**: 実際の検証は実施しない
3. **クラウドプロバイダーの機能に依存する**: 自前の復旧手順は定義しない

## 影響

### 肯定的な影響

- 障害発生時の復旧目標が明確になる
- ビジネス継続性が確保される
- ユーザーへの影響を最小限に抑えられる

### 否定的な影響

- バックアップ頻度の増加によりストレージコストが増加する
- 定期的な検証により運用負荷が増加する
