# ADR-0023: 非機能要件 E-01（認証・認可・アクセス制御）に対応する

## 日時

2026-10-27

## 状態

承認済み

## 背景

AgiloomシステムはクラウドベースのSaaS学習プロジェクトです。非機能要件
E-01（認証・認可・アクセス制御）では、以下の要件が定義されています。

- 認証方式：OAuth 2.0 / OpenID Connect
- MFA（多要素認証）：対応（管理者は必須）
- セッション管理：30 分アイドルでタイムアウト
- ロールベースアクセス制御：対応（RBAC）

認証・認可は、システムのセキュリティの基礎となる重要な要件であり、本番環境を想定した設計として対応する方針とする。

## 決定

非機能要件 E-01（認証・認可・アクセス制御）に対応する。

具体的には、以下の要件を実装する。

- OAuth 2.0 / OpenID Connectを用いた認証を実装する
- ロールベースアクセス制御（RBAC）を実装する
- セッションタイムアウト機能を実装する
- 管理者はMFAを必須とする

## 代替案

1. **認証方式を簡素化する**: OAuth 2.0ではなく、セッションベースの認証のみとする
2. **MFAは導入しない**: 学習プロジェクトであるため、MFAは必須としない
3. **ロールベースアクセス制御を簡素化する**: 単純なユーザー/管理者の2ロールのみとする

## 影響

### 肯定的な影響

- システムのセキュリティが向上する
- ユーザーデータの保護が強化される
- アクセス制御の柔軟性が高まる

### 否定的な影響

- 認証・認可機能の実装により開発コストが増加する
- MFAの導入によりユーザー体験が低下する可能性がある
