# ADR-0018: 非機能要件 C-05（ソフトウェア・ハードウェア構成管理）に対応する

## 日時

2026-10-27

## 状態

承認済み

## 背景

AgiloomシステムはクラウドベースのSaaS学習プロジェクトです。非機能要件
C-05（ソフトウェア・ハードウェア構成管理）では、以下の要件が定義されています。

- IaC（Infrastructure as Code）：Terraform 等による管理
- バージョン管理：Git による管理
- 環境分離：開発・テスト・ステージング・本番の分離
- 構成ドリフト検出：自動検出・アラート

構成管理は、インフラの再現性と環境間の差異を最小限に抑えるために重要であり、本番環境を想定した設計として対応する方針とする。

## 決定

非機能要件 C-05（ソフトウェア・ハードウェア構成管理）に対応する。

具体的には、以下の要件を実装する。

- Terraform等のIaCツールを活用し、インフラをコードで管理する
- Gitによるバージョン管理を実施する
- 開発・テスト・ステージング・本番の環境を分離する
- 構成変更はレビュープロセスを経る

## 代替案

1. **IaCは導入しない**: 手動でのインフラ管理のみとする
2. **環境分離を簡素化する**: 開発・テスト・本番の3環境のみとし、ステージングは設けない
3. **構成ドリフト検出は実施しない**: 手動での確認のみとする

## 影響

### 肯定的な影響

- インフラの再現性が向上する
- 環境間の差異が最小限に抑えられる
- 構成変更の透明性が向上する

### 否定的な影響

- IaCツールの学習コストが発生する
- 構成管理の複雑性が増す
