# ADR（Architecture Decision Record）一覧

## 概要

本ドキュメントは、Agiloomシステムにおけるアーキテクチャ決定の記録（ADR）を一覧で管理します。ADRは、決定の透明性・知識の共有・将来の参照・オンボーディングのために記録します。

ADRには2つの系統があります。

- **非機能要件ADR（ADR-0001〜）**: 非機能要件項目ごとの対応可否の決定
- **アーキテクチャ決定ADR（001〜）**: 設計・技術選定・開発ワークフロー等の決定（旧 `docs/95 Architecture decision record (ADR)/` から集約）

## ADRの書き方

新しいアーキテクチャ決定を記録する際は、`template/template.md` をコピーして新しいADRファイルを作成し、本一覧へ追加します。記入例は `example/` を参照してください。

各ADRは以下の構造に従います：

1. **タイトル**: 決定の簡潔な説明
2. **ステータス**: 提案中、承認済み、廃止、置換など
3. **コンテキスト**: 決定が必要となった背景や状況
4. **決定**: 実際に選択された選択肢とその詳細
5. **結果**: この決定から予想される結果（ポジティブ、ネガティブ、中立）
6. **代替案**: 検討されたが選択されなかった他の選択肢
7. **関連**: 関連する他のADRや文書へのリンク
8. **見直しの条件**: 決定から再度判断が必要となる条件

## 状態の説明

- **提案中**: 決定を検討中
- **承認済み**: 決定が完了し、実施中または保留中
- **廃止**: 以前の決定が取り消され、新しい決定に置き換えられた
