# フロントエンドフレームワークの技術選定（React / Vue / Svelte / SolidJS）

## ステータス

提案中

## 日付

2026-10-11

## コンテキスト

本プロジェクトのフロントエンドは未実装状態であり、新規開発におけるフレームワーク選定が必要です。2026年時点で主流な4つのJavaScriptフレームワーク（React,
Vue, Svelte, SolidJS）を比較検討し、プロジェクトに最適な1つを決定します。

比較軸は以下の6つです：

1. **学習コスト**: 新規メンバーが習得するまでの時間
2. **開発生産性**: 開発速度、DX（Developer Experience）
3. **パフォーマンス**: 初期ロード、レンダリング性能
4. **エコシステム**: ライブラリ、コミュニティ、日本語リソース
5. **採用企業**: 日本での採用状況、求人数
6. **将来性**: 開発アクティビティ、ロードマップ

## 決定

**React** を推奨します。

Next.jsとの組み合わせにより、SSR/SSG/ISRなどのサーバーサイドレンダリング戦略が包括的に利用可能であり、エコシステムの規模、採用市場の広さ、日本語リソースの豊富さにおいて他を圧倒するためです。

## 各フレームワークの Pros / Cons

### React

**Pros:**

- エコシステムが最大級。npmパッケージ数、Stack Overflow回答数、採用企業数すべてで他を圧倒
- Next.jsとの組み合わせで、SSR/SSG/ISR/ストリーミングなど包括的なレンダリング戦略が利用可能
- 日本での求人が最多。エンジニアの採用・確保が容易
- 日本語の学習リソースが非常に豊富（Qiita、Zenn、公式ドキュメント日本語版など）
- React Nativeにより、Webとモバイルを同じ技術スタックで開発可能
- React Compiler (2025年10月 v1.0到達) により、手動の `useMemo`/`useCallback` が不要になりつつあり、開発体験が改善
- 大規模チームでの分業開発に適したコンポーネントベース設計

**Cons:**

- フレームワークの複雑さが年々増加。Hooks、Context、Server Components、複数のレンダリング戦略を理解する必要がある
- 学習曲線が相対的に急。新規メンバーのオンボーディングに時間がかかる
- エコシステムの断片化。スタイリング、状態管理、ルーティングなど、どのライブラリを選ぶかという追加の判断が必要
- バンドルサイズが比較的大きい（約45 KB）
- 満足度が比較的低め（72%）。開発者の不満が蓄積している側面あり

### Vue

**Pros:**

- 学習コストが最低クラス。JavaScript初心者のチームでも習得が容易
- 日本語ドキュメントの質が最高級と評価され続けている
- 段階的採用が可能。既存サイトに一部だけVueを導入して動的機能を追加できる
- Nuxt 4により、Next.jsに匹敵するSSR/SSG機能が利用可能
- VueのユニバーサルレンダリングモデルはReactの複数戦略よりシンプル
- Composition APIにより、React Hooksに匹敵する再利用性が実現
- Vapor Modeにより、仮想DOMを使わない超高速化がオプションで利用可能
- 日本国内の事業会社・受託領域での採用実績が根強い

**Cons:**

- エコシステム規模はReactに劣る。一部のニッチなライブラリが不足する可能性あり
- 日本での求人はReactより少ないが、依然として十分な供給がある
- モバイルアプリ開発の公式サポートがない
- 外資系・グローバル案件やスタートアップの新規立ち上げではReactが前提になりやすい

### Svelte

**Pros:**

- 満足度が高い（86%）。比較対象の4フレームワーク中、SolidJSに次ぐ水準
- 学習コストが低く、特にReact経験がない開発者にとって習得が容易
- コンパイラベースのアーキテクチャにより、ランタイムが最小限。バンドルサイズ約2-3 KBで最小級
- パフォーマンスが最高級。仮想DOM不要で直接DOMを更新
- 記述量が少なく、コードの可読性が高い
- Svelte 5のRunes ($state, $derived) により、明示的なリアクティビティで予測可能性が向上
- SvelteKitにより、エッジコンピューティングとの親和性が高いフルスタック開発が可能

**Cons:**

- エコシステムがReact/Vueより小さい。一部のライブラリが利用できない可能性あり
- 日本での求人が非常に少ない。採用が困難
- SolidJSと同様、Reactライブラリは直接使用できない
- コンパイラアプローチのため、特定の動的パターンが実装しにくい場合がある
- SvelteKitのエコシステムはNext.jsと比較してまだ成熟途中
- 日本語リソースが中程度。React/Vueほど豊富ではない

### SolidJS

**Pros:**

- パフォーマンスが最高級。ファイン・グレーン・リアクティビティにより、必要なDOMノードのみを更新
- バンドルサイズが約7 KBで軽量
- JSX構文を採用しているため、React開発者は数日で生産性に到達可能
- コンポーネントは1回だけ実行され、再レンダリングがない。Reactのメンタルモデルから解放される
- 満足度が高い（89%）。5年連続でトップまたはトップ近傍を維持
- APIがシンプルで、学習すべき概念が少ない

**Cons:**

- エコシステムが最小級。Reactライブラリは直接使用できない
- 日本での求人がほぼなし。採用が極めて困難
- 公式メタフレームワークが存在しない
- SolidJS 2.0はRC段階で、2.0.0-rc.13が公開済み。正式リリース前のため、非同期モデルの本番適用には検証が必要
- コミュニティが小さい。問題発生時の情報収集が困難
- 日本語リソースが非常に少ない
- Reactのメンタルモデルを「忘れ直す」必要がある。再レンダリングがないことを理解するまで時間がかかる

## 推奨フレームワークと理由

**React** を推奨します。その理由は以下の通りです：

1. **採用市場の広さ**: 日本でのフロントエンド求人でReact経験者が最多。6ヶ月以内にエンジニアを採用・確保できる確実性が高い。
2. **エコシステムの深さ**: npmパッケージ数、Stack Overflow回答数、ライブラリ充実度すべてで他を圧倒。5年後も廃れにくい選択肢。
3. **日本語リソースの豊富さ**: Qiita、Zenn、公式ドキュメント日本語版など、学習・トラブルシューティングに必要な情報が豊富に揃っている。
4. **Next.jsの成熟度**: SSR/SSG/ISR/ストリーミングなど、包括的なレンダリング戦略が利用可能。新規Reactプロジェクトの約78%がNext.jsを使用。
5. **React Compilerの進化**: 2025年10月にv1.0に到達。手動最適化が不要になり、開発体験が大幅に改善された。
6. **React Nativeによるモバイル対応**: Webとモバイルを同じ技術スタックで開発できる選択肢がある。
7. **大規模開発への適性**: コンポーネントベース設計により、複数人での並行開発が容易。

Vueは日本での採用実績や学習コストの面で魅力的ですが、エコシステムの規模やグローバルでの採用市場ではReactに劣ります。SvelteとSolidJSはパフォーマンスと満足度で優れていますが、エコシステムの小ささと採用市場の狭さが本プロジェクトではリスクとなります。

## 結果

### ポジティブな結果

- エンジニアの採用が容易で、チーム編成のリードタイムが短縮される
- 豊富な日本語リソースにより、新規メンバーのオンボーディングがスムーズ
- 成熟したエコシステムにより、必要な機能のほとんどが既存ライブラリでカバーできる
- Next.jsにより、SEO対策やパフォーマンス最適化が包括的に実現可能
- React Nativeへの移行パスが確保され、将来的なモバイルアプリ開発の選択肢が広がる

### ネガティブな結果

- フレームワークの複雑さが年々増加しており、チームの学習負担が継続的に発生
- エコシステムの断片化により、ライブラリ選定における追加の判断コストがかかる
- バンドルサイズが比較的大きく、初期ロードパフォーマンスに若干のトレードオフがある
- 満足度が比較的低め（72%）。開発者のモチベーション維持に注意が必要

### 中立的な結果

- React Compilerの導入により、従来のパフォーマンス最適化の手間が軽減されるが、新しいパターンの習得が必要
- Server Componentsの導入により、アーキテクチャ設計の自由度が増すが、理解コストも増加

## 代替案

### 代替案1: Vue.js

Vue.jsは学習コストの低さと日本語リソースの豊富さで優れており、特に中小企業の内製化やJavaScript初心者のチームには最適な選択肢です。日本国内の事業会社・受託領域での採用実績も根強く、Nuxt
4によりReact/Next.jsに匹敵する機能が利用可能です。

**選ばれなかった理由**:
エコシステム規模とグローバルでの採用市場がReactに劣る。外資系・グローバル案件やスタートアップの新規立ち上げではReactが前提になりやすく、長期的なキャリア上の柔軟性を考慮するとReactが優位です。

### 代替案2: Svelte

Svelteは満足度が高く（86%）、バンドルサイズ最小（約2-3 KB）、パフォーマンス最高級という点で技術的に最も魅力的なフレームワークです。Svelte
5のRunesにより、大規模アプリでの予測可能性も劇的に向上しました。

**選ばれなかった理由**:
エコシステムが小さく、日本での求人が非常に少ない。採用が困難であり、チーム編成のリスクが高まります。また、SvelteKitのエコシステムはNext.jsと比較してまだ成熟途中です。

### 代替案3: SolidJS

SolidJSはパフォーマンス最高級、バンドルサイズ軽量（約7
KB）、JSX構文によりReact開発者の習得が容易という点で魅力的です。満足度も89%で高い水準を維持しています。

**選ばれなかった理由**: エコシステムが最小級で、日本での求人がほぼなし。SolidJS
2.0はRC段階で、2.0.0-rc.13が公開済みです。正式リリース前のため、非同期モデルの本番適用には検証が必要です。公式メタフレームワークの欠如も課題です。

## 見直しの条件

- SvelteやSolidJSのエコシステムが大幅に成熟し、日本での採用市場が拡大した場合
- React Compilerが完全に安定し、開発体験がVueやSvelteに匹敵するレベルに到達した場合
- プロジェクトの要件が、バンドルサイズの最小化やパフォーマンスの最大化を最優先する場合
- チームメンバーのスキルセットがVueやSvelteに特化している場合
- SolidJS 2.0が安定リリースされ、公式メタフレームワークが登場した場合
