# ミューテーションテスト (Pitest) 導入ガイド

## 概要

本プロジェクトには [Pitest](https://pitest.org/) を用いたミューテーションテストが導入されています。
ミューテーションテストは、コードに意図的な変更（ミューテーション）を加えてテストがそれを検出できるかを検証し、テストの品質を評価する手法です。

## 対象モジュール

| モジュール              | 対象パッケージ                       | 備考                                 |
|-------------------------|--------------------------------------|--------------------------------------|
| `mizo432-shared-common` | `com.github.mizo432.shared.common.*` | フレームワーク非依存の共通ライブラリ |
| `backend`               | `undecided.shared.*`                 | 初回導入時はsharedパッケージに限定   |

## 実行方法

### 共通ライブラリのミューテーションテスト

```bash
./gradlew :mizo432-shared-common:pitest
```

### バックエンドのミューテーションテスト

```bash
./gradlew :backend:pitest
```

### レポートの参照

実行後、以下のパスにHTMLレポートが生成されます：

- `mizo432-shared-common/build/reports/pitest/index.html`
- `backend/build/reports/pitest/index.html`

ブラウザで `index.html` を開くと、パッケージごとのミューテーションスコアや生存したミュータントの詳細を確認できます。

## 結果の解釈

### 主要メトリクス

| メトリクス         | 説明                                                                   |
|--------------------|------------------------------------------------------------------------|
| **Mutation Score** | 殺されたミュータントの割合。100%が理想。                               |
| **Line Coverage**  | ミューテーション対象クラスの行カバレッジ                               |
| **Test Strength**  | カバーされたミュータントの割合（カバーされていないミュータントを除外） |
| **No Coverage**    | テストでカバーされていないミュータント数                               |

### ミュータントのステータス

| ステータス      | 意味                                             |
|-----------------|--------------------------------------------------|
| **KILLED**      | テストがミューテーションを検出 ✓                |
| **SURVIVED**    | テストがミューテーションを検出できず ✗          |
| **NO_COVERAGE** | そのコードにテストカバーがない                   |
| **TIMED_OUT**   | ミューテーションによりテストが無限ループになった |
| **ERROR**       | ミューテーション適用中にエラーが発生             |

## 構成オプション

各モジュールの `build.gradle.kts` に以下の構成が定義されています：

| プロパティ            | 値                 | 説明                               |
|-----------------------|--------------------|------------------------------------|
| `targetClasses`       | パッケージパターン | ミューテーション対象のクラス       |
| `junit5PluginVersion` | `1.2.1`            | JUnit 5 サポートプラグイン         |
| `threads`             | CPUコア数          | 並列実行スレッド数                 |
| `outputFormats`       | `HTML, XML`        | 出力フォーマット                   |
| `timestampedReports`  | `false`            | タイムスタンプなしでレポートを生成 |
| `skipFailingTests`    | `true`             | 不安定なテストをスキップ           |

## backend モジュールの注意点

backendモジュールのテストは主に `@SpringBootTest` を使用した統合テストであり、Testcontainers による
PostgreSQL 起動が必要です。
そのため、以下の制限があります：

1. **テストタグ**: デフォルトの `test` タスクは `medium`・`large` タグを除外するため、Pitest
   も同様に制限されます。
2. **実行時間**: Spring Bootの統合テストは起動に時間がかかるため、ミューテーションテストの実行時間が長くなります。
3. **対象範囲**: 初回導入時は `undecided.shared.*` パッケージに限定しています。必要に応じて範囲を拡張してください。

### 統合テストを含むミューテーションテストを実行する場合

```bash
# mediumタグのテストも含める場合
./gradlew :backend:mediumTest :backend:pitest
```

## ミューテーションスコアを改善する

1. **SURVIVED** したミュータントを確認し、対応するテストを追加・修正する
2. **NO_COVERAGE** のコードにテストを追加する
3. 不要なコードを削除する

## CI/CD での活用

Pitest を CI パイプラインに組み込む場合は、以下の点を考慮してください：

- **実行時間**: ミューテーションテストは通常のテストより数倍〜数十倍時間がかかります
- **対象範囲**: 全パッケージを対象にすると実行時間が非常に長くなるため、変更されたファイルに限定するなど範囲を絞ってください
- **閾値設定**: `mutationThreshold` や `coverageThreshold` を設定して、一定のスコア未満でビルドを失敗させることができます
